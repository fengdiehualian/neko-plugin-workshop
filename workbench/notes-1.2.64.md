# v1.2.64 更新说明

这一版是对上一版(v1.2.63)的复查。复查提了七条,逐条核实后**七条都成立**——
其中最重要的一条是:上一版做的「外发写要你确认」门禁,在真实环境里根本不会被触发。
本轮全部修好,并且每条都补了能重复跑的验证。

## 一、门禁之前是空转的,现在真的会拦(issue #1 第 1 条 + #10)

上一版的确认逻辑挂在引擎的 `permission.asked` 事件上,而工坊写给引擎的是 `bash: "allow"`。
从引擎二进制里能看到:字符串会被展开成 `{"*":"allow"}` —— 任何命令都不发出权限询问,
于是那条线从来不响。

改成 **`bash` 通配 `ask`:引擎一律先问工坊,由工坊判断**。
为什么不能用「外发形态才问」的模式表(实测结论,不是推测):真引擎跑
`git add . && git push origin main` 时——

- `git push*` 前缀形态命中不了(命令不是以它开头);
- `*git push*` 包含形态也命中不了(**引擎的通配不跨空格**,`*` 只能匹配一个词);

结果整条被 `{"*":"allow"}` 放行。模式列不完,所以默认改成一律先问。

「都要问」不会把人淹死:工坊对**非外发写**的询问自动应答(毫秒级,不打扰你),
只有判定为外发写才弹出确认卡。判定层同时改成**按 `&&`/`;`/`|`/换行逐段解析**,
并且整串也判一遍(像 `python -c "...requests.post(...)"` 必须看到全句才成立,只拆分会漏判)。
另外补上了此前漏掉的间接外发:别名(`git -c alias.x=push`、`git config alias.push ...`)、
`curl --json/--data/-F`、`scp`/`sftp`/`rsync 到远端`、`aws/ossutil/gsutil` 上传、
`twine`/`cargo`/`gem`/`mvn`/`gradle` 发布、`docker/podman push`、解释器内联脚本发 HTTP。

**真引擎端到端证据**(`tools/probes/e2e-outward-gate.cjs`,16 项全过):

| 断言 | 证据 |
|---|---|
| 外发写进入确认队列 | 队列里拿到 `reason=git push(推送到远端仓库)`,事件 `resources` 就是命令原文 |
| 批准前没执行 | 网关计数「真执行 = 0」(引擎没带着工具结果回来) |
| 批准后执行 | 点「允许这一次」后真执行计数变 1,会话继续 |
| **复合命令** `git add . && git push` | 同样进队列(本轮新签的清单/工具调用计数 1→2 证明是这一轮产生的),批准前真执行仍为 0 |
| 点「不要」 | 真执行 0→0,并收到 2 条**拒绝回执**(引擎拿到的是「权限被拒」,不是执行结果) |

顺带修了一个测量口径错误:「有工具结果回来」不等于「命令执行了」——被拒绝时引擎也会回一条结果。
网关现在分开数 `executedReqs` / `rejectedReqs`,否则拒绝路径会被读成假阳性。

**边界仍然要说清**:ZCode 底座是外部 CLI,权限由它自己管,工坊收不到询问事件,
那条路径只有任务书规则约束。现在设置页的「Agent 底座」里**直接写明了当前底座有没有这道硬闸**
(切到 ZCode 显示「拦不住」,切到 OpenCode 显示「已生效」),不再让人以为都在保护。

## 二、发布脚本不再拿 token 走不加密校验的链路(issue #1 第 2 条 + #11)

- 新增 `workbench/release_tls.py`,三个脚本统一口径:**默认证书校验开启**,CA 用 Node/Git 自带的 bundle。
- git 侧实测清楚了:本机 PortableGit(schannel)够不到吊销服务器,一律报 `0x80092013`,
  而 `http.schannelCheckRevoke=false` **在这个构建上不生效**(照样报错)。
  正解是 `http.sslBackend=openssl` + `http.sslCAInfo=<ca-bundle.crt>` —— 实测双端在完整证书校验下都能通。
- `push-both.cjs` 之前干了三件错事:设 `GIT_SSL_NO_VERIFY=1`、`tag --force` 强推、tag 名写死 `v1.2.63`。
  现在:不接受 `GIT_SSL_NO_VERIFY`、tag 从 `package.json` 读、**远端 tag 与本地不一致就拒绝**(要挪必须显式 `--force-tag` 并打印警告)。
- 码云 token 从 URL 查询串改到 `Authorization: token …` 请求头(实测双端都认),URL 不再进日志。
- `check_release_state.py` 现在**把资产本体下回来算 SHA256**,不再只信发行说明里那行字。
  实测码云附件下回 71,717,376 字节、SHA 与本地一致 ✓;顺带修掉我自己写的 content-length 误报
  (GitHub 资产下载会 302 到 CDN,拿那一跳的头当基准会误判)。
- 真要临时降级只剩 `NEKO_INSECURE_TLS=1` / `NEKO_INSECURE_GIT=1` 两个显式开关,而且每次都会打印凭据泄露风险。

## 三、更新清单必须核对版本与体积,验签失败直接拒(issue #1 第 3 条 + #12/#3)

上一版虽然加了 ed25519 签名清单,但有两处不够硬:

- **没核对清单内容**:清单里写的 `version`/`asset`/`size` 与本次要装的是不是同一份,当时完全没验。
  后果是一张签名完全合法的**旧版清单**能给回滚背书。现在三项都核对,对不上直接拒。
- **验签失败被当成「没有清单」**:那样就退回到「双渠道互相印证」放行。清单坏了本该更警惕,不能更宽松。
  现在验签失败/内容不符 → **硬拒**,错误里明写「不因『多渠道一致』而放行」。

端到端实测(`tools/verify-security.cjs`,13 项全过),五种攻击演练全部被拒:

```
单渠道且无签名清单            → 不自动安装
清单签名伪造                  → 硬拒(不退化为多渠道互证)
签名合法的旧版清单冒充新版     → 拒绝(清单版本 v9.9.8 与要装的 v9.9.9 不一致)
清单有效但包被换              → 拒绝(期望 c897ba395dff… 实算 fc77d04cb92f…)
正文哈希与签名清单矛盾         → 拒绝
清单验签 + 哈希一致            → 才放行
```

测试素材也改了:示范清单以前是用**生产私钥**签的,那等于制造一条合法但与真实发布无关的签名;
现在改用独立的测试钥匙(`test/fixtures/` 内),并有一条单测专门断言「生产公钥验不过测试素材」。

**需要你负责的一件事**:签名私钥只在发布机 `C:\Users\Administrator\.neko-workshop\update-sign-ed25519`,仓库里没有。
这把钥匙丢了就签不出新清单,自动更新只剩「双渠道互相印证」这条路,再不行会提示手动安装。**请自行备份。**

## 四、安装包不再携带第三方市场语料(issue #1 第 4 条 + #4)

以前 `git archive` 会把 `market-corpus` 一起打进安装包里,而许可实测结果是这样:

| 判定结果 | 目录数 |
|---|---|
| 未声明(仓库里没有可识别的 LICENSE) | 84 |
| Apache-2.0 | 23 |
| MIT | 11 |
| GPL | 5 |
| AGPL | 4 |
| LGPL | 1 |

「语料都在 MIT 下再分发」的说法确实不成立。现在用 `.gitattributes` 的 `export-ignore` 让
**打包机制**保证语料与本机探针脚本不进包(以前只在文档里写「不分发」,那不算数):

- 载荷从 11,167 条 / 74.2MB 变成 **195 条 / 40.6MB**,安装包 40,353,792 字节;
- `build_payload.py` 收尾会检查禁含条目,**命中就拒绝出包**;
- `check_package.ps1` 把成品 exe 只解不装再核对一遍(必查齐全 + 禁含为空)。

这条修了三轮才对,踩的坑记下来免得再犯:`export-ignore` 只对**已提交**的属性文件生效;
而且目录本身(`dir`)与目录内容(`dir/**`)**两行都要写**,只写 `dir/**` 时 git archive 照样导出。
现在这两条都有单测钉住。

老用户不受影响:覆盖安装只解包写入载荷里存在的文件,不会删除本机已有语料。
新装需要语料的,在自己机器上跑 `node workbench/fetch_corpus.cjs`(工坊启动时也会提示这一点)。

## 五、其余复查条目(issue #1 第 5-7 条 + #13)

- **只有 opencode.json、没在设置页重存过 API 的老实例**,权限配置永远不会刷新。
  现在启动时自愈:检测到旧的字符串形态(`bash:"allow"`)或规则数偏少就就地升级并标记重启引擎,日志会写明。
- **写死本机路径**清零:`release_tls.resolve_git()/resolve_node()` 统一按「环境变量 → PATH → 已知位置」解析;
  `tools/probes/paths.cjs` 集中管理隔离实例/安装实例目录;`push-both` 的 tag 名从 `package.json` 读;
  `check_package.ps1` 用 `$PSScriptRoot` 推默认路径。另外生成的 opencode.json 里**不再有只有大小写不同的重复键**
  (`git -C * push*` 与 `git -c * push*` 会让 PowerShell 直接拒绝解析这个配置)。
- **`_zcode` 来源登记**:`workbench/zcode_bundle.json` 记录 Node v24.14.0、ZCode 0.13.3、三件文件的 size/sha256,
  并逐项写明 `upstream`(下载地址)与 `hash_source`(哈希出处,Node 侧对齐官方 SHASUMS256.txt)。
  `build_payload.py` 逐项比对,**登记缺失或哈希对不上就拒绝出包**(以前只是打印一句警告继续,那等于没登记)。
- **许可清单可复核**:`THIRD_PARTY_NOTICES.md` 由 `workbench/collect_notices.cjs` 实测生成,
  逐目录列出判定依据;「有 LICENSE 文件但没读出名堂」与「根本没有 LICENSE」分开表述(以前把 23 个 Apache-2.0 误并进「未声明」);
  MIT 全文不再用 `<年份> <持有人>` 空模板,直接引用仓库 LICENSE 的真实版权行。
- **CI 钉版本**:`bun-version: latest` 改成 `1.4.2`(上游发新版不该把我们 CI 的跑法换掉)。
- **测试小错误**:`Math.min(...lastAsk)` 应为 max(用 min 时只要第一条 ask 在开头就能骗过断言),
  该测试已按新语义重写并明确注释为什么不能用 min。

## 校验

- 大小与 SHA256 见下方「校验」段;工坊自动更新会按它比对,并且只接受**内置公钥验签通过、且版本/资产/体积都对得上**的清单。

## 升级方式

覆盖安装即可(双击 setup.exe,或工坊「检查更新 → 是」)。
`runtime\`(API 配置、会话、记忆、`engine-auth.json`)与 `workspace\`(你生成的插件)都不会被动到;
本机已有的 `market-corpus` 也不会被删除,只是新版本安装包不再携带它。
