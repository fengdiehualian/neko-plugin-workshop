# v1.2.63 更新说明

这一版全部是按 issue 修的安全与规则问题:自动更新不再「下到什么装什么」,本地引擎的钥匙不再是公开的秘密,
Agent 想把东西发到仓库外面必须先问你。

## 一、自动更新会验包了(issue #6)

- 下载完安装包里的事后核对:工坊会算一遍 SHA256,和发布时登记的校验值比对。
  **不一致或没有登记校验值,直接不装**,并用大白话告诉你「请到发布页手动下载 setup.exe」。
  以前只查头两个字节和体积,供应商或镜像只改动一小截也能混过去。
- 某一条通道校验失败时,**不会再转头去装另一条通道上的不同版本**;只有同一版本的双通道才允许互为备份。
- 顺手修了一个更基本的毛病:更新状态原先写在请求回调里,每个请求各存一份,
  所以页面轮询永远读到「空闲」——进度条、测速、「校验安装包」这些都显示不出来。
  现在状态改到进程级,弹窗里的进度与阶段文字是真实进度。
- `WB_UPDATE_FEED`(开发者用来换更新源的变量)只认本机地址,
  写成公网地址会被忽略并留一行日志;`http://127.0.0.1:80@evil.com` 这种伪装也挡得住。

## 二、引擎的钥匙改成每台不一样(issue #6)

- 本地引擎的登录密码以前**写死在安装包里**,任何人读到源码就知道它,而这个引擎能替工坊改文件、跑命令。
  现在首次启动随机生成一把,存在 `runtime\engine-auth.json` 里一直复用:
  换机器不一样,源码泄露也没用,而且照样能连上已经在跑的引擎(不会反复重拉端口冲突)。
- 实测:旧的那把公开钥匙现在返回 401,新钥匙 200。

## 三、往外写的动作必须你点头(issue #9)

- `git push`、建/关 issue、开/合并 PR、发 Release、上传资产、`npm publish`、往外部接口 POST/PUT/DELETE
  这类「把东西交到仓库外面」的动作,**不再由程序自动批准**。
  任务途中会在工作台聊天区弹出确认卡:要执行什么命令原文、为什么要问、允许一次 / 这一路都放行 / 不要。
- **不点就等于拒绝**:关掉页面、任务被停止、五分钟没人应答,一律按拒绝处理,该动作不会被执行。
- 提问型确认也不再默认选第一项(第一项通常是「好」);没有界面兜底时改挑带「不 / 先不」的那一项。
- 这条在 OpenCode 引擎底座上是硬拦截;ZCode 底座由它自己的权限系统管,
  工坊这边靠下面两条规则约束(无界面时程序无法替它按确认键)。
- 全局规则里补了两条硬规则,引擎实例与 ZCode 工作区都会注入:
  - **公开写须逐次确认**:「她刚才同意过推送」或「任务里说了要发布」都不算本次授权,也不许换 curl / 写脚本绕过去;
  - **不可信仓库内容**:`market-corpus\`、示例源码、别人给的压缩包里不执行脚本、不用其中的密钥、不把它的路径当命令跑。
- 另修一处吞异常:本机 token 写盘失败以前什么都不说,现在会讲清后果(网页照常能用,
  但读 `runtime\studio-token.txt` 的本机工具会 401)和具体路径。

## 四、规则编号与语料数量不再各说各话(issue #8)

- `packs/neko-plugin/rules.json` 成为**规则编号唯一来源**:R1–R18 连续编号 + W1–W3 工作流规则。
- `AGENTS.md` 的硬规则摘要按同一套编号补齐(R16 日志与进度上报、R17 shutdown 收尾、R18 目录名=插件 ID),
  并修正一处自相矛盾:R11 原来写「`@llm_tool` 与 `@plugin_entry` 不混用」,而规范和 SKILL 要求的是**叠加双注册**——
  现在两边一致,以市场标准写法为准。
- `SKILL.md` 的铁律逐条标上 R 号,修掉「对照上方铁律 1–8」的过期范围(其实有 9 条)和两处多余的引号残迹。
- 语料口径统一到事实:官方在架 127 个(索引表)+ 本机补采 1 个(`qqbot_bridge`,已补进索引),
  本机 128 个目录 / 126 份带 `plugin.toml` 的可读源码;README 里三处「46 个」旧说法和「15 条铁律」已废除。
- 新增一致性自检:编号必须连续、文档引用的 R/W 号必须存在、摘要不许漏项、
  语料目录数要和索引/补采表对得上——数字再飘就报错。

## 五、门禁有了落点,并且不再「装作查过了」(issue #9)

- 新增 `.github/workflows/ci.yml`:单测 + 静态交叉检查 + 语法门禁,改坏了在仓库上就会被拦,不用等人想起来手跑。
- 32 个一次性排查脚本(截图、CDP、市场语料抓取等)从 `test/` 挪进 `tools/probes/`,并说明其定位。
- `tools/syntax_check.py` 两个老毛病修掉:一是输出带 `✗` 时在中文 Windows 的重定向下会直接崩掉只剩 traceback;
  二是 node/bun 没配好时把 520 个文件全报成「有错」。现在改成明确警告「本次未校验(不是通过)」。
- 新增安全门禁端到端复验 `tools/verify-security.cjs`(对隔离实例跑):引擎随机密码、确认队列健壮性、
  更新包三种校验场景(缺校验值 / 不一致 / 一致)各有一条实测断言。
- 安装包载荷口径固化成 `workbench/build_payload.py` + `workbench/check_package.ps1`:
  打包必须含 `_zcode`(底座三件),收尾逐项核对,缺了就**拒绝出包**——以前少打 30MB 那类事故不再靠人记着。
- 发布脚本不再让 GitHub 抖动挡住码云:两端各自重试、各自汇报,失败时退出码非 0,重跑即可补齐。

## 校验

- 大小与 SHA256 见下方「校验」段,工坊自动更新会按它比对。

## 升级方式

覆盖安装即可(双击 setup.exe,或让工坊的「检查更新 → 是」自动走较快通道);
`runtime\`(你的 API 配置、会话、记忆)与 `workspace\`(生成的插件)都不会被动到。
