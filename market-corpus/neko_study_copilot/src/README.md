# 学习辅助猫娘（neko_study_copilot）

一个会规划、会出题、会看卷子、还会做心理疏导的 N.E.K.O 学习插件。

面向 **14 类考试**：高考 / 中考 / 四六级 / 考研 / 校内期末，以及大学生专属的
**大学期末（学分制 · GPA）**、**教师资格证**、**软考**、**注册会计师**、**法考**、
**雅思 / 托福**、**全国计算机等级考试**。

**用你自己的真实数据**做规划，而不是给你一套通用模板。

---

## 它能做什么

### 1. 规划：按「还剩多少分可拿」分配时间

不是平均分配，而是算清楚每门课离满分还差多少：

```
压力值 = (1 - 加权掌握度) × 该科满分
```

数学 150 分、物理 100 分，同样一半不会，数学就该拿更多时间。

- 按剩余天数自动划分**基础 → 强化 → 冲刺 → 临考**四个阶段；
- 周计划按科目轮转，不会出现"连着三周全是语文"；
- 每天开场固定 20% 时间给**到期复习**（艾宾浩斯间隔 1/2/4/7/15 天）；
- 每阶段末尾设检查点，测完更新掌握度，下一阶段自动重排。

#### 大学生：学分制是两套压力，得拆开算

大学和高中最大的区别是：**及格只要 60 分，但绩点决定保研、奖学金和出国**。
所以插件对大学考试用的是完全不同的口径：

```
学分系数 = 学分 ÷ 3        → 5 学分的课比 1 学分的课更值得投入
挂科风险 = 掌握度 < 62%    → 濒危科目时间 ×1.6，先抢救
时间压力 = (1 - 掌握度) × 满分 × 学分系数 × 风险系数
```

在面板（或配置 `credits`）里填上各科学分，例如 `math_adv:5,english:3,politics:3,cs:4`，
就会得到：

- 按学分加权的**时间分配**；
- 按学分加权的**绩点预估**（4.0 / 5.0 制）+ 保研 / 奖学金门槛定位；
- 一份**挂科风险清单**（按得分率升序，先保这些）。

覆盖的课程：高等数学、线性代数、概率论与数理统计、大学英语、思政课、
计算机与程序设计、大学物理、经管类（微观/宏观/管理学）、专业课。

#### 证书类考试

教资（综合素质 / 教育知识 / 学科教学）、软考（上午综合知识 + 下午案例或论文）、
注会（六科，60 分及格，五年内通过）、法考（客观题 180 + 主观题 108）、
雅思（四项均分 9 分制）、托福（合计 120）、NCRE（选择 40 + 上机 60）。
每类都自带合格线，预估时会按**实际计入科目的满分合计**等比缩放。

### 3. 教学：三段式，且严格遵守命题规律

这是本插件最硬的一块。每个知识点都登记了**它只会以哪些题型出现**：

| 知识点 | 只会考成 | 不会考成 |
|---|---|---|
| 名篇名句默写 | 填空题 | 解答题、选择题 |
| 交变电流 | 选择题 | 计算题、大题 |
| 计数原理与二项式 | 选择 / 填空 | 解答题 |
| 导数及其应用 | 选择 / 填空 / 解答 | — （压轴载体） |
| 中值定理与导数应用（高数） | 选择 / 填空 / **证明** | 案例分析 |
| 图论（数据结构） | 选择 / 填空 / **编程** | 论述题 |
| 软考论文写作 | **论述** | 选择题 |
| 法考民法 | 选择 / **案例分析** | — |

共登记 **193 个知识点**、**14 种题型**（含大学特有的证明题、论述题、案例分析题、
编程/上机操作题）。出题前会先过一遍题型白名单，出错了直接拒绝并说明原因。
所以不会出现"这道题根本不会这么考"的废题。

三段难度：

- **基础**（掌握度 < 45%）：题干直接对应定义，一步到位，不设坑；
- **中期**（45% ~ 75%）：允许设坑，但坑必须来自该点登记的真实易错点
  （定义边界、使用条件、符号方向），**不靠文字游戏**；
- **后期**（> 75%）：综合创新；若该点不是压轴载体，会明确要求"在允许题型内创新，
  别硬凑成解答题"。

### 4. 诊断：三档分数预期，说清楚依据

```
现在就考：约 317 分
最坏预期：约 312 分（发挥失常 + 题目变形）
最  可  能：约 353 分
较好预期：约 381 分（按计划执行到位）
波动区间：±25 分
```

模型链路是**掌握度 → 得分率 → 分数**，而不是拍脑袋给数：

1. 按分值权重算各科加权掌握度；
2. 把剩余学习时间按权重分给各知识点，`增益 ∝ 还剩多少没掌握`（自带边际递减）；
3. 三档分别对应"计划执行 35% / 65% / 100%"；
4. 临场波动按总分 4.5% 计；通过线按**实际计入科目的满分合计**缩放
   （只选了语数英物时，750 制的本科线不能直接套）。

依据会逐条写出来，包括"这个结论是基于多少条作答记录"。

### 5. 疏导：具体到今天能做什么

不说"你一定可以的"。按考试类型区分压力源：

- 高考 → 长跑倦怠、意义感流失
- 中考 → 年纪小、靠环境设计而非意志力
- 四六级 → 拖延型焦虑、没有过程反馈
- 考研 → 孤立无援、长期没有外部反馈
- 大学期末 → 「及格就行」与「绩点要好看」是两套压力，且没人盯着你学
- 注会 → 长周期消耗，六科五年，很容易形成挫败性归因
- 法考 → 体量型压力 + 「客观题没过就白学一年」的门槛结构
- 雅思 / 托福 → 单项瓶颈（口语写作）/ 时间压迫（三小时机考）
- 计算机等级 → 轻视型压力，卡在上机操作没真练过

七种情绪状态各有对应的认知重构与三条可执行动作。**检测到自伤/长期失眠等风险信号时，
立即停止打鸡血，转为给出真实热线**（12355 青少年服务台、400-161-9995 希望 24 热线）。

### 6. 识图：聊天框发截图就行

这是猫娘，主要就该在聊天框里交流——**截图发过去，别手打复制**。

```
你：[截图]                       ← 题目 / 试卷 / 作业 / 成绩单
你：这套卷子我哪里弱？
猫娘：已读取你发的截图并转写如下
     第 1 题（3 分）… 第 2 题…
     ======== 诊断 ========
     导数及其应用 掌握度 38% → …
```

链路：`@message(source="chat")` 记住你最近发的文本与图片 → 视觉模型把图**转写成文字**
（保留题号、选项、分值、图注，认不出的地方标〔无法辨认〕）→ 再走常规诊断 / 讲解链路。

- 认三种图片来源：消息里的内存字节、本地路径、http 地址，都会转成 data URL；
- 优先用宿主 **vision 档**模型，该档没配就自动退回 **conversation** 档；
- 面板「诊断预估」页也留了手动上传入口（`/api/vision`），但**推荐走聊天框**；
- 关掉 `vision_enabled` 就完全不改聊天消息，只记文本。

### 7. 资源：不只给链接，而是按你的需求做内容判断

关键词命中只是"找到了候选"，不等于"这份东西对你现在有用"。所以检索分三步：

```
检索（关键词找到候选） → 抓正文（这份材料到底讲了什么） → 内容分析（对你的需求有没有用）
```

输出每条都会给出四件事，而不是一个光秃秃的链接：

```
1. 【标题】　来源：B 站学习区
　　讲了什么：导数单调性的判定步骤与例题
　　和你的需求：你要的"中值定理"，这份只在最后一节带过
　　适合阶段：一轮基础
　　建议用法：看前 12 分钟就够，后半段是竞赛内容
```

- 抓不到正文（站点风控 / robots 不允许）时**自动降级**成「平台 + 标题 + 链接」，不会空手；
- 面板里的「**只要平台直链**」按钮完全不抓取，秒回各平台带好关键词的搜索直链；
- 直链清单也能单独要：「给我导数这块的资源清单」→ `study_resources` 入口。

### 8. 聊天时把「模型能联网」用起来

你接的模型本身可以联网检索，缺的不是能力而是**准确的落点**。所以讲解 / 出题时，
提示词里会带上一段「资源线索」：各免费平台的搜索直链（已带关键词）+ 本次抓到的具体条目，
并明确告诉模型——可以用自己的联网能力去核实具体课程名与知识点表述，但**不许把没查到的东西当事实说**。

### 9. 教学模式：人设强度可调

猫娘人设是主体，但人设越强，教学输出越容易被口癖、语气词稀释——术语密度下降、结构感变弱。
所以给一个显式档位（`persona_level`）：

| 档位 | 效果 |
|---|---|
| `full` | 默认。猫娘人格完整：自称『本喵』、句尾『喵』、适度颜文字 |
| `light` | 保留称呼与温度，但以知识为主，口癖每段至多一次 |
| `off` | **教学模式**。禁止口癖 / 颜文字 / 拟声词，术语准确、结构优先、先结论后理由 |

三种切换方式：面板顶栏的「教学模式」开关、聊天里说「开启教学模式」「别卖萌，正经讲课」
「恢复正常」、或直接改配置。**故意留的一个例外**：心理疏导场景下，`off` 只降到 `light`——
冷冰冰的疏导反而没用。

### 10. 记忆：短期对话记忆 + 长期事实记忆

模型本身是**无状态**的，每次调用都从零开始。所以「发张截图诊断完，再问第 3 题」这种
追问，如果没人把上下文接上，它必然接不上。插件用一张本地 SQLite（`data/study.db`）
做两级记忆：

| | 存什么 | 生命周期 |
|---|---|---|
| **短期记忆** `memory_turns` | 聊天与面板里的对话回合、截图转写、当次讲解/诊断/出题的原话 | 默认 **7 天**，到期自动清理 |
| **长期记忆** `memory_facts` | 进度、薄弱点、反复错的原因、偏好、诊断结论（按 `kind + key` 去重覆盖） | **不自动删** |

关键在**清理前先压缩**：`purge()` 在删除过期对话之前，会把这一周涉及的次数、
知识点、时间范围压成一条 `progress:weekly-*` 长期事实。删的是原话，留下的是结论。

接入方式（都在 `__init__.py`）：

- `_llm_chat(..., topic=, keywords=, record=True)` —— 一处接入，全流程生效：
  调模型前先 `MemoryKeeper.build_context()` 召回「最近聊过 + 相关长期事实 + 上次诊断」，
  接在提示词前面；回答后再写回短期记忆；
- `@message(source="chat")` 里额外调 `_remember_capture()`：**聊天框说的话也进记忆**
  （不然「说完就忘」还是没解决）；
- 诊断完成后把 top3 薄弱点 `upsert` 成长期 `weakness`；批改答错时写 `mistake`；
- 清理时机：`_ensure_ready()` 里调用，内部 12 小时只真跑一次。

隐私与可控：全部落本机、不上传；面板「档案」页有记忆卡片（条数、最近记录、长期事实），
可以逐条「忘记」，也能一键清短期 / 清全部。聊天里说「你记得我什么」「忘掉刚才」
「清空记忆」都行（入口 `study_memory`）。

配置：`memory_enabled` / `memory_short_days`（默认 7）/ `memory_recall_turns`（默认 8）。

### 11. 事实纪律：不许拿默认值和模板当事实

线上出过一次很难看的事故：用户只丢来一句「我草泥马」，疏导输出却是

```
85 天、掌握度五成、身边还飘着「某某考了三次都没过」的声音
```

三件事全是编的——天数是按常规考期**估算**的，「掌握度五成」是**没有作答记录时的默认值**，
第三句是我们压力源模板里的一句**通用描述**。模型没错，它只是照着喂进去的材料在讲；
错在我们把估算值、默认值和通用规律混进了「事实」里，还顺手给了它一份写好的三段式答案，
于是用户说什么都得到同一套。

现在按这条纪律改：

- `_guard.py` 定义**事实纪律**，凡是会生成自然语言的地方都带上；
- `counsel()` 把材料拆成三层，模型只能照第一层讲：
  - `facts` —— 已知事实，**每条带来源**（档案 / 估算 / 作答记录 / 他的原话）；
  - `unknowns` —— 不知道的事，明确禁止推测成数字（「0.5 只是默认值，不是他的水平」）；
  - `pattern` —— 通用压力模式，标注「**不是说他就是这样**」，只许用来理解他。
- 模板里的重构角度、动作素材、暗示句全部降级为**可选素材**，提示词里写死
  「不是给你的台词，严禁按顺序复述」；
- 提示词第一条要求**先回应他刚说的那句话**；信息太少（「唉」这种）就直接问一个具体问题，
  禁止给三条动作；
- `detect_mood()` 认不出来时**返回空串**而不是兜底成「焦虑」——兜底应该是「问」，不是「猜」；
  新增 `angry`（烦躁/火气）档，这种场景不上呼吸法、不劝他别生气、不下发归因暗示句；
- 预估 / 计划 / 诊断同理：没有作答记录时，输出里会明写
  「⚠ 目前没有任何作答记录，下面的分数按默认掌握度 50% 估算，只能看量级」
  「时间分配是等权起步」，不再宣称「按提分性价比排的」。

回归测试在 `tests/test_smoke.py::TestFactDiscipline`，直接拿事故原句跑一遍。

### 11. 面板

- **信息层级**：顶栏只留「教学模式」开关 + 状态胶囊（可点刷新）+ 一个「外观」入口；
  字体 / 字号 / 背景 / 蒙层全部收进**外观抽屉**，不再堆一排在顶栏。
  切页时有页头说明这一页是干什么的；少用的字段（学校 / 年级 / 科目 / 学分）折进「更多设置」。
- **结果一键复制**：计划、诊断、题目、资源、疏导每个结果区右上角都有「复制」，方便直接贴到聊天里；
  空结果显示虚线空态，而不是和正文长得一样。
- **进行中看得见**：所有耗时操作的状态文字前面带一个小 spinner，不再只有一句"生成中…"。
  细滚动条、键盘 focus 描边、`Enter/空格` 也能触发状态刷新。
- **字体可换**：内置 6 套（系统默认 / 微软雅黑苹方 / 思源黑体 Noto / 霞鹜文楷 / 圆体 / 等宽），
  中文走系统字体栈，拉丁与数字用自托管的 Quicksand、Lora、JetBrains Mono（各 15~22KB，离线可用），
  选择会写进 `data/panel_prefs.json`。
- **输出结构化渲染**：后端统一用 `##` 小节 / `-` 列表 / `>` 提示条 / `[[bar:0.x]]` 进度条记号，
  前端渲染成小节标题、列表、进度条与可点链接，**不再把裸文本塞进 `<pre>`**。
- **背景与配色**：全屏背景图 + 白色蒙层 + 淡紫毛玻璃卡片，左侧竖排图标导航。
- **背景可换成自己的图**：顶栏「背景」三选一——**插件自带（默认）** / 我上传的图 / 纯色渐变；
  旁边还有「换图」（PNG / JPG / WebP / GIF，≤8MB）与「蒙层」薄/中/厚（照片花的时候把蒙层调厚，
  字就压得住）。上传的图存在插件的 `data/backgrounds/`，**不进安装包、不覆盖默认那张**；
  「恢复默认」只切模式不删文件，随时能切回来。图丢了会自动退回默认，不会把界面搞成一片白。
  面板由宿主托管时，背景图会改从插件自己的端口取（宿主只代理 `/api/*`，不代理 `/bg/custom`）：
  前端会先把取图地址探测出来再应用，并且**真加载一次做校验**——取不到就退回自带背景并把原因写在旁边，
  不会留一片空白。图片与字体的响应带缓存头，不会每开一次面板重下几 MB。
- 页面由宿主托管时同源相对路径会 404，所以前端会先探测宿主代理，再探测插件自己的
  `127.0.0.1:<panel_port>`，**两边都通**才认为服务可用；静态文件（背景图 / 字体）也由插件端口提供。

### 12. 修行等级：只对真实学习给经验

游戏化的部分单独放一节，因为**最容易做歪**——"点一下 +10"那种激励，本质是让学生
自己骗自己，也和事实纪律冲突。所以规则是硬的：经验只来自真实学习行为。

| 行为 | 经验 |
|---|---|
| 答对一题 | +10 |
| 答错一题 | +3（敢做就有分） |
| 复习到期项 | +6 |
| 完成一次诊断 | +15 |
| 识图诊断 | +12（省了手打） |
| 讲解一个知识点 | +8 |
| 出一轮题 | +5 |
| 掌握度每提升 1% | +2（单次上限 20，防刷） |
| 当天第一次学习 | +10（一天只给一次） |

- **等级**：每级需求递增（60 / 105 / 150 …），20 级封顶；`_progress.py` 里可复算。
- **头衔**：走科举路子——懵懂猫崽 → 描红学童 → 破题生员 → 独步会元 → 状元及第 → 学海宗师，
  每个阶段配一句"人话"提醒（如 10 级：这个阶段的分多半是捡回来的，会的全对）。
  头衔**不加任何数值**，避免"头衔高但水平水"。
- **徽章**：13 个，条件全部来自真实数据——首战告捷 / 三日不辍 / 七日成习 / 月余不怠 /
  十题不倒 / 百题斩 / 稳（30 题以上且正确率 ≥80%）/ 通经三十 / 起死回生 / 望闻问切 /
  传道十次 / 破晓者（7 点前学过）/ 登科（10 级）。
- **界面**：顶栏等级胶囊（点开跳到档案页修行卡片）；档案页有等级、头衔、进度条、
  连续天数、徽章墙（未获得的是灰色锁）、最近获得明细，以及一份可展开的**经验规则说明**。
- **点击特效**：动作完成后按**后端真实增量**飘 `+N EXP`、撒星点；升级时弹「修行突破」横幅。
  前端不做本地假加——飘出来的数字一定和数据库里涨的一致。
- 配置项 `progress_enabled`，关掉就完全不记经验。

### 12. 鼠标轨迹与「钢琴键」解压页

**鼠标轨迹**：划过面板时留一条会散开的青紫轨迹（初音配色），canvas 铺满视口但不吃鼠标事件；
不动鼠标时**主动停掉 requestAnimationFrame**，不会一直在后台空转。
外观抽屉里可开关，默认 `auto`——跟随系统的「减少动态效果」，也可以显式开/关。

**钢琴键解压页**（侧栏「解压」）：

- **平铺的键，每个键音高都不同**：键面直接写音名（C3 / D#4）+ 唱名，一眼看得出它们不一样；
- 声音用 **Web Audio 实时合成**（`OscillatorNode` + 包络 + 一点延迟做空气感），
  **不加载任何音频文件**——离线可用，也不给安装包增加体积；
- 四种音阶：半音阶（默认，每个键都不同）/ 五声 / 大调 / 蓝调；三种音色：电子（初音感）/ 风铃 / 木琴；
  键数 5 / 7 / 9 / 12 列；
- 键数会**按音阶可提供的不同音高数封顶**（五声 20、蓝调 24、大调 28、半音 48），
  这样永远不会为了凑格子出现重复音（第一版这里写错了，28 个键只有 15 个不同音高，已修并加测试）；
- 键盘也能弹：`1234567890` / `qwertyuiop` / `asdfghjkl;` / `zxcvbnm,./` 四排对应四行；
- **这里不给经验**：解压就是解压，经验只来自真实学习行为（见上一节）。
  测试里专门断言这段代码不许调用任何接口。

### 13. 电子板（参考 Mikutap）

侧栏「解压」页有三个模式：**电子板** / **钢琴键** / **切水果**（页面顶部切换）。

**电子板**参考 [Mikutap](https://aidn.jp/mikutap/) 的玩法，抓的是它的三个机制而不是外观：

1. **整块画布都是乐器**：点/拖任意位置都触发声音，位置自由（拖动等于一串联音）；
2. **声音对齐到节拍**：点击会排到**下一个八分音符**上（128 BPM，格 0.234s），
   所以怎么点都不会难听——这是 Mikutap 的灵魂，不是"有键就行"；
3. **画面跟着音频时钟踩拍**：视觉事件按 `AudioContext.currentTime` 排队消费，
   不是跟鼠标走；每 8 小节换一个场景（涟漪 / 曼陀罗 / 声柱 / 点阵 / 斜扫），配色一起换。

- 背景是 4 小节循环：鼓（底鼓 / 军鼓 / 踩镲）+ 贝斯 + 和声垫，用 `Am → F → C → G` 进行，
  由 **lookahead 调度器**（提前 120ms、25ms 心跳）排音符，不会因为主线程卡一下就抖；
- "人声"用**共振峰合成**（锯齿波过 3 组带通，a/i/u/e/o 各一组，带轻微颤音）代替采样，
  所以离线可用、安装包不增大；
- **触发音 20 种**按顺序轮转：10 个元音（两个音区）+ 底鼓 / 军鼓 / 踩镲 / 拍手 / 通鼓 /
  牛铃 / 上升扫频 / 和弦 / 铃铛 / 高音点；
- **点哪都在原地弹出一个图形**（圆 / 三角 / 方 / 星 / 双环，带弹出与旋转动画），
  配色跟着场景走——这是"好看"的主要来源；拖动时按距离节流，一条划过就是一串图形 + 一串音；
- **满屏按钮**：舞台可以全屏，画布按当前尺寸重算，横竖屏都能铺满；解压页也会放宽到更宽的版式。
- **默认音源自带**：`static/audio/pad/` 是 **FluidR3_GM**（**CC BY 3.0**，署名见该目录的 `CREDITS.md`）
  的采样——人声 `choir_aahs`、`music_box`、`marimba`，共 14 个基准音、269KB。用的是 SoundFont 的
  通行做法：**只留几个基准音，其余音高用 `playbackRate` 换算**，所以体积小、音域宽。加载不到时才退回
  实时合成的 20 种音色。
- **点哪都开始**：不要求用户去够那个按钮——点舞台任意位置、按任意键都直接开始（照 Mikutap 的行为）。
- **不再静默失败**：音频上下文被浏览器挂起、初始化异常、满屏被拒，都会在状态行写明原因
  （最常见的就是「浏览器拦住了播放，再点一下屏幕任意位置即可出声」），同时打进控制台。
  之前的"点了没反应又不知道为什么"就是这么来的。

#### 想换成别的声音？——本机导入，不进安装包

Mikutap 不是开源许可：作者条款写明「**仅用于非盈利的公共使用用途**，商业用途请联系作者」，
而且它的音源是初音未来的采样（Crypton 的 IP）。N.E.K.O 本体在 Steam 上架，插件要发官方市场，
**打包这些文件属于商用分发**，所以发行包里一个音频都不带。

但你自己非商业自用是完全允许的，所以做成了**本机导入**：

1. 面板「解压 → 电子板」点 **导入本地音源**，选中你自己那份 Mikutap 的 `mp3` 文件夹
   （用的是 `webkitdirectory`，浏览器直接把文件读给你本机的插件）；
2. 文件存到 `data/mikutap_audio/`（单文件 ≤8MB、最多 120 个），**不进安装包、不上传**；
3. 检测到音源就自动改用真采样播放（每 4 个音补一记底鼓保持节奏），没有就继续用内置合成音。

相关实现：`_games.scan_pad_audio()`（自然序扫描）、`/api/game` 的 `pad-audio` / `import-audio`
两个动作、静态路由 `/pad-audio/<文件名>`（只读、限扩展名、防目录穿越）。

### 14. 切水果（内置小游戏）

- 按住鼠标在果盘上划过去切水果，触屏直接划；**漏掉水果或切到炸弹各扣一条命**，三条命用完结束。
- **积分**：水果分值不同（15~30 分），同一次滑动里连切有**连击奖励**（3 连起算，越多越高但有上限）。
- **等级**：每 120 分升一级，最高 20 级；等级越高**出水果更快、下落更快、炸弹更多**（都封了顶，
  不会变成不可能玩）。
- **记录**：最高分 / 最长连击 / 单局最长存活 / 累计局数 / 累计切中与漏掉，落库保存，重启不丢。
- **成就**：8 个——第一刀 / 破百 / 果王（500 分）/ 连击达人（8 连）/ 手稳（切 ≥20 且零漏）/
  持久（≥90 秒）/ 千果（累计 1000 个）/ 果园主（10 级）。
- 音效全部 **Web Audio 实时合成**（切片是带通扫频噪声、连击是琶音、炸弹是低通噪声 + 低频锯齿），
  不依赖任何音频文件。
- ⚠️ **游戏成绩与修行等级是两条线**：玩这个不加修行经验、也不影响掌握度。
  测试里专门断言了「打一局 999 分之后 `exp_total()` 仍然为 0」——一旦游戏能涨经验，
  整套激励就变成刷分了。
- 规则（水果分值、等级曲线、难度参数）由后端 `/api/game` 下发，JS 不另抄一份，避免两边跑偏。

### ⚠️ 铁律：不要顶层 import「冷门」标准库

宿主是 **PyInstaller 冻结进程**，标准库里**只打包宿主自己（或其依赖）引用过的模块**。
插件和宿主共用同一个解释器，所以「标准库一定有」这个假设**不成立**。

线上真实事故：`_crawl.py` 顶层写了 `import urllib.robotparser`，宿主没打包这个模块，
插件在 import 阶段直接死掉。而宿主把子进程 stderr 吞了，日志里只剩
`PLUGIN_START_FAILED`，`logs/plugin/` 和插件 `data/` 都不生成，**一点线索都没有**。

约定：

```python
try:                       # 宿主有就用官方的
    from urllib.robotparser import RobotFileParser as _HostRobotParser
except Exception:          # 没有就用自带兜底，绝不连累插件启动
    _HostRobotParser = None
```

- 已确认宿主**缺少**：`urllib.robotparser`
- 已按此约定改造（不再依赖）：`http.server` → 自己用 `socket` 写面板服务；
  `gzip` / `zlib` → 解压失败就原样返回；`html` → 自带实体反转义；
  `concurrent.futures` → 缺了退化成串行。
- `tests/test_smoke.py::TestFrozenHostCompat` 会在子进程里**屏蔽这些模块**再 import 一次
  插件，并用 AST 检查禁掉顶层硬导入。新增 import 前先跑它。

### 排查启动失败的正确姿势

宿主吞 stderr，所以插件自己落盘：

- `%TEMP%\neko_study_copilot_crash_import.txt` —— import 阶段崩溃的完整 traceback
- `%TEMP%\neko_study_copilot_crash_startup.txt` —— `on_startup` 阶段
- `%TEMP%\neko_study_copilot_host_modules.txt` —— 宿主冻结环境里哪些标准库可用（探针）
