# MO！策略积木：Scratch 模式重构方案

## 目标

把策略编辑器从“动作清单表单”改为 Scratch 式积木编辑器。普通用户只需要拖动、插入、点击下拉菜单和填写数字，就能组成可执行策略；内部对象编号、协议字段和桥接命令全部隐藏。

这份方案是界面、数据模型和执行器的共同契约。原有《策略积木完整目录》保留为能力字典；本方案规定这些能力如何被压缩成易用积木。

## 一、必须遵守的 Scratch 结构

### 1. 五种连接形状

|形状|中文名称|用途|可以插入的位置|
|---|---|---|---|
|帽子形|当……发生|启动一条策略线程|只能放在脚本顶部|
|堆叠命令|执行一个动作|移动、攻击、生产、维修等|顺序槽、分支槽、循环槽|
|圆角报告器|取得一个值|单位、建筑、数量、位置、资金|命令参数、比较积木|
|六边形布尔|一个判断|是否开始、是否有敌人、是否缺电|如果、重复直到、等待|
|C 形容器|包住一段流程|如果、重复、并行、持续监视|内部只能放允许的连接形状|

禁止把“选择电厂”“攻击目标”“数量大于”做成一排互不相连的卡片。它们必须分别是报告器、命令或布尔积木，并由插槽决定连接关系。

### 2. 积木定义字段

每个积木在注册表中只需要以下字段：

```json
{
  "id": "unit.select",
  "中文名": "选择单位",
  "形状": "报告器",
  "颜色组": "单位",
  "输入": [{"名": "阵营", "类型": "菜单"}, {"名": "类别", "类型": "菜单"}, {"名": "单位", "类型": "菜单"}],
  "输出": "单位引用",
  "允许连接": ["移动.对象", "攻击.对象", "编队.成员"],
  "执行器": "world_model.select_unit"
}
```

`id` 和 `执行器`只供程序使用；用户界面只显示中文名、图标、菜单和提示。

## 二、真正的“指定单位”插排积木

### 1. 用户看到的积木

```text
选择 [盟军 ▼] 的 [步兵 ▼] [海豹突击队 ▼]
```

它是一个圆角报告器，可直接插入：

```text
征召 [选择 盟军 的 步兵 海豹突击队] [数量 20]
攻击 [选择 盟军 的 步兵 海豹突击队] [最近的敌方步兵]
保护 [选择 我方 的 采矿单位 矿车] [选择位置 基地矿区]
```

### 2. 菜单逐级插入

点击第一个插槽后依次显示：

1. 阵营：美国、欧洲联盟、太平洋阵线、苏俄、拉丁同盟、中国、心灵军团、厄普西隆总部、天蝎组织、焚风三子阵营、我方、敌方、中立。
2. 类别：建筑、步兵、装甲、飞机、海军、采矿单位、建设单位、运输单位、支援单位。
3. 具体对象：从单位注册表显示中文名称、图标、科技等级和简短用途。
4. 可选筛选：生命值、部署状态、装载状态、距离、是否空闲、是否受控。

每一级菜单都会保留“任意”选项，因此既能指定一个单位，也能生成单位集合。用户永远不输入内部 ID。

### 3. 指定单位的四种简化模式

|模式|示例|输出|
|---|---|---|
|具体单位|盟军→步兵→海豹突击队|单位类型引用|
|单位集合|我方→装甲→全部坦克|单位集合引用|
|按角色|我方→角色→护矿单位|角色集合引用|
|按条件|敌方→步兵→生命低于 50%|动态集合引用|

“具体单位”和“单位集合”使用同一个积木，只由最后一个菜单的选择方式决定，避免出现四套重复积木。

## 三、Scratch 式积木抽屉

界面左侧只保留 12 个颜色组；每组先显示 6 至 12 个最常用积木，其余放入“更多积木”。

### 1. 事件（黄色）

`当对局开始`、`当敌军出现`、`当基地受攻击`、`当矿车受攻击`、`当科技升级`、`当资源低于底线`、`当任务阶段改变`、`当玩家授权自主作战`、`当对局取消`。

## 四、三个最小可用脚本

### 示例 A：生产并攻击指定单位

```text
当玩家授权自主作战
  如果 <我方资金 > 5000> 那么
    生产 [盟军→步兵→海豹突击队] [数量 20]
    等待 <已生产吗？>
    征召 [盟军→步兵→海豹突击队] [数量 20]
    攻击 [刚刚征召的队伍] 的 [敌方→步兵→最近目标]
    如果 <已击毁吗？> 那么
      选择 [敌方→防御建筑→最近目标]
```

### 示例 B：矿区扩张且不打断主产线

```text
当矿区已经衰减
  如果 <预计扩张后资金仍高于底线> 那么
    并行执行
      生产 [建设单位→机动建设车] [数量 1]
      持续监视 <主建筑产线>
    移动 [刚生产的建设车] 到 [最近的安全新矿区]
    展开 [建设车]
    建造 [经济建筑→矿场] 到 [建设车附近]
```

### 示例 C：接敌后的反应

```text
当敌军出现
  如果 <需要反步兵吗？> 那么
    征召 [我方→反步兵单位] [数量 10]
  如果 <需要反装甲吗？> 那么
    调用策略 [反装甲防守]
  如果 <兵力优势允许总攻> 那么
    攻击 [进攻队] 的 [敌方→生产建筑→最高价值目标]
  否则
    移动 [进攻队] 到 [基地防御圈]
```

## 五、内部执行分层

1. **积木编辑层**：只处理拖放、插槽、中文菜单和脚本保存。
2. **脚本编译层**：把积木树转换为带类型检查的策略 AST，不直接拼接桥接命令。
3. **调度层**：把 AST 拆成事件线程、产线线程、队伍线程和验证线程。
4. **世界模型层**：每次线程运行都读取最新快照，目标引用失效时重新解析。
5. **动作执行层**：提交单个经过授权的游戏动作，等待回执，不阻塞其他独立线程。
6. **验证与学习层**：记录成功、失败、超时、冲突和战损，供临时策略库使用。

## 六、必须删除或隐藏的旧式设计

- 删除用户直接填写内部单位 ID、建筑 ID、协议字段的入口。
- 不再让“攻击指定目标”“选择电厂”“数量大于”作为平级卡片堆放。
- 不再让一个动作同时承担目标筛选、数量计算、路径规划和执行验证。
- 不再把所有生产任务排进一条全局队列；产线必须是独立资源。
- 复杂参数默认折叠到“更多选项”，初始界面只显示常用插槽。

## 七、迁移顺序

1. 先实现五种连接形状和类型检查。
2. 把“指定单位”改为阵营→类别→具体单位的插排报告器。
3. 把移动、攻击、生产、建造、插件、装载、部署改成命令积木。
4. 接入事件帽子、如果/否则、重复、并行和验证积木。
5. 将现有固定策略转换为脚本树，旧硬编码只保留为执行器适配器。
6. 最后开放临时学习库和玩家自定义积木，不允许未验证脚本直接进入正式库。

验收标准：普通用户不查看任何 ID 或英文，就能在十分钟内搭出“生产 20 个海豹→组成队伍→攻击最近敌方步兵→击毁后转攻防御建筑”的完整脚本，并且编辑器能指出缺少目标、数字类型错误、产线冲突和缺少验证的具体积木位置。

## 八、变量、列表与自制积木的数据契约

### 1. 变量

变量存放在当前策略的 `payload.variables` 中，形式为“中文名称→值”。值必须标注类型：数字、文字、真假、单位引用、队伍引用、位置引用。默认值只能在编辑器中填写；执行时每个策略实例拥有自己的变量副本，不会污染其他对局。

### 2. 列表

列表存放在 `payload.lists` 中，形式为“中文名称→项目数组”。列表项目可以是文字、单位引用、目标引用或位置引用。列表积木必须提供：加入、删除、清空、项目数量、取第一个、取最近目标、遍历每个项目。列表遍历期间不得修改同一个列表，修改操作进入下一轮循环，避免调度器跳项。

### 3. 自制积木

自制积木存放在 `payload.custom_blocks` 中，每个定义包含：中文名称、形状、模板、参数名称、颜色和子脚本。自制积木只允许调用已经注册的积木，不允许直接填写桥接命令、协议版本、内部单位 ID 或任意 Python/JavaScript 代码。保存时执行器检查参数类型、递归深度和动作验证；不合格的自制积木只能保存在临时学习库，不能进入正式策略。

### 4. 作用域

变量和列表默认是“当前策略实例”；标记为“猫娘长期记忆”的内容才写入学习库。自制积木默认跟随策略保存，也可以通过“导出到我的积木库”供同一猫娘的其他策略使用。正式策略只能调用已验证的自制积木版本。
