# MO！策略积木一万条规模整体重构方案

## 0. 先确定问题

当前截图中的右侧内容不是新的积木树，而是旧策略的字符串流程被包装成橙色卡片。它存在三个根本错误：

1. 右侧条目没有来自左侧积木注册表的唯一定义。
2. 历史英文 ID 没有完成“ID → 中文积木 → 参数插槽”的迁移，只是把原文显示出来。
3. 条件、目标、行动、验证没有形成嵌套树，用户无法像 Scratch 一样把报告器插入命令的插槽。

因此不能继续在现有卡片上加按钮，必须更换编辑器数据模型和渲染流程。

## 1. 总体架构

```text
规则数据层
  rulesmo.ini + CSF + MO Wiki资料 + 玩家别名
        ↓
统一知识注册表
  单位、建筑、武器、护甲、科技、产线、支援技能、地形
        ↓
积木注册表（唯一来源）
  中文名称、形状、插槽类型、菜单、执行器、验证器
        ↓
策略脚本树
  帽子 → 控制容器 → 条件/报告器/命令/验证
        ↓
类型检查与编译器
  目标解析、数字检查、产线冲突、权限、验证完整性
        ↓
调度运行时
  事件线程、产线线程、队伍线程、验证线程、学习线程
        ↓
动作适配器
  现有桥接动作函数，只负责执行已编译动作
```

旧的 `plugin.py`、`adaptive_tasks.py`、经济和战斗模块不得再直接读取历史策略字符串。它们只能作为动作适配器被积木执行器调用。

## 2. 一万条策略的组织方式

一万条策略不能全部作为左侧积木。左侧只能放“积木类型”；策略放在右侧脚本库。

### 2.1 三层索引

|层级|数量目标|内容|
|---|---:|---|
|基础积木类型|约 300|条件、报告器、命令、验证、控制器、学习器|
|可复用自制积木|约 2,000|由基础积木组合的生产、进攻、防守、扩张模板|
|策略脚本|10,000+|按模式、阵营、地图、科技阶段、威胁和人格组合索引|

一条策略只保存积木树和参数，不复制积木定义。这样 1 万条策略不会导致编辑器加载 1 万份重复 UI。

### 2.2 策略唯一索引

每条策略必须带有以下标签：

```json
{
  "模式": "遭遇战",
  "阵营": "美国",
  "地图": "任意",
  "阶段": "中期",
  "威胁": ["步兵群", "轻装甲"],
  "目标": "守住矿区并推进",
  "人格": ["平衡运营", "精打细算"],
  "来源": "玩家/规则迁移/猫娘学习",
  "状态": "已验证"
}
```

数据库按标签和威胁建立索引，编辑器只加载当前筛选结果，禁止一次渲染全部策略。

## 3. 唯一积木注册表

### 3.1 注册表定义

```json
{
  "id": "行动.攻击",
  "中文名": "攻击",
  "形状": "命令",
  "颜色组": "行动",
  "插槽": [
    {"名": "队伍", "类型": "队伍引用", "必填": true},
    {"名": "目标", "类型": "目标引用", "必填": true},
    {"名": "方式", "类型": "菜单", "默认": "集中火力"}
  ],
  "允许子积木": ["验证.已击毁", "控制.重复直到", "控制.超时回退"],
  "执行器": "action_adapter.attack",
  "验证器": "验证.已击毁"
}
```

左侧积木和右侧积木都必须通过 `id` 读取同一个定义。右侧绝对不能出现只存在于某条历史策略中的“神秘积木”。

### 3.2 基础积木分类

1. 事件帽子：对局开始、敌军出现、基地受袭、资源变化、科技升级、任务阶段变化、玩家授权、对局结束。
2. 控制容器：如果、否则、重复、重复直到、持续监视、并行、等待、超时、重试、回退、调用策略。
3. 条件布尔：对局状态、连接状态、权限、单位数量、兵力比例、资金底线、威胁类别、路径、可见性、产线状态。
4. 报告器：单位、建筑、队伍、目标、位置、数字、比例、变量、列表项目、支援技能、科技等级。
5. 命令：移动、攻击、部署、装载、维修、占领、生产、建造、插件覆盖、支援技能、释放控制权。
6. 验证器：到达、生产完成、建造完成、覆盖成功、装载成功、部署成功、击毁、维修完成、阶段改变。
7. 学习器：记录战损、收益、耗时、失败层级、失败原因、适用环境、方案评分、临时归档。

## 4. 指定单位必须是可插入报告器

右侧必须显示真实的插槽，而不是一行文本：

```text
生产 [选择单位：美国 → 步兵 → 海豹突击队] 数量 [20]
攻击 [刚生产的队伍] 目标 [敌方 → 步兵 → 最近目标]
```

选择单位报告器的交互固定为：

```text
关系 → 子阵营 → 类别 → 具体单位 → 可选筛选
```

其中“关系”包含我方、敌方、中立；“类别”包含建筑、步兵、装甲、飞机、海军、采矿、建设、运输和支援。单位菜单数据来自统一注册表，显示中文别名、科技等级、角色、威胁标签和是否插件。

## 5. Scratch/TW 式编辑器改造

### 5.1 工作区布局

```text
左侧：积木抽屉       中央：脚本画布                 右侧：属性/错误检查
分类按钮             帽子积木                     当前积木参数
积木预览             C 形控制容器                  中文提示
搜索积木             命令堆叠                     连接错误
                     报告器插槽                   验证缺口
```

### 5.2 右侧堆叠规则

- 每个节点显示真实形状：帽子、命令、报告器、布尔或 C 形容器。
- 右侧只显示 `label_zh + 插槽 + 图标`，说明文字默认隐藏。
- 备注、高级筛选、失败回退放入折叠的属性面板。
- 拖动时显示插入线和合法/非法插槽颜色。
- 删除、复制、撤销、重做均操作 AST 节点，不操作字符串。
- 历史条款迁移后直接渲染为对应注册表积木；找不到映射时标红并显示“待迁移”，不能伪装成普通积木。

### 5.3 容器嵌套

```text
当玩家授权自主作战
  如果 <现金高于 [5000]> 那么
    并行执行
      生产 [海豹突击队] 数量 [20]
      持续监视 <基地防御圈>
    等待 <生产完成>
    攻击 [进攻队] 目标 [最近敌方步兵]
    确认 <目标已击毁>
```

## 6. 历史一万条策略迁移

### 6.1 迁移管线

1. 读取历史条款的原始 ID、中文名称、条件、动作、目标和来源。
2. 通过迁移字典把每个动作映射到注册表积木 ID。
3. 把英文或内部目标转换成阵营、类别、单位报告器。
4. 把条件转换成布尔积木，把数字转换成数字插槽。
5. 把顺序、循环、并行、超时转换成 C 形控制器。
6. 自动补齐验证积木；无法推断的验证标记为待补全。
7. 编译并运行静态检查。
8. 通过离线模拟后进入临时库，绝不直接覆盖正式策略。

### 6.2 迁移结果状态

|状态|含义|编辑器显示|
|---|---|---|
|已转换|所有节点均有注册表定义|正常积木|
|待补目标|动作存在但目标无法解析|红色目标插槽|
|待补验证|动作没有可靠完成条件|黄色验证插槽|
|冲突|同一单位或产线被并行占用|红色冲突线|
|不支持|旧逻辑没有对应适配器|灰色待实现积木|

## 7. 执行器统一接入

所有历史模块改造成以下适配器接口：

```python
async def execute(node, world, runtime) -> ActionResult:
    """只执行一个已经通过类型检查的积木节点。"""
```

适配器按积木 ID 注册：

```text
行动.攻击       → 现有攻击命令适配器
建筑.寻找插件位 → 插件覆盖适配器
经济.分配预算   → 经济调度适配器
验证.已击毁     → 动作验证适配器
```

旧模块不再自行决定策略顺序；顺序、条件、并行和回退全部由 AST 调度器决定。这样 1 万条策略共用同一套执行器，避免复制 1 万份硬编码。

## 8. 规则与 Wiki 数据接入

数据导入器读取：

- `rulesmo.ini`：单位、建筑、武器、弹头、科技前置、产线、插件覆盖、部署和载员。
- CSF 文件：单位和建筑中文名称、简介、提示文本。
- 心灵终结 Wiki 知识：角色、科技等级、克制标签、范围伤害、防空、特殊机制。
- `player_aliases.json`：玩家简称和常用中文名。

导入后统一写入注册表，保留 `source_file`、`source_key`、`source_hash` 和 `imported_at`。游戏原文件只读，插件使用自己的快照，规则更新时生成差异报告。

## 9. 一万条规模的验收标准

1. 左侧抽屉只显示注册表积木；右侧不存在未注册的普通积木。
2. 任意历史策略都能追溯到原始 ID 和对应中文积木。
3. 找不到映射时明确标红，不得显示“已迁移作战行动”。
4. 普通用户十分钟内可搭建“生产 20 个海豹并攻击最近步兵”的脚本。
5. 编辑器可处理 10,000 条策略，首屏只加载当前分页和脚本树。
6. 每个动作都能定位目标、执行器和验证器。
7. 任意策略都能离线编译、模拟、回放和比较，不依赖真实桥接。
8. 只有通过类型检查、动作验证和离线模拟的策略才能进入正式库。
