# 天气猫娘 · neko_weather

让猫娘帮你查天气，并且**每天早上主动播报**。数据来自 Open-Meteo，**完全免费、不需要任何 API Key**。

## 为什么做这个

我统计了插件市场全部 85 个插件：**天气是彻底的空白，0 个覆盖**。对「住在你电脑里、会主动说话」的 AI 猫娘来说，天气是最自然、使用频率最高的实时信息——她本来就该知道今天要不要带伞。

## 功能

| 能力 | 说明 |
|---|---|
| 当前天气 | 温度、体感、湿度、风速、天气现象（带图标） |
| 逐日预报 | 1-7 天，最高/最低温、降水概率、日出日落 |
| 逐小时预报 | 从现在开始的未来 N 小时温度与降水概率，**跨天自动顺延** |
| 穿衣建议 | 按体感温度分 8 档给建议 |
| 带伞建议 | 综合天气码、实时降水、当日降水概率 |
| 出行建议 | 雷雨、降雪、大风、高温、低温分别提醒 |
| 每日主动播报 | 到点由猫娘主动把今天天气说给你听 |
| **猫娘语气** | 撒娇口吻 + 结尾「喵～」，可自定义后缀或关闭 |
| **语音播报** | 播报以「需要回应」的形式推送，触发角色语音念出来 |
| 地名容错 | 中文名 / 英文名 / `东京, JP` 限定 / `30.29,120.16` 坐标 |
| 记住城市 | 说一句「把主页城市设成杭州」就持久化 |

## 聊天里怎么用

插件已经注册了 5 个 LLM 工具，**猫娘会自己判断什么时候调用**，你正常说话就行：

| 工具 | 会命中的说法 |
|---|---|
| `get_weather` | 今天天气怎么样 / 外面冷不冷 / 明天要带伞吗 / 杭州天气 / 现在几度 / 今天热不热 / 要不要穿外套 |
| `get_hourly_weather` | 等会儿会不会下雨 / 下午要带伞吗 / 今晚冷不冷 / 过两小时天气怎么样 |
| `set_home_city` | 我住在杭州 / 以后看上海的天气 |
| `push_weather_brief` | 给我播报一下天气 / 念一下今天天气 / 早上好，说一下天气 |
| `check_daily_weather_push` | 今天播报了吗 / 说好的天气呢 |

区别在于：前三个回答完就结束了；`push_weather_brief` 和 `check_daily_weather_push` 会让猫娘**主动播报并念出来**。

## 猫娘语气与语音

播报长这样：

> 主人主人～人家帮你看好啦喵～ 杭州 · 浙江 · 中国现在阴☁️，气温 19°C（体感 21°C）。湿度 96%，风速 7.6 km/h。接下来几天嘛：明天阴☁️16~22°C，降水概率 10%；后天晴☀️12~22°C，降水概率 0%。要穿什么的话～有点凉凉的，加一件薄外套吧喵～。伞的事情交给人家记着：今天大概率要下雨，伞一定要带上喵～。出门的话适合出门玩耍喵～。记得照顾好自己哦喵～

天气现象也会跟着换说法：晴天说「心情也跟着亮闪闪的」、下雪说「好想堆雪人」、打雷说「人家有点怕…」。

三个相关配置：

```toml
[weather]
cute = true        # 关掉就回到中性的「天气播报」腔
cat_suffix = ""    # 留空用「喵～」，可换「呜喵」「nya～」
voice = true       # 让猫娘念出来（见下）
```

### 关于语音触发

插件通过 `push_message` 的 **`ai_behavior`** 控制猫娘说不说：

| 取值 | 行为 |
|---|---|
| `respond` | 模型读取并**回应** → 走角色语音，猫娘会念出来 |
| `read` | 只写进上下文，猫娘不一定开口 |
| `blind` | 只在聊天框显示，模型完全不知道 |

`voice = true` 时每日播报和主动播报用 `respond`，所以猫娘会把天气**念给你听**。关掉则用 `read`，只留文字记录。

注意：插件本身**不能直接调 TTS**。它只能把文字交给宿主，由猫娘自己的语音系统决定怎么说 —— 所以语气和断句会受角色当前语音设置影响（语速、情绪、音色都在你的角色配置里）。

## 阴阳怪气翻译腔彩蛋

有概率触发一段"翻译腔吐槽版"播报，默认 **20%**：

> 让我看看明天有哪个倒霉蛋要被雨淋湿？哦，该死，居然是晴天，你可真是走了狗屎运，我的老伙计。邯郸 · 河北省 · 中国现在大致晴朗🌤️，气温17°C，体感13°C。未来：明天大致晴朗🌤️12~27°C，降水概率0%；后天晴☀️15~29°C，降水概率0%。偏冷哦，外套或卫衣别忘了喵～。不用担心下雨，伞可以放家里喵～。适合出门玩耍喵～。我向上帝发誓，太阳会像隔壁苏珊婶婶的烤箱一样热情，别把自己晒成猫干。喵。愿上帝保佑你，别感冒。

### 设计原则：数据由代码算好，彩蛋只负责套壳

这是整个彩蛋最重要的一条。模板里**只有占位符**，所有数值都从已经算好的 `report` 里搬运：

```
{location} {current_condition} {temp} {feels_like} {humidity} {wind}
{forecast} {clothing} {umbrella} {outing}
```

彩蛋**不解析也不修改**任何天气数据。所以无论模板怎么变，都不会出现"17°C 被写成 27°C"。

每个模板必须包含 7 个必需占位符（`location`/`current_condition`/`temp`/`forecast`/`clothing`/`umbrella`/`outing`），
`feels_like`/`humidity`/`wind` 可选（短模板里不放是正常的）。测试会逐条校验模板完整性。

### 按天气分类抽模板

优先级：**雷暴 > 雪 > 雨 > 高温 > 严寒 > 大风 > 雾 > 晴 > 多云 > 通用**

每类有多个模板随机抽，所以同一类天气不会每次都是同一句。类别缺模板时逐级回退到通用池。

### 在哪里调概率

**最直接的方式：改运行配置文件**

```
<用户数据根目录>/plugins/neko_weather/config/plugin.toml
# Windows 默认：%LOCALAPPDATA%\N.E.K.O\plugins\neko_weather\config\plugin.toml
```

```toml
[weather]
snark_enabled = true
snark_probability = 0.2      # ← 改这个：0.2 = 20%
snark_cooldown = 2
snark_style = "zh"
snark_tags = true
```

存盘即生效，**不用重启插件** —— 插件会收到配置变更事件并自动刷新。

**插件管理器里：插件列表 → 天气猫娘 → 「配置」页**

配置页会按 `[plugin_runtime]` / `[weather]` 分段列出所有可编辑的项，找到 `weather` 段下的 `snark_probability` 改掉即可。

> **⚠️ 版本差异**
>
> 本项目附带了 `config.schema.json`，它能把配置渲染成**带中文标题和说明的表单**
> （`snark_probability` 会显示成「彩蛋触发概率」下拉框）。
>
> 但那个能力需要 **2026-09-11 之后构建的 N.E.K.O**（和「开发插件」页面同一批）。
> 在较早的版本里（例如 Steam v0.9.0 Patch 2），后端不会返回 `config_schema`，
> 配置页只能按**原始键名**显示 —— 你会看到 `snark_probability` 这个英文键，
> 没有中文标签和下拉框。这时直接改上面的 TOML 文件反而更清楚。

概率支持几种写法，都会正确解析：`0.2`、`20`、`"20%"`、`"0.35"`。
冷却的作用是防止连着刷：**概率调成 100% 也不会每次都彩蛋**，仍然要等冷却过去。

### 加自己的模板

在运行配置里加一段 `[weather.snark_custom_templates]`，**整体替换**对应类别：

```toml
[weather.snark_custom_templates]
sunny = [
  "今天的太阳简直是在针对你，我亲爱的老伙计。{location} {current_condition} {temp}°C，体感{feels_like}°C。{forecast}。{clothing}。{umbrella}。{outing}。喵。"
]
rain = [
  "又下雨了？真是毫无惊喜的人生。{location} {temp}°C。{forecast}。{clothing}。{umbrella}。{outing}。喵。"
]
```

类别键可用：`general` `sunny` `cloudy` `rain` `storm` `snow` `hot` `cold` `wind` `fog`。
模板里必须写全那 7 个必需占位符，否则测试会报缺哪个。

## 安装方式

### 先确认你的版本

「加载未打包插件」所在的页面只存在于 **2026-09-11 之后构建的 N.E.K.O**。
侧边栏入口叫 **「开发插件」**，页面大标题才叫「开发模式」——在导航里找「开发模式」是找不到的。
Steam 的 v0.9.0 Patch 2 构建时间戳是 `2026-09-11 17:27`，比开发页面那个提交（`20:34`）早 3 小时，
所以那一版没有这个页面；用下面的方式二即可。

### 方式一：开发插件页（需要较新构建）

1. 打开 N.E.K.O → 插件管理器 → 左侧 **开发插件**，打开开关
2. 点 **加载未打包插件**，选择本目录：`<你放的位置>/neko-plugins/neko_weather`
   （必须选到含 `plugin.toml` 的那一层，且填**运行后端那台机器**上的绝对路径）
3. 点 **校验** 确认无误，再点 **加载未打包插件**，然后 **启动**
4. 去「入口点」页触发 `get_weather`（city 填 `杭州`）验证

### 方式二：用自带打包接口（**旧版本也能用**，推荐）

把本目录放到 N.E.K.O 的用户插件根目录，然后调用它自带的 `plugin-cli` 打包接口：

```powershell
# 用户插件根目录（官方只允许打包位于这里的源码）
$root = "$env:LOCALAPPDATA\N.E.K.O\.neko-plugin-installations\plugins"

# 把本目录复制进去
Copy-Item "<本插件所在目录>" $root -Recurse -Force

# 再调用 plugin-cli/build 生成安装包（可用浏览器打开 http://127.0.0.1:48916/docs 查看接口）
```

生成的 `.neko-plugin` 放在 `%LOCALAPPDATA%\N.E.K.O\.neko-plugin-packages\`，
然后在插件管理器的 **包管理** 页面导入即可。

> 接口细节：`POST http://127.0.0.1:48916/plugin-cli/build`
> body `{"mode":"single","plugin":"<插件目录绝对路径>"}`

### 方式三：官方 CLI（要发布到市场时）

放到 N.E.K.O 源码的 `plugin/plugins/` 下：

```bash
uv run neko-plugin check neko_weather
uv run neko-plugin build neko_weather --out neko_weather.neko-plugin
```

## 配置

编辑 `<用户数据根目录>/plugins/neko_weather/config/plugin.toml`
（Windows 默认 `%LOCALAPPDATA%\N.E.K.O\plugins\neko_weather\config\plugin.toml`），
或在插件管理器的「配置」页里改（带了 `config.schema.json`，会渲染成表单）。

**最少只需要改一项**：

```toml
[weather]
home_city = "杭州"
```

完整可选项：

```toml
[weather]
home_city = ""              # 常用城市；留空则每次都要显式给城市
geocode_language = "zh"     # 地名返回语言
timeout_seconds = 15
default_days = 3            # 默认看几天预报
temperature_unit = "celsius"
daily_push = true           # 是否每日主动播报
push_time = "07:30"         # 播报时间（电脑本地时间，24 小时制）
push_window_minutes = 180   # 超过这个时长就不再补播，避免开机刷屏
push_city = ""              # 播报专用城市，留空用 home_city
include_advice = true
cute = true                 # 猫娘语气（撒娇 + 喵）
cat_suffix = ""             # 自定义语气后缀，留空用「喵～」
voice = true                # 让猫娘把播报念出来
```

### 关于每日播报

定时任务每 60 秒检查一次「今天是否已经播报过」。到了 `push_time` 之后：

- 在 `push_window_minutes` 窗口内 → 立刻播报一次
- 已经超出窗口（比如电脑一整天没开机）→ **跳过今天**，不在开机瞬间补推一堆过期信息
- 想立刻看效果，用 `push_daily_brief` 入口手动推一次，不用等到明天早上

## 两个值得一提的实现细节

### 1. 中文地名歧义

Open-Meteo 的地理编码接口**中文查询会优先命中中国境内的同名小地方**。实测查「东京」返回的是：

```
东京/江苏/CN   lat=32.20 lon=119.28
东京/浙江/CN   lat=28.05 lon=119.42
```

真正的日本东京根本不在结果里。所以 `_geo.py` 做了两层处理：

- **别名表**：把约 90 个容易歧义的常见城市（东京、首尔、纽约、伦敦、杭州、成都……）直接钉到确定的国家与行政区
- **候选打分**：按国家提示（±60）、行政区提示（±35）、地名匹配、居民点类型、人口规模综合排序；机场、村庄会被压低

现在查「东京」会稳定返回 `東京 · 东京都 · 日本`。

### 2. 逐小时预报跨天顺延

Open-Meteo 的 hourly 数据按自然日返回。深夜查询时今天只剩 1-2 个小时，直接截取会得到一条没有意义的预报。`summarize_hourly` 会从「现在」开始取，取不满就顺势用第二天的数据补上；插件在请求小时级数据时会自动把 `forecast_days` 提到 2。实测 22:06 查 6 小时，返回的是 23:00 → 04:00 的连续数据。

## 已知限制

- Open-Meteo 是免费公共接口，**有速率限制**，个人使用完全够，别做高频轮询。
- 地名别名表是手工维护的，冷门小地方依赖接口本身，可能仍需用 `城市, 国家码` 限定。
- `7 天预报` 只能到 7 天，Open-Meteo 免费档不支持更远。
- 温度单位配置项目前只影响展示文案，实际请求固定摄氏度。
- 播报时间用**电脑本地时间**；电脑时区不对的话，播报时间也会偏。
