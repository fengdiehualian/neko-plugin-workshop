# 第一版收口说明

日期：2026-10-25。代码版本：6.0.1。交付级别：候选版，不是已完成真实对局识别的正式版。

## 本轮修复

- 放大牌面只作为区域观察，不写 `last_order_card`，不产生出牌事件，不固定归属我方。
- 删除全局“最近放大卡牌”自动分配给新单位的认领逻辑。同一张观察不会再命名多个敌我单位。
- `recognized_cards` 使用 `observation_id` 与 `frame_id`，不伪造棋盘 `instance_id`。这些是最近观察，不是当前棋盘清单。
- 未知回合保留 `null`。普通回合按钮只证明按钮位置；未验证的激活态不能提供行动方。未知、携带状态与重复帧不计入回合切换确认。
- 界面模型严格按 `models_manifest.json` 的 `capabilities` 过滤。当前只有 `card_back`、`end_turn_button` 通过；其余八类不进入场景、单位跟踪或卡牌裁图。
- 加载时校验类别 ID/唯一性、任务、映射版本、模型路径、类别数、文件 SHA-256、静态输入输出形状。缺失/非法契约拒绝加载，不按旧七类解释新权重。
- 卡牌原始最高分类为 conflict 或资源无效时直接 unknown，不让次高结果顶替，也不重新归一化以放大分数。
- 修复模型测试夹具：假权重使用独立测试清单哈希，生产 SHA 校验保持严格。
- 面板展示实际启用类别和可信卡数；数字为 null 时显示未知，不显示 0。保留概览、记录、诊断、设置，不恢复卡组、目标、连接测试和卡牌数量说明区域。

## 验证结果

- Python 3.11.9：`668 passed`，命令为 `.venv311\Scripts\python.exe -B -m pytest tests -q -p no:cacheprovider`。
- TSX：本机已有 esbuild 编译通过。宿主实际渲染、加载另行记录，不能由语法检查替代。
- 两个真实 ONNX 的 SHA-256 与模型清单一致；使用已有训练环境的 ONNX Runtime CPU provider 执行加载与空白输入冒烟成功，输入输出形状正确、结果有限。
- 真实模型包装层状态：界面模型 loaded、supported_class_count=2；卡牌模型 loaded、trusted_card_count=0，空白裁图返回 unknown。
- 空白输入仅证明加载和张量链路，不证明对局准确率或性能达标。CPU 推理在不同线程配置和冷启动下差异明显，本轮不新增性能达标结论。
- 本轮不训练、不下载、不增加白名单、不读取私人录屏内容，不发送真实播报，不启动或操作 KARDS。

## 发布与回滚

第一版以 dev 候选收口。完成源码回归后备份并同步 dev，通过宿主重载检查 `6.0.1`、双模型哈希、supported 类别、可信卡数和 dry-run 状态。保持正式版停用；不为满足部署脚本而伪造 `delivery.submitted` 或复用旧 SDK 接受记录。

实际同步清单、逐文件哈希、备份位置和宿主读取结果存放在插件仓库外的 `kards-acceptance` 目录，避免验收报告进入源产物指纹后反复改变指纹。若宿主加载失败，用同步报告中的备份恢复原 dev 文件并重新加载；配置、模型和启用覆盖分别核验。

## 第一版结束时的限制

- 还没有通过真实画面验收的具体卡牌；卡牌效果、单位身份、出牌、阵亡、回合归属和胜负不能宣称识别可靠。
- 当前界面标签来自启发式预标和程序化补标；独立真值不足，另一模型同意不等于答案正确。
- 私有录屏未上传或改写，原始素材和旧训练结果保留。
- 完整离线分发包、模型/图像再分发条件和真实对局端到端验证仍未完成。
- 后续若继续开发，应先补可靠的独立验证证据及界面训练标签，再考虑提升能力白名单。本版不靠放宽阈值解除限制。
