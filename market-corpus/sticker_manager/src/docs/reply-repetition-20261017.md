## 目前能定位到哪里

只读检查了实际构建宿主快照
`%LOCALAPPDATA%\Temp\neko-exe-build-20261017-c21391a\source`：

- `main_logic/omni_offline_client/_tools.py`：先流式返回工具前的正文，执行工具后 `continue`，再次请求模型。
- 代码会把工具前正文写入 assistant tool-call 的 `content`，不是简单地无条件丢弃它。
- `_streaming.py` 的 `tool_round_persisted` 只重置最终历史段，完整轮次缓冲仍保留工具前正文；
  这本身不能证明它重播了正文。
- 插件 `reply_tail` API 只登记显示图片；返回的 `note` 是给模型读的普通字符串，没有
  “已答完则停止本轮续答”的宿主控制字段。

当前强嫌疑是模型工具续答时重说已发出的正文，但现有日志没有原始 HTTP 响应分段，
不能排除服务端丢弃 assistant content、客户端适配或拼接链路重放。
也不能从“只有一次工具调用”推出模型只输出过一次正文。

插件不能读取或过滤宿主的正文/TTS 输出流。现有公开 SDK 也不能用工具返回值硬停正文。
因此不能通过新写一个 `stop=true` 字段或再加强提示词声称修复。
保持“只改插件”边界，未修改宿主源码、安装目录、当前 API 设置或聊天记录。

## 原始模型流观察器

`tools/trace_reply_http.py` 只使用 Python 标准库，无需安装依赖。
只监听 `127.0.0.1`，转发到启动参数指定的固定上游；不跟随重定向，不读取或修改宿主配置。
只支持 OpenAI Chat Completions 的文字 HTTP/JSON/SSE 链路，不支持实时语音 WebSocket、
Gemini 原生或 Anthropic 原生协议。

启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 'D:\neko kaifa3\n.e.k.o_plugin_sticker_manager\tools\start_reply_trace.ps1'
```

当前免费文字上游默认仍是 `https://www.lanlan.tech/text/v1`。
其他接口须用 `-UpstreamBase` 指定原有实际上游，不能换成别的模型来验证本问题。
端口冲突用 `-Port` 指定空闲端口。

接入方式：在宿主支持的自定义文字模型配置中，把**实际文字对话使用的 OpenAI 兼容 Base URL**
临时设置为启动后打印的 `http://127.0.0.1:49321/v1`，模型名称、Key 和其他生成设置保留。
这里只是诊断接入说明，本次未替你切换设置。若当前免费预设不允许改文字 URL，
需通过自定义文字接口保持相同 `free-model`、免费 Key 和生成参数；确认仍调用同一免费上游。
请勿把实时语音 URL 改成这个 HTTP 地址。

开始一个新文字会话，用平常聊天复现一次。观察器不会主动发消息，也不会调用额外模型。
测试结束恢复原有文字 API 地址，再按 Ctrl+C 关闭观察器。

输出是 `D:\neko kaifa3\dist\test-builds\20261017-reply-diagnostics\reply-trace-*.jsonl`。
原请求 JSON、认证头与回复内容照常转发；落盘只保留字数、随机会话密钥生成的 HMAC 指纹、
调用标识 SHA256 指纹、工具名白名单、时间、完成状态和比较结论，不保存原文、Key、图片或完整请求。
内存比较有界，单个 trace 上限 8 MiB，达到上限后继续转发但不再记录。
请求/回复内容不被改写；诊断代理会增加一次本地转发，不能用于证明原有延迟完全不变。

判读：

| 证据 | 定位与后续 |
| --- | --- |
| 后续请求未带回原先正文；提供方重新输出 | 修历史/接口适配，不靠提示词 |
| 后续请求带回原正文；提供方仍重说 | 修工具续答控制或工具边界处的确定性重复前缀过滤 |
| 提供方只输出一次，但同轮宿主记录/界面两次 | 追宿主流式拼接、UI/TTS 调度 |
| 调用身份无法关联、流不完整、超长截断或不支持的编码 | 证据不足，不能宣称排除了任意一层 |

`provider_replayed_pretool=true` 只判断规范化后“后续输出以完整的前文开头”，
不是所有语义复述的检测器；插入语气词、改写或仅重说中段可能漏检。
工具带图后出现额外 user image 消息、工具 ID 缺失等也可能无法关联，报告会保留这个限制。
自然档 14:38:37 的部分重复由离线头部重复检测另行发现。

## 修复边界

诊断结果若落在宿主工具循环，需要宿主提供明确、受原始回复身份约束的续答策略，
或在工具边界上过滤已发出的重复前缀，同时保留真正新增的正文；不能一刀切吞掉所有工具后文本，
否则会丢掉“先查图、后回答”的正常轮次、失败说明和其他工具的结果回答。
该修复要分别验证正文先发、只发图、空候选、工具失败、打断与新轮次，以及 UI/TTS/历史一致性。

本次没有越界改宿主，也没有用抹掉气泡、清空历史或二次发送替代原正文的方式掩盖问题。
诊断版不等于已修复版，需同条件实机复现后再据证据落修复。
