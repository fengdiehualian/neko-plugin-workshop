# 表情包管理 0.9.4

本次只更新图片投递链路，保留 0.9.3 的面板、候选检索、明确 ID 选图和频率设置。
插件 ID 保持 `sticker_manager`，只在 GitHub 发行，不通知插件市场。

## 更新

- 宿主同时提供可信原回复上下文与 `reply_tail` SDK 时，工具登记图片后立即返回，
  由宿主将图片排在原回复全部文字呈现之后；不等待语音播放结束。
- 兼容尾发通道为原图提供独立的 1MiB 字节预算，内置 190 张 GIF 全部可保留原字节，
  避免提前换成普通消息预算内的有损发送版。原图本身的分辨率不会提高。
- 登记不等于已发送。只有确认提交才更新使用次数、发送冷却及台账；
  登记回执不确定时查询原登记，不立即重发。关闭插件、取消和并发结算按同一身份处理。
- 图片上传后重新核对文件、启停和激活区；失效时不先发配文或登记图片。
- 兼容 SDK 下复用工具的原回复角色，避免候选查询额外探测角色，保留分角色去重。
  工具和登记耗时沿用普通运行日志，不增加聊天采集或诊断代理。

## 安装与兼容

从本次 GitHub Release 下载 `sticker_manager.neko-plugin`，在插件管理中覆盖导入。
正常升级保留配置、图库、条目 ID 和使用记录；不要卸载清除数据。

`send.host_reply_tail=true` 默认请求尾发能力。缺少可信上下文或 SDK 能力时，
保持旧版即时发送；单独升级插件不能给旧宿主添加尾发接口。
面板试发、后台 Agent 和语音不属于本次原回复尾发保证，仍使用普通消息预算和发送版。
超过尾发预算的图片仍按既有发送版、上传或拒绝规则处理，不静默压平动画。

## 已知限制

- 模型是否调用工具、图片是否符合对话仍依赖主回复模型。
- 重复回复及在正文或括号动作里叙述选图过程仍可能发生，本版本没有根治这两项问题。
- 宿主确认提交不是前端展示确认；本地隔离测试不能代替安装版 UI 的实机验收。
- 不修改宿主源码、二进制、用户聊天历史或运行配置；不包含独立诊断工具与聊天样本。

本地发布快照通过 1150 项隔离 Python 测试、2 项跳过，覆盖真实 SDK 传输、
190 张原图逐字节投递、旧 SDK 回退、取消及丢失回执；Ruff、SDK 检查、
隔离发布构建与 Hosted TSX 检查通过。SDK 临时副本仅有缺少独立 `.git` 的预期警告。
测试替身保留宿主共享 SDK 的模块路径，CI 目录布局无需预加载 SDK 也能运行传输联测。
传输联测按正常服务启动路径加载图片校验器，覆盖官方宿主的显式校验器绑定。

本地测试和标准 GitHub Verify / Release 工作流分别核对。版本发布结果以固定标签、
成功工作流和三个标准发行资产为准，不以本地测试包代替远端结果。
