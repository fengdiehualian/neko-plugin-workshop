# 回复意图与表情选择

0.9.2 已于 2026-10-15 发行。2026-10-16 的三个 `0.9.3+test` 本地测试包
包含候选召回、动作阶段、独立发送冷却和面板简化；这些改动连同本次日志修复
整理为正式 `0.9.3`。按维护者要求仅在 GitHub 发行，不通知插件市场。仅修改插件。

此前默认流程是模型选择分类，再由插件随机抽一张图。分类中同时包含害羞、
被摸头、主动示爱和鬼脸时，分类相容不代表具体动作与这轮回复相容。

本轮借鉴参考插件的三点：依据回复者意图而非照搬用户情绪；逐图说明表达
动作归属、用途和复合语气；让模型从候选选择具体 ID，不贴切时可以不选。
参考插件的普通分类模式仍会随机，语义检索及辅助模型是可选能力。

## 当前流程

1. 模型决定这句话是否值得配图，优先按自己的回复意图给出正向短关键词，
   例如 `sticker_list(query="自己被摸头 舒服")`；也可以浏览分类。
2. `sticker_list(group=...)` 返回该分类逐图说明；query 支持空格或逗号分词。
   已识别的明确动作至少要匹配一项，其他词用来排序；没有动作词时仍取关键词并集。
   同时给 group 时限定该分类。关键词检索最多提供五个候选，
   分类浏览仍受现有目录上限约束；count 表示总命中数，shown 表示展示数。
3. 模型比较说明，区分自己的难过、安慰对方、自嘲和嘲笑，核对对象与强度，
   再用 `sticker_send(sticker_id=...)` 发送。没有合适图片就继续文字回复。

仅给 group 或 query 的 `sticker_send` 为兼容旧调用返回候选；即使只有一张、
给了 force 或额外配文也不会自动发送。Agent 的无参数入口同样改为浏览候选。
指定 ID 不可用时不会尝试另一张图片。面板仍按准确 ID 试发。

候选查询不消耗发送冷却、概率或使用计数，且剔除该角色最近发过和禁用的图片。
实际发送继续走原 Sender，保留冷却、去重、概率、即时/排队和图片反馈规则。
日志记录候选 ID，检索词和配文仍只记长度。

## 图库说明

以动画不同阶段的抽帧核看现有 190 张图，补充逐图用途和标签；重点修正
被摸头与主动摸人、自嘲与评价对方、单纯笑与指人笑、开心与强撑的区别。
分类仅作导航，证据不支持分类名称时，以逐图说明为准，不补造情绪。
抽帧仍可能遗漏极短动作，标注是可修订的解释，不是绝对语义结论。

`tools/official_labels_v3.json` 是这轮人工标注源。
`tools/review_official_labels.py` 生成开发用抽帧图；
`tools/update_official_labels.py` 只重建 manifest，保留媒体成员原始字节，
再由 `tools/split_official_pack.py` 生成随包分片。
正常升级通过现有内容版本和指纹配对，仅更新官方区现有图片的未手改字段。

## 边界与验收

本轮没有接入 embedding、视觉标注服务或第二个在线模型。关键词召回不是
真正语义检索，短关键词未命中时可能漏图；最终贴切程度仍取决于回复模型。
聊天检索会忽略用途说明中“不适合难过”等明确限制性分句，避免反向召回；
完整说明仍提供给模型，管理面搜索也保留原文匹配。限制短语规则不能解释所有否定、
转折和复杂句式，不能把文本命中当作可直接发送的结论。

当前 N.E.K.O 工具在回复期间提交，没有使用 AstrBot 的完整回复后处理钩子。
模型之后改变文字态度时，插件不能保证未来全文与已发图片绝对一致。

本地回归覆盖候选不发送、单命中仍需 ID、分类与关键词交集、无匹配无替代、
禁用与近期过滤，以及新版说明升级不覆盖手改字段、不补回已删除图片。
真实宿主还需观察：自己难过时是否避免喜庆图；安慰用户时是否避免指人笑；
害羞是否确有触发；被摸头和主动摸人的对象是否一致。测试通过不等于模型
在所有对话中都能作出正确语义判断。

## 候选召回与动作匹配优化

2026-10-16，优先改善贴合度，不调整积极度、提醒间隔、冷却、概率或近期去重。

- 补充少量常用短语：求摸摸、揉脑袋可以找到摸头／揉头图，陪着可以找到陪伴图。
  同等标注强度下原词命中优先于同义词扩展；不把相近情绪当成相同动作。
- 对词表中已识别的摸头、戳鼻尖、捏脸、梳尾巴、蹭人、拥抱、舔人、拆礼物、
  安慰、鼓励及轻度抗议进行筛选，至少符合查询中的一个动作／用途。
  例如“摸头 难过”只保留摸头候选，不再额外加入只有难过标签的图片；
  “摸头 抱抱”表示两种备选动作。未知短语仍依赖原文匹配，不推断长句含义。
- 对已有明确主被动说明的动作，排除相反方向，例如求摸摸不能召回主动摸对方，
  安慰对方不能召回想被安慰。对象未标明时仍需模型读图义确认，不自动补造对象。
- 分类名和图内文字不作为具体动作的证据；分类仍通过 group 浏览和限定范围。
  分组名称本身不再令整组图片成为关键词候选。
- 不把“不开心”命中成“开心”；保留“不满”“不安”“我不行了”等实际表达。
  否定用途只在检索视图中裁除，不改主人标注、图库或媒体文件。
- 常驻指引优先按回复意图查询，并再次提醒：抗议不是害羞、主动蹭人不是被摸头。
  查询只提供候选，仍须按具体 ID 发送；无匹配不换分类凑图，不随机补发。

回归用现有官方图库验证求摸摸命中 115、116、134，抗议命中鼓脸图，
而主动蹭人、梳尾巴毛和拥抱无对应动作图时返回空候选。
这些是检索契约验证；分类浏览、模型未写出动作词或模型之后改变回复时，
仍要依赖模型判断及实机对话检查，不能据此保证每次发送都语义一致。

### 同话题不等于同动作、同阶段

2026-10-16 14:41–14:46 的实机记录中，泡茶给对方的文字配了自己喝茶图，
展示已做好的茶配了期待图。继续收紧以下环节：

- 查询指引要求有具体动作时写动作、对象和阶段，例如 `给对方泡茶 已完成 开心`，
  不只写 `茶 开心`。泡茶、递茶、自己喝茶使用不同动作词，递茶区分给予与接过。
- 明确的期待、进行中、已完成阶段排除已标明的冲突阶段；
  未标阶段的图仍交模型判断，不从普通笑脸推断事情完成。
- 宽泛情绪查询优先少附带情节的图片，降低未被查询支撑的礼盒、奖杯、跳舞、
  饮茶、进食场景的排序；明确提及相关场景时保留正常召回。
  这只是少量词组的排序提示，不证明其他图片没有道具或额外情节。
- 官方包回归中，泡茶／递茶无对应图返回空候选，喝茶仍能找到 165–167；
  开心优先单纯笑脸，期待优先 150、151，已完成排除这两张期待图。

不增加工具参数、模型调用或发送频率。分类浏览和按 ID 发送仍由模型核对说明；
不能凭关键词规则判断全部自然语言，也不拦截宿主未来生成的文字。

### 等待收礼、等待来访与已经发生

2026-10-16 15:21–15:25 的本地测试中，29 轮回复有 8 次查询、7 次成功发送，
没有发送拒绝。0 秒发送冷却保存后重启仍有效，成功发送最短间隔约 8.43 秒。
保存的回复未见选图操作旁白；但“明天会早早等您”配了拆礼盒图，
“安静等您、路上小心”配了见面挥手图，动作和阶段仍不一致。

针对此问题继续修改开发源码，改动纳入 `0.9.3+test.20261016.3` 本地测试包：

- 识别 `等待收到`、`期待收到礼物`、`还没收到`、`等待来访`、`等你来`、
  `明天见` 等正向短语，按尚未发生处理；对应等待说明优先于只有宽泛开心的命中。
- 明确等收礼时排除自己已抱着或展示礼盒的画面；拆礼物、已经收到和见面问候
  属于已发生证据。即使图片另有“期待”标签，也不能用该标签抵消已发生的画面。
  “等待来访 见面问候”这类查询仍按等待处理，不用后一个动作词提前到见面阶段。
- 图片说明中的“期待收到”“准备打开礼盒”不作为已发生证据；
  比较句“情感强于普通问好”不作为实际打招呼动作。
- 宽泛情绪查询中，未提及的红包／金币、奖杯、礼盒、见面问候／报到、
  应援，以及原有跳舞、饮茶、进食场景不再只降序后补进结果。
  宁可少于五张或为空；近期去重后也不以这些无关情节补位。
- 明确查询 `红包 开心`、`获胜 开心`、`收到礼物 开心`、`拆礼物 开心`、
  `见面问候 开心` 时仍能召回对应图片。明确动作查询继续先筛动作再排序；
  管理搜索、无关键词分类浏览和准确 ID 发送保持原有契约。

使用随包的 190 张官方图及自建边界样例回归等待、收礼、拆礼物、问候和宽泛开心。
这些规则只认识列出的短语和场景线索，未覆盖的长句或图片标注仍可能漏召回、
召回过宽，且分类浏览和直接 ID 发送仍依赖模型判断；不保证所有对话绝对贴合。
不改在线配置、图库或官方标注，不增加模型调用，不调整积极度、提醒、冷却和其他发送限制。
