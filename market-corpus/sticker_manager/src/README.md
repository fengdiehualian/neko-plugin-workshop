# 表情包管理

让 YUI 在聊天中自主挑选并发送合适的表情包，也为你提供一个整理和管理表情收藏的面板。

**插件 ID：`sticker_manager` · 作者：qaqms**

## 能做什么

- **聊天配图**：猫娘阅读快捷候选的用途与语气说明，贴切时直接用 `sticker_send` 按 ID 发送，需要更多选择才用 `sticker_list`；没有合适图片就纯文字。
- **内置收藏**：随包提供 190 张表情及分类信息，首次启动自动导入。
- **分区收藏**：按“区 → 分类 → 图片”整理图库，只让猫娘使用当前激活区；浏览其他区不会自动改变她的选图范围。
- **导入与整理**：收集 PNG、JPG、GIF、WebP，支持批量导入、搜索、勾选、移动分类与删除。
- **图片详情**：查看原图和动画，编辑说明、使用情境、标签与图中文字；返回时保留图库的搜索和选择。
- **发送偏好**：矜持、自然、爱发三档积极度，配合冷却、最近去重和提醒间隔控制节奏。
- **迁移收藏**：导入、导出套图 ZIP，保留图片及说明、标签、分类信息。

随包附带 **190 张表情、22 个分类**。首次启动会收进面板的“官方”区；删除后可通过“恢复官方收藏”重新导入。“官方”是插件内置收藏区的名称，不代表 N.E.K.O 项目对素材来源或版权作出背书。

素材以分片文件随包提供，插件直接读取，不额外下载，也无需手动合并。分片仅改变存储方式，不改变图片与动画。

## 安装

本插件需要 N.E.K.O 宿主，不能单独运行。
需要宿主提供 Hosted TSX 面板、LLM Tool Calling 和插件图片消息接口。
SDK 声明：推荐 `>=0.1.0,<0.2.0`，支持范围 `>=0.1.0,<0.3.0`；
这不是对所有历史安装版的实测保证，具体导入与聊天行为请以目标宿主验收为准。

请从插件市场或本仓库的 **Releases** 获取已发布版本的 `.neko-plugin` 安装包。
若入口尚无可安装版本，表示版本发布尚未完成；源码 ZIP 不是安装包。

1. 获取 `.neko-plugin` 安装包。
2. 在 N.E.K.O 的插件管理中导入安装包，确认安装或替换同 ID 插件。
3. 启动插件，打开“表情包管理”面板。
4. 在面板顶部打开“猫娘发表情包”。**默认关闭**，不开启时猫娘不会查看目录或发表情，但你仍可整理图库。

市场版本以实际审核和发布结果为准；GitHub Release 的存在不等于已在插件市场上架。

更新时直接覆盖导入，不需要先卸载。正常更新会保留用户配置与图库；不要选择“清除数据”，除非确实打算删除收藏。`0.9.0` 是版本重定号，相较开发版本 `0.20.x` 数值更低，已安装用户应使用明确确认的手动替换，不应依赖自动升版提示。

## 第一次使用

**直接使用内置收藏**：激活“官方”区，开启发送总开关，积极度先选“自然”，然后开始新对话。可以先明确说“发一个表情包”检查调用链，再观察日常聊天中的自主配图。

**建立自己的收藏**：创建一个区，在其中新建分类，写一句分类适用的情境，例如“轻松接话或表示赞同”。把图收进对应分类，再将这个区设为激活区。逐图说明不是必填项，但准确配图需要说明“谁在对谁做什么、什么情境适用、语气多强”，例如“自己被摸头后舒服地眯眼”。分类只用来缩小范围，不能代替逐图判断。

切换或更新插件后建议开始新对话。工具由宿主和模型共同决定是否调用，积极度更高也不保证每轮发图。

`0.9.5` 汇总本轮测试改动，为爱发档增加回复后的独立补图选图。10 月 18 日增加面板中的“补图触发轮数”，
可调整数 **0–10**，默认 **1**：**0 表示每轮帮选**；1–10 表示连续相应轮数完整回复未配图后，
为最新回复进行一次选图判断，有贴切候选才提交一张图片；之后仍无贴切图会在后续回复再判断。
在“设置”中选择“爱发”，调节滑块并保存后立即生效，参数重启后保留。
请在宿主插件管理的模型配置中，将文字模型绑定到本插件的 **“爱发补图选图”**
（用途 ID：`eager_attachment`）。这个绑定不会自动复用当前聊天模型。
补图选图会增加模型调用与图片等待时间，正常正文先回复，不触发猫娘续答或额外配文。
未绑定或服务不可用时，面板会显示提示，原有自主工具发送仍可使用。
本轮已有成功或待处理发送时不竞争补图；新输入、会话切换、切档、关闭插件或换图库会丢弃过期选择。
冷却、概率、最近去重、纯文字要求、严肃任务和不贴切候选仍会限制发图，
轮数是补充判断的触发门槛，不是无条件送达保证。同一回复最多判断一次，0 也不重复补图。自然与矜持保持原策略。

`0.9.9` 起，“矜持”承接 `0.9.8` 原“爱发”的完整提示策略与每 3 轮提醒节奏，
作为后续调优基线。更新后选择“矜持”即可使用；已有配置不会自动切档。
`0.9.12` 测试版增加同轮重复对话诊断，三档行为保持 `0.9.11`；尚未宣称修复。
`0.9.13` 保留诊断，并将爱发档恢复为自然档的完整策略加一句本轮换新图的偏好。
诊断方式与证据边界见开发仓库的 `docs/reply-repetition-20261017.md`。

`0.9.11` 起，“自然”承接 `0.9.10` 原“爱发”的完整提示、快捷候选和每 1 轮提醒策略，
只将提示中的档位名改为“自然”。这轮 `0.9.10` 实机样本为 23 次完整回复、5 张图，
无查图或发送拒绝；这是观察结果，不是固化的发送比例。
“自然”以轻松聊天中主动配一张贴切图为偏好，日常问答也可用单纯表情回应态度，
不等强烈情绪或用户提醒。用户要求纯文字、图片不贴切或严肃任务时仍用纯文字。
自然和爱发的跟随档位提醒间隔均为每 1 轮，仍受提醒最小间隔和轮询节拍限制；
自定义正数间隔继续优先，提醒不等于实际发图。“矜持”的基线保留。
“爱发”沿用自然档的完整指引，不再删短快捷候选、日常问答示例、匹配与查图说明；
提示部分增加“上一轮发过，本轮有贴切的新图仍优先配一张”的偏好，
正式版 `0.9.5` 另增加上述独立补图判断，继续尊重纯文字请求和匹配条件。
已有配置不会自动切档；想复现上一版策略请选择“自然”。
矜持基线保留原提示中“每 2～3 条完整回复配一张”的软参考；
这不是实测频率或发送配额，也没有把本次约每 14～15 轮一张硬编码成规则。
用户要求纯文字、候选不贴切时仍不配图。
查图和发送工具会一起跟随档位更新，正文仍先正常回复，只说一次，默认不额外配文。

发送工具会展示最多 12 个带逐图说明的快捷候选，说明总长度最多 2,000 字符。
贴切时猫娘可直接选 ID 发送，省掉一次查图；需要更多选择时再查询分类或短关键词。
快捷候选来自当前激活区，已禁用或没有逐图说明的图片不进入此列表；
自然和爱发在相同预算内优先覆盖赞同、调皮、喜欢、撒娇、陪伴、犯困等日常表达；
仍是常用代表列表，不是根据当前对话动态选出的候选。
图片成功使用后按现有图库刷新节拍更新，发送时仍核对可用性、冷却和当前角色的最近去重。
共享快捷列表还会避开最近成功使用的 N 张不同图片，N 跟随“最近去重”设置；
这只影响快捷展示，按角色查图和发送仍用各自台账，不因其他角色用过就拒发。
常驻工具说明保留匹配原则，详细例子放在查图结果。
自然与爱发均保留日常问答用法示例，爱发另提醒上一轮配图不妨碍本轮的新表达，
限定纯文字时仍纯文字；
这些快捷候选与提示调整参考本地 AstrBot 项目的可选教学示例，未引入其输出标记协议；
独立补图使用上文说明的显式模型绑定。

有文字回复时，提示词要求猫娘先通过正常通道说完正文，再选 ID 配图；
工具返回后正文已说完就结束，只补尚未说完的话，`text` 默认留空，不另发一份正文。
只发图的请求仍可直接选图。选图是内部操作，不在正文或括号动作中播报。
这是插件提示顺序的修正，实际首字延迟和是否重复仍受回复模型影响。
图片还需符合实际动作、对象和发生阶段；
同属开心或亲昵并不代表适用。等收礼可用 `等待收到 期待` 查询，等对方来可用
`等待来访 期待`，区别于已经收到、拆开或见面问候。宽泛情绪查询不再靠未提及的
红包、奖杯、礼盒或见面情节补满候选；候选少或为空时可以不发。
已知动作与情绪的连写短词（如 `求摸摸舒服`）也可识别；未知长句仍建议改为带空格的短词。
空候选日志会区分词未命中、动作／阶段／场景筛除和最近去重，只记录数量，不记录查询原词。
短语筛选不能理解全部自然语言，最终仍依赖回复模型核对说明，插件不能过滤宿主自己的回复流。
常用情绪近义词和完整的已知情绪组合可一起检索，如 `高兴`、`谢谢 喜欢`、
`温柔感谢喜欢`；具体动作仍建议使用空格分开的短语。空候选时直接续聊，
不播报检索状态，不放宽动作和阶段来补图。重复回复和选图过程进入台词仍可能发生，
本版本没有过滤宿主文字流，也不保证模型遵守所有内部操作指令。

## 常用设置

面板默认打开图库，顶部切换收藏区，搜索、分类筛选和导入集中在图片上方。
搜索旁的“…”展开新建分类、导出和修复；各分类可直接添加图片，
“更多”里保留全选、分类说明与删除操作。浏览其他区不会切换猫娘使用的区，
需要另点“设为使用区”。

“设置”优先显示配图积极度和发送冷却；提醒间隔在“高级设置”，
统计与测试提醒在“运行诊断”。折叠内容不影响原参数生效。
完整配置字段见仓库内的 `config.example.toml`。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 发送总开关 | 关闭 | 允许猫娘读取当前图库目录、收到提醒和发表情 |
| 配表情积极度 | 自然 | 调整配图意愿，不绕过冷却和去重 |
| 补图触发轮数 | 1 轮 | 仅爱发档：0 每轮帮选，1–10 连续相应轮数未配图后帮选 |
| 发送冷却 | 20 秒 | 面板可设 0–3600 秒，0 关闭冷却；保存后立即生效 |
| 最近去重 | 5 张 | 自主选图时避开该角色最近成功发过的图片 |
| 放行概率 | 1.0 | 默认全部放行；调低后可能拒绝已选中的图片 |
| 提醒最小间隔 | 60 秒 | 限制相邻配图提醒的频率；不是发图计时器 |

提醒在本地结合用户轮次与有限情绪线索触发，不为情绪判定额外调用模型。总开关关闭时，提醒也不生效。
发送冷却与提醒最小间隔分别保存；提醒间隔设为 0 不会关闭发送冷却。

## 动图与发送限制

收藏、详情和导出保留内置 GIF 的原始字节。聊天发送使用原图或预算内的动画 WebP；为满足大小限制，发送版可能有损压缩或缩小尺寸，但不会替换收藏本体。图库缩略图是静态图，详情和聊天才播放动画。

- 单张导入图片最大 **8MiB**；面板分块直传总量最大 **128MiB**。
- 单个套图包最多导入 **512 张**；超出部分计为拒收，收件箱源包保留。全库导出超过 512 张时明确拒绝，不生成无法完整导回的包。
- 分类名全库唯一。向另一区导入同名分类的新图片会计为拒收，不会静默进入原分类所在区；相同图片仍按重复处理。
- 普通发送内联预算默认 **256KiB**。较大的静态图通过宿主上传发送；超预算动图默认拒绝，不静默压成首帧。
- 支持尾发接口的兼容宿主通过独立通道保留最多 **1MiB 原图**，内置 190 张 GIF 均可原字节发送；旧宿主、面板试发和后台 Agent 继续使用预算内发送版。
- 表情包独立显示为插件图片消息，不伪装成猫娘的普通文字气泡。
- 支持尾发的宿主提供可信本轮上下文和新 SDK 时，工具先登记图片，前端在原回复全部文字显示和入场动画结束后展示图片；不等待 TTS 播放结束。
- `[sticker_manager.send].host_reply_tail=true` 默认请求该能力；旧宿主缺少能力时保持即时发送，单独升级插件不能为旧宿主补上尾发支持。语音、后台 Agent 和面板试发不属于这条保证。
- 尾发登记被拒绝或结果不确定时不立即重复补图；成功次数和冷却只在宿主确认提交后记一次，提交回执不等于前端展示确认。
- 兼容排队发送是可选配置，依赖宿主日志信号，不能作为精确的前端播放完成回调。

## 数据与隐私

图库、用户配置和使用台账存放在宿主选择的用户数据根，正常代码更新不覆盖这些数据。Windows 默认位置为 `%LOCALAPPDATA%\N.E.K.O\plugins\sticker_manager`，迁移存储根后可能不同。

插件没有独立外部遥测或自动更新服务器。它使用宿主消息总线观察轮次，调用本机接口检查角色和工具状态；开启兼容排队时还会只读主日志的新增完成记录。提醒会进入模型上下文，选图目录也会提供给模型；图片发送和宿主模型请求仍遵循宿主的网络配置，不代表整个工作流完全离线。

使用台账供最近去重与排序，不保存可选配文或检索词的原文。导出的套图包含你收集的图片与说明，分享前请确认其中没有个人信息。反馈问题时请脱敏日志，不要公开整个用户数据目录。

## 常见问题

**开启后还是不发图？**

先检查插件是否运行、发送总开关是否开启、当前激活区是否有可用图片。新对话中明确请求一次表情包；若可以发送但日常聊天较少配图，可调整积极度。没有工具调用和选图后被冷却、去重拒绝是不同问题，运行状态与日志可帮助区分。

**GIF 在图库里不动？**

图库墙使用静态缩略图。点开详情查看原始动画；聊天显示另以发送素材为准。

**更新后会重新添加被删掉的内置图吗？**

正常升级不会补回主动删除的图片，也不会抢回移到自定义区的图片。只有主动使用“恢复官方收藏”才重新导入缺少的收藏。

**在哪里查日志？**

Windows 默认日志目录为 `%LOCALAPPDATA%\N.E.K.O\logs`，插件日志在 `plugin` 子目录。宿主迁移过存储根时，以实际存储位置为准。

## 开发与发布

市场首次上架流程是：推送源码并通过远程 Verify → 提交仓库的固定 commit 审核 → 审核通过 → 标准 GitHub Release → 通知市场发布版本。
本地导入包用于测试；它不能代替首次审核，也不应手动上传后就视为已完成市场发布。
完整规则见 [更新与发布](https://github.com/qaqms/n.e.k.o_plugin_sticker_manager/blob/main/docs/updates-and-release.md) 和 [官方发布教程](https://project-neko.online/zh-CN/plugins/cli)。

运行时插件不额外依赖第三方 Python 库。开发测试需要 Python 3.11+、uv；素材构建与测试使用 Pillow，面板检查需要 TypeScript。

在插件源码根目录运行：

```bash
uv sync --group dev
uv run python tools/release_gate.py
node tests/hosted_ui_regression.cjs --node-modules ../N.E.K.O/frontend/plugin-manager/node_modules
uv run python tools/build_package.py --host-root ../N.E.K.O
uv run python tools/inspect_package.py ../dist/sticker_manager_v0.9.3.neko-plugin
```

宿主源码默认位于相邻的 `N.E.K.O` 目录。校验和元数据探测在隔离副本中执行，不安装到正在运行的宿主；产物默认写入相邻 `dist` 目录。测试、开发工具、内部文档、缓存和用户数据不进入安装包。

源码仓内文档：`docs/updates-and-release.md` 说明市场审核和发布步骤，`DESIGN.md` 记录实现约束，`CHANGELOG.md` 保留版本历史。发布操作会推送标签并触发远程工作流，应与本地验证分开执行。
