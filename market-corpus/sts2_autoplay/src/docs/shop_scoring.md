# 商店采购策略：牌组量化 × 商品量化 → 买分最高的，都不够高就不买

玩家口径（2026-10-07）：

> 商店好像很喜欢买遗物？这里最好评估一下那些是真正需要的。如果没有需要的就留到下一个商店
> 还可以买药，买两瓶药可以冲精英
> 这一块需要量化牌组和商店的可购买项，买评分最高的，都不高就不买

## 现状（为什么"商店很喜欢买遗物"）

`heuristic_planner.py:1328` `_preferred_shop_relic_index`：

```python
# 只看买得起；偏好 record 的索引是通用 choice 语义（可能指向卡/其它项），不借此挑遗物。
_cards, relics, _potions = self._shop_affordable_items(summary_context)
for relic in relics:
    index = self._safe_int(relic.get("index"))
    if index is not None:
        return index          # 第一个买得起的遗物，直接买
```

- **遗物路径没有任何评分**，而调用处（`heuristic_planner.py:685`）给的 reason 却是
  `shop_high_value_relic` —— 名字与行为不符，日志也看不出"为什么买了"。
- 卡牌路径是有评分的（`_shop_best_card_index(..., min_score=_SHOP_HIGH_VALUE_SCORE)`），
  **只有遗物是无条件买**。
- 采购顺序是**死板的类别优先**：遗物 → 高价值卡 → 药水 → 删牌 → 其他卡
  （`heuristic_planner.py:682` 起）。这会**把买药水的钱先花在遗物上**——
  而玩家明确要"买两瓶药冲精英"。

## 目标

1. **牌组量化**：算出这套牌"缺什么"（缺口向量）。
2. **商品量化**：每个可购买项（卡/遗物/药水/删牌服务）算一个分，分 = 它补上的缺口 × 情境加权。
3. **买分最高的**；**全部低于门槛就不买**，把金币留到下一个商店。
4. "冲精英"是明确的采购意图：前方有精英时药水加权上调，并为"补满药水栏"预留金币。
5. 日志说实话：每一件为什么买/为什么不买。

## 一、牌组量化（缺口向量）

输入只需要 mod 已给的 `deck[]`（含 `card_type`/`rarity`/`upgraded`/`resolved_rules_text`/`dynamic_values`）。

先按现有 `_infer_archetype_tags` 的路子归纳，再产出**缺口权重**（0..1，可正可负）：

| 维度 | 怎么量 | 缺口判据（示例） |
|---|---|---|
| 输出（单回合伤害） | 攻击牌数 + 平均伤害（`resolved_rules_text`/`dynamic_values` 取数） | 低于每层期望 → 缺口高 |
| 格挡/生存 | 防御牌数与平均格挡，配合 `max_hp` | 血量低且格挡薄 → 缺口高 |
| 抽牌/循环 | 抽牌关键词（抽牌、重放、消耗） | 牌组 > 18 张且无抽牌 → 缺口中高 |
| 能量/费用 | 费用曲线，0 费牌占比 | 高费牌过多 → 缺口高 |
| 状态/群伤 | 易伤/虚弱/中毒、AoE 关键词 | 精英/群怪多而无 AoE → 缺口中 |
| 牌组质量 | 打击/防御**未升级**张数、诅咒/状态牌张数 | 未升级多、带诅咒 → "删牌/升级"缺口高 |

`牌组缺口` 就是这张表算出来的向量，全 0 表示"什么都不缺"（那就别买）。

## 一之二、已有遗物与药水也要量化（决定了"还缺不缺"）

只看牌组会得出错误结论：手里已有"力量+2"的遗物时，再买一件加力量的遗物几乎没有边际收益；
药水栏已经补满时，"再买一瓶"本身就是伪需求。所以"缺口"要**减去已有覆盖**：

### 已有遗物 → 覆盖度向量

把每件遗物按**效果类别**归类（读 mod 已给的 `relics[].description`，与牌组量化共用同一张维度表）：

| 效果类别 | 举例特征词 |
|---|---|
| 输出/力量 | 力量、伤害、攻击牌 |
| 防御/敏捷 | 格挡、敏捷、减伤 |
| 能量/费用 | 能量、费用、每回合 |
| 抽牌/循环 | 抽牌、手牌上限、弃牌 |
| 生存/回复 | 治疗、回复、最大生命、复活 |
| 经济 | 金币、商店、价格 |
| 战斗开始/条件 | 战斗开始时、每回合开始时 |

- 同类别**累加但边际递减**：`覆盖度 = 1 − 0.6^n`（n = 该类别已有件数），
  即第 1 件几乎补满、第 2 件只补 40%、第 3 件起基本无价值；
- 一件遗物横跨多类别就按类别分摊；
- **遗物覆盖度直接抵减对应维度的缺口**：缺口_维度 = max(0, 牌组缺口_维度 − 遗物覆盖_维度)。
- 覆盖度整体很高（构筑已成型）→ **门槛上调**，更倾向"留钱到下一个商店"。

### 已有药水 → 覆盖度

- 按用途归类：单体爆发 / 群伤 / 减伤 / 回血 / 清状态 / 抽牌 / 其它；
- 统计**覆盖到几类**以及**栏位是否已满**（`shop.potions[].occupied`、空的 `potion_id` 为 null）；
- 药水缺口 = "冲精英需要的那几类" − 已有药水覆盖到的类别；
  例：已有 1 瓶减伤、栏位还剩 1 → **还缺爆发类**，只给爆发类药水打高分；
- **栏位已满 → 药水整类不评**（买了没地方放）。

### 合起来

```
可买分 = 补缺分( 牌组缺口 − 遗物覆盖 ) × 情境加权( 精英/金币 ) − 代价惩罚 − 重复惩罚
药水分 = 药水缺口 × 精英加权 − 代价惩罚        （栏位满则不评）
```

注意"重复惩罚"与"覆盖度"是两件事：**覆盖度**是"这类效果我够不够"（作用于分数高低），
**重复惩罚**是"是不是同一件东西"（同名/同 `relic_id`，直接排除）。

## 二、商品量化

`分数 = 补缺分（0..1）× 100 × 情境加权 − 代价惩罚`

### 通用部分

- **补缺分**：这件东西补上缺口向量里最缺的那一维多少。
- **代价惩罚**：价格 / 当前金币（花掉一半以上的钱要重罚）。
- **重复惩罚**：遗物同名/同 `relic_id` 直接排除；卡牌与牌组里已有同名过多降分。

### 分类细则

- **遗物**：关键词加权（力量/敏捷/能量/抽牌/格挡/治疗为正面；条件苛刻或负面的降权）
  + 稀有度（Rare > Uncommon > Common）+ 与缺口的匹配度。
- **药水**：按"救命能力"评分——伤害/减伤/回血/清状态高分；
  **前方有精英时整体加权上调**（这就是"买两瓶药冲精英"）；
  **栏位已满（`potions[].occupied` 全满）则不评**（买了也没地方放）。
- **卡牌**：沿用现有 `_shop_best_card_index` 的评分，接进统一比较。
- **删牌服务**：分数来自"牌组质量"缺口（未升级/诅咒/低价值牌的张数）；只有缺口高才值得。

## 三、决策规则

1. 把所有可购买项打分，取**最高分**；
2. **最高分 < 门槛就不买**（一分不花，把钱留到下一个商店）；
3. 门槛本身随情境浮动：
   - 前方有精英 → 药水门槛降低（更容易买）；
   - 金币很多（例如 > 300）→ 门槛略降，避免"攒着不花"；
   - 金币很少（例如 < 100）→ 门槛升高，优先留钱。
4. **预留金币**：买遗物前先扣掉"留给药水的钱（冲精英时=补满栏位）"和"下一个商店的底钱"，
   即 `遗物预算 = 金币 − 药水预留 − 底钱`；不够就不买遗物。
5. 药水栏位满 → 不买药水；牌组没缺口 → 不买卡；没有低价值牌 → 不删牌。
6. 顺序上**不再按类别硬排**：遗物/药水/卡/删牌进同一个池子比总分。

## 四、日志与可观测

- 每件商品一行：`[sts2_shop] item=遗物X score=42 (补缺=输出0.7 情境=1.2 代价=-8) → 买/不买(原因)`；
- 决策结果带进 `reason`：`shop_scored_buy` / `shop_score_below_threshold`（替掉现在名不副实的
  `shop_high_value_relic`）；
- 没买时把"最高分是多少、门槛是多少"写进日志，方便事后调参。

## 五、配置项（可调，默认按上面保守策略）

| 参数 | 含义 | 默认 |
|---|---|---|
| `shop_score_threshold` | 统一门槛 | 40 |
| `shop_elite_potion_boost` | 冲精英时药水加权 | 1.4 |
| `shop_potion_reserve_gold` | 为药水预留的金币 | 冲精英时=补满栏位的钱 |

## 六、测试矩阵

1. 前方有精英 + 钱够两瓶药 → **买药水而不买遗物**；
2. 前方没精英、遗物平庸 → **什么都不买，钱留着**；
3. 药水栏位满 → 不买药水，钱转去买评分够高的遗物；
4. 遗物与已有重复 → 不买；
5. 钱很多 → 该买的照买（不误伤）；
6. 牌组满是无用牌 + 删牌服务 → 买删牌；
7. 最高分恰好等于门槛 → 买（边界）；
8. 日志里能读出"没买是因为要留钱给药水"；
9. **已有同类遗物**（例如手上已有力量遗物）→ 再买加力量的遗物**降分到不买**；
10. **遗物覆盖度已很高**（构筑成型）→ 门槛上调，倾向留钱；
11. **已有 1 瓶减伤、栏位剩 1** → 只给爆发类药水高分（覆盖度决定买哪瓶，不只是"要不要买"）；
12. 栏位满 → 整类药水不评（与第 3 条互为印证）。

## 八、战斗中：预计损血 > 8 就鼓励用药水

玩家口径（2026-10-07）：

> 还有每次对战如果损血大于8就鼓励使用药水

与商店那条是同一套思路（药水是"能换命"的资源，该用就用、但不乱用），只是触发点从
"前方有精英"变成"这一下要挨超过 8 点"。

### 判据（数据都在 mod 已给字段里）

- **预计损血** = `Σ intents[].total_damage − player.block`（不够减就取 0）；
  拿不到意图数据时不触发（宁可不喝，也不乱灌）。
- **触发线**：`预计损血 > 8`（可配 `potion_hp_loss_threshold`，默认 8）。
- **保命优先（无条件触发）**：`current_hp − 预计损血 <= 0` → **立刻用药水**，
  哪怕没到 8 点。这条永远压过其它考虑。

### 用哪一瓶

给每瓶可用药水（`can_use=true`；`requires_target=true` 时还要 `valid_target_indices` 非空）
按"能不能把这 8 点以上损血压下去"评分：

1. **减伤/闪避/格挡类** → 最高（直接抵掉这一下）；
2. **群伤/清场类** → 次高（把还在打你的怪清掉，等于少挨几轮）；
3. **回血类** → 只在"预计会死"或血量低于 30% 时优先，否则降权（回血不减少这一下的伤害）；
4. **清状态类** → 与减伤同档的备选；
5. 其它（抽牌等）→ 战斗里不当保命手段，不因这条规则触发。

### 节流（药水是稀缺资源）

- 同一场战斗**同一回合只喝一瓶**；喝完记一笔，避免连灌；
- 普通小怪战把阈值上调（更省），**精英/Boss 战下调**（更愿意喝）——
  与 `shop_elite_potion_boost` 是同一套"情境加权"；
- 栏位空（没药水）自然不触发；
- 日志一行：`[sts2_potion] 预计损血=12 > 8 → 用〈减伤药水〉(评分 88)`，
  或 `预计损血=12 但不喝（原因：已在本回合喝过 / 手里只有回血类且不会死）`。

### 测试

13. 预计损血 12、手里有减伤药水 → **喝**；
14. 预计损血 12、手里只有抽牌类药水 → **不喝**（不当保命手段）；
15. 预计损血 6（未到线）、但 `current_hp − 损血 <= 0` → **无条件喝**（保命优先）；
16. 同一回合第二次触发 → **不重复喝**；
17. 意图数据缺失 → 不触发；
18. 预计损血 12、手里有减伤与回血各一瓶 → 选**减伤**（评分更高）。
