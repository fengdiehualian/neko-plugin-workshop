# 可转发给 Neko 上游的兼容需求

我们的 Minecraft 自主框架独立运行，Neko 插件只转交新鲜复盘、返回高层目标并由宿主演出。当前本机公共 SDK 的 push_message 支持角色、合并键、metadata 和 ai_behavior，但没有会话范围或回复持久化策略。把 request_scope / persist_response 放进 metadata 不会生效；visibility=[] 也只隐藏插件原文。

目前普通插件复盘会读取角色历史，并把新解说写回历史。现场出现主脑反复沿用旧练习目标的现象；框架已修复用户意图与主脑阶段的来源标记，但尚不能认定历史污染是唯一原因。宿主现有 minecraft_execution 分支只匹配旧游戏插件和特定合并键，且它本身也仍读取普通角色历史。

请提供面向所有插件的公共通知策略：按已认证插件身份和会话 ID 选择上下文范围，并可显式禁止自动复盘回复写入普通聊天历史。策略应默认保持现状，由用户启用；文字和实时语音路径含义一致。角色人格继续保留，游戏当前目标、事实和原文查询入口由插件提供，不能依赖历史聊天推断现场。继续使用宿主的模型、语音、限频、合并和过期机制，不为游戏复制主脑或额外增加模型循环。

希望补充回归：不同插件和游戏会话隔离；旧测试对话不覆盖新用户目标；临时复盘不累积成普通聊天记忆；停止、过期和取消时不派发新任务；同一通知只产生一次决策。请避免继续按具体 Minecraft 插件名称硬编码兼容。

2026-10-14 北京时间 16:59–17:03 的补充现场事实：新的游戏复盘通知得到自然解说和官方语音播放回执，但主脑没有调用复盘确认工具，框架如实记录 `main_brain_not_acknowledged`。此前同一入口有成功阶段决策，因此不能说所有通知或工具注册都不可用。希望公共 SDK 提供可选的结构化工具确认要求，区分「通知已收」「模型仅说话」「阶段决策已确认」；未确认时按有界重试与过期处理，不凭解说自动产生游戏目标或把旧回执当新确认。

这是 Neko 公共能力需求，不是 Minecraft 服务器故障报告。当前插件未伪装旧来源，也未修改宿主 SDK或删除角色历史。

2026-10-14 晚间补充：用户希望自然的重点解说，避免反复朗读背包和“读取现场”。适配层已将数量/耐久变化过滤，并把短解说要求放到通知最前面，但主脑有时直接说话而不调用复盘工具；只在工具返回写静默要求并不足够。希望增加通用、显式、由用户开启的通知响应策略：可以要求先完成指定的结构化工具确认，再决定是否允许对外文字/语音；常规后台复盘可静默用工具，重要变化才给一个短解说机会，用户直接聊天照常回应。该策略应在实际输出与语音通路执行，不靠 metadata 中未实现的字段，也不要按某个 Minecraft 插件名硬编码。希望测试同时覆盖通知预览裁剪、模型只说话未确认、重试重复解说、取消/停止、文字与实时语音的一致含义。
