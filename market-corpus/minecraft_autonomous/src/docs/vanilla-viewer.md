# 原版优先：运行与观战边界

通用基线是 **Minecraft Java 原版 1.21.1**。先验收无人持续操作时的采集、工具制作、
食物与安全住所，再做千灯纪等可选扩展。原版模式不注入私服命令、任务、技能或旧材质。
一次登录、一次合成、收到区块，均不表示已完成长期自主生存验收。

## 可选的同角色观战

完整离线包已包含固定共享源码、原版视觉/声音资源、YUI 与渲染引擎；按 [离线安装步骤](../README.md#完整离线包安装) 准备后，嵌入式默认从版本化缓存解析同一套路径。源码开发者或自定义安装按 [源码安装指南](install-source.md#4-可选公开的原版观战和声音资源) 读取权威依赖清单，再校验共享 Git 资源并准备 catalog。插件只做公共核心的 extension 装配；大型资源位于完整离线包相邻运行时，不放入 SDK 插件导入包。

在独立配置或 Neko 配置面板填写：

```toml
[viewer]
renderer_directory = "/absolute/mc-visual-console/packages/modern-viewer/renderer-src"
catalog_file = "/absolute/private/viewer-catalog.json"
listen_port = 28985
auto_open = true
url = ""
port = 0
console_port = 0
```

自定义 `renderer_directory` 和 `catalog_file` 须一起配置；嵌入式留空时使用已准备离线包的默认资源。
已有外部观战服务仍可单独填 `url`。目录和地址是用户自己安装的本地配置，
不内置开发者磁盘路径、测试服务器、账号或模型服务。

显式启动后，运行层会等到角色连接成功、观战服务可用，再请求默认浏览器打开一次。
状态刷新和重连不会反复弹窗。`viewer_window=requested` 只表示打开请求成功，
`manual_open_required` 表示需要手动打开；两者都不证明浏览器完成渲染。
远程或无桌面部署可将 `auto_open=false`。

版本来自配置及真实连接的交叉核对；本版游戏协议仍只支持 1.21.1。观战 catalog
按精确版本和注册表选择资源，缺少匹配就显示不可用，不能套用 1.20.6 材质或模组注册表。
可视化失败不会停止独立身体队列。端口冲突时不终止其他进程。

观战读取执行角色自己的连接、UUID、区块、位置及背包，不增加游戏账号。
Neko 的 `viewer_body_binding_verified` 还要求新鲜读数与配置账号相符；完整场景、
光照和实体渲染一致性另行验收。观战画面尚未自动作为规划模型的视觉输入。

## 自主生存验收

使用普通生存账号和原生规则，保留真实世界，不通过 OP、送物品、改时间或手工连续下发
每一步来替代自主行为。核对连续多个自然决策及其世界变化：

- 已有资源能转为必要工具，缺材料时先补齐，失败不会反复重试同一非法参数。
- 食物储备、饥饿和生命有实际改善；危险触发避险，后续能恢复工作。
- 能形成并维护可核验的安全住处，不以模型宣称“安全”代替世界证据。
- 新用户反馈能插入/改变目标，之后继续生活；显式停止不被自动恢复。
- 无 Neko、无多模态或无快决策模型时，分别遵守已声明的独立运行/文字/规则回退。

当前阶段保持开发版，不将上述尚未通过的项目描述为已完成，也不发布 Market 版本。

当前固定 1.21.1 公开资源、共享仓库根目录准备命令与 catalog 示例见 [源码安装指南](install-source.md)。可选声音还需要浏览器用户手势；资源存在不等于实际播放。
