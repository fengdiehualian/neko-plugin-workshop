## Decision

Use its independent `packages/agent-mc-world` core for the generic N.E.K.O plugin. Keep the
My Agent World host adapter optional; do not copy the whole server repository into the plugin.
This replaces the earlier 0.3 baseline and its source-extraction/build coupling.

| Component | What source inspection established | This integration |
| --- | --- | --- |
| Independent core 0.4.0 | Own core/client/contracts/MCP source, neutral default export and public types; no Cortico build/runtime requirement | Adopted as base, with reviewed standalone cleanup patch |
| `agent-mc/v1` | Turn IDs, barriers, cancellation, current facts, archived events and execution receipts | N.E.K.O host consumes these explicitly |
| Generic Mineflayer | Explicit protocol version and remote host/account configuration | Fixed to Java 1.21.1 / 767 |
| Bundled viewer | Upstream asset lock still identifies Java 1.20.6 assets | Excluded; no claim of 1.21.1 rendering |
| My Agent World native host | Optional original-body UUID/controller binding, native operations/ledger and two provider semantics | Evaluated, not installed or wired |

The new commit makes MCP instructions overrideable for an explicit host environment while retaining the default
instructions. It does not require a new Cortico inference loop. Core source, build inputs, runtime imports and
public type boundaries were inspected separately; the neutral protocol and public-type tests also run with
framework resolution forbidden. The supplied core is the user's Minecraft plugin. Further inspection found legacy names, defaults and compatibility paths; the derived distribution removes these through a hash-pinned source patch, rather than retaining them as runtime compatibility.

For the exact cleanup scope and a forwarding prompt, see [standalone core audit](standalone-core-audit.md).

## Why the native adapter is not the default

Sources:
[adapter](https://github.com/jcs130/minecraft-ai-friend/blob/7889ce261a2309d94400b739c6198468d8271d83/world/src/agent-mc-host/index.mjs),
[installer](https://github.com/jcs130/minecraft-ai-friend/blob/7889ce261a2309d94400b739c6198468d8271d83/tools/install_maw_agent_mc_world.py),
[upstream handoff](https://github.com/jcs130/minecraft-ai-friend/blob/7889ce261a2309d94400b739c6198468d8271d83/docs/MY-AGENT-WORLD-AGENT-MC-WORLD.md).

- `@my-agent-world/agent-mc-host` is generated by its installer, not a self-contained published npm package in this tree.
  It uses `world-adapter`, native SDK credentials/Numen clients and NeoForge handshake/mod-call modules.
- Its `mc_do(action_id, operation, args)` differs from generic `mc_do(steps)`. Blindly swapping entry files would
  preserve neither tool semantics nor action ledgers.
- Mineflayer provider owns a connection; Numen attaches an existing remote body. Closing the latter deliberately
  leaves the body/actions alive. The generic plugin's disconnect-and-stop guarantee cannot be assumed there.
- Native unknown outcomes and the original body ledger must block replay. A different dataDir must not become
  a new native ledger or bypass a controller lease.
- Upstream documentation says full generic-core scripts, survival reflexes and continuous chat/damage/death
  subscriptions have not all been ported to the native adapter. Source handoff claims its own verification;
  those are not fresh game checks performed in this task.
- The original installer targets a server deployment path and verifies a full upstream viewer build.
  We did not run it against production or substitute this headless archive for that distribution.

For ordinary compatible 1.21.1 servers, generic Mineflayer is the smaller independent route.
For the user's actual My Agent World/NeoForge server, the native adapter is the appropriate future route;
setting a vanilla client to 1.21.1 alone is not sufficient. It should enter through a separately configured
execution provider after the native dependency closure and disconnect semantics have their own acceptance tests.

## Build and evidence

- Headless archive: `agent-mc-world-0.4.0.tgz`, SHA256
  `a4fcfabf5f5a6c9582f33bc8217eb8247dbf9f6a4abc6971605756a810e704c9`.
- Derived build compiles 196 runtime files and generates 241 public declaration files from the pinned core plus
  the reviewed standalone patch. The 207 source files and supplied license notices are preserved; a `dist/neko-headless.json` receipt records source and compiled hashes.
  This is explicitly not an upstream release or a completed upstream viewer build.
- Installation uses a pinned npm lockfile, scripts disabled and archive/build-file verification.
- Real Python → Node MCP discovery/status/error checks run with networking and Cortico imports denied.
  There are 24 upstream tools; phase remains disconnected. The configured 1.21.1 registry maps to protocol 767.
- Core protocol, public types, procedures, authentication, placement, digging and offline-boundary regressions: 58 tests passed across 11 suites. The IPC fixture is a fake engine,
  not a Minecraft server. Public declarations passed both Bundler and NodeNext resolution checks.
- Plugin tests cover stop races, unknown outcome recovery, event retention, barriers, pending actions,
  complete receipt paging, model/host ownership and conservative whole-request context limits.
- Fresh plugin suite: 43 passed; managed Ruff passed. Real stdio also verified a pending event wait does not
  block status and can be cancelled. The default stable request budget is 17,485 (UTF-8 bytes plus reserves),
  leaving room for current facts within the 32,768 default budget; actual model tokens/cache hits are unmeasured.
- Public N.E.K.O `get_client` / `aclose` and model-usage declarations were checked against official
  [main ce008bb](https://github.com/Project-N-E-K-O/N.E.K.O/blob/ce008bb313b7c2559bd4fff0bf5d8baf65e6b717/plugin/sdk/shared/core/models.py)
  and its model API example. The installed CLI's structure checker warns that `plugin.models` is an unknown
  field, despite the official example using it; this warning is retained, not worked around with a private API.
- No model request, game connection, live voice synthesis, account migration or existing service restart occurred.
  Real gameplay, cache-hit improvement, body-bound viewer frames and native adapter acceptance remain unverified.
