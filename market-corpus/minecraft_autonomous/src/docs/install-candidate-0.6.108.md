# 0.6.108 开发包安装范围

本版使用框架 0.2.103、核心 0.5.7-rc.99 和固定共享观战 8b89927d。源码、正式插件包和完整离线运行资源分别核对；公开 Release/Market 仍是 0.6.70，此文不会把开发构建当作已发布版本。

接收完整 Windows x64 包的用户先完整解压，双击 `一键安装.cmd`，准备成功后在 Neko 插件中心导入相邻同版 `.neko-plugin`。保留原配置和数据；升级前先正常停止旧版游玩。无需 Git、Python builder、npm 或作者的目录、账号、模型密钥。仍需自己的 Neko、可用模型绑定和可进入的服务器。

插件由真实 SDK 生成，包内须有 `plugin.meta.json`、全部声明的 vendor 依赖与 dist-info，不能用源码目录或仅 sync 后的目录代替。完整运行资源由单独清单校验，包括 Node、固定核心、共享观战、1.21.1 资源、浏览器和许可；准备程序不启动宿主、模型或游戏。默认自动启动和 autonomy 都关闭，配置后再显式开始。

源码安装者按 [源码指南](install-source.md) 的真实 SDK build/import 路径操作。Windows CPython 3.11 x64 包对应同平台宿主；其它平台和 Python ABI 需要在匹配环境重新构建，不能直接复制 Windows 二进制依赖。固定依赖和资源来源以 `pyproject.toml` 及同步后的 `vendor/agent_mc_autonomy/core_distribution/source.json` 为准。

本次交付检查包括正式导入器在全新独立目录安装、元数据与入口实际导入、中文/空格路径、空缓存准备和迁移后资源定位；源码回归与安装验证不等于所有服务器、外观、声音或长期生存行为均已验收。实际构建摘要、平台和 SHA256 随交付包提供。

Windows 宿主若没有启用长路径支持，旧版可能把确实存在的深层构建文件报为 `backend_build_mismatch: missing or invalid build path`。本版在校验时使用 Windows 扩展路径，无需改系统注册表或宿主；缺失、篡改和越出包目录的文件仍拒绝。如果文件确实没有解压完整，错误会标明相对成员名。官网的 NEKO 基础包还需将公共音频与截图浏览器两份组件解压到同一目录，再运行准备入口；不要用其它版本的后端填补文件。
