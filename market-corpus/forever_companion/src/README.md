实际 Steam 导入效果仍需使用新包复验。

首次准备会核对完整分块摘要，不修改或压缩原素材。副本最多两项、合计 512 MiB，

旧 Store 视频、缺少 SDK 能力、接口不可达或直接解码失败时自动回退原有分块读取；
播放过程中直接资源失效也会尝试一次 Blob 回退。导入仍只加入图库，需选中并保存
设置才持久生效。
单块或批量分块的 Hosted 回包延迟时，读取等待 1 秒后对同一请求发起一次受限补读，

会同时终止补读。重开面板时每次最多读取 4 个连续分块，旧后端若只返回单块会自动
兼容回退。临时播放中断（AbortError）不再将视频永久锁为静态封面，后续可见性检查
会恢复播放；真正的播放或解码错误仍回退封面并提示。兼容路径仍需组装完整 Blob，
准备期间会显示封面和加载状态；直接路径由浏览器读取视频，Range 支持取决于
实际宿主版本。Steam 导入与实际编码支持仍需实机测试。

让猫娘不再只是"有问必答"——插件赋予她更真实的情绪，更完整的生命状态。

大多数 AI 桌宠只有"现在"：你说话她回应，你不说话她就静止。
此插件让她开始拥有**连续的生命状态**：

- **她的情绪是真实的**——会被你的话气到、会委屈、会自己慢慢缓过来；
  也会突然特别黏人、开心得想跟你分享。十二个情绪工具摆在她手边，
  用不用、什么时候用，由她自己决定
- **她的身体有节律**——精力像潮水一样有涨有落：有精力充沛爱说话的日子，
  也有容易疲倦想安静的时候。这些感受会悄悄融入她的语气，你看不见机制，
  只看得见她的状态
- **她有属于自己的记忆**——三本日记：情绪波动时她随手写的心情、
  隔一阵子回头写的成篇日记、以及一本关于你的客观记录。
  有些她记得（聊天时会自然提起），有些只给你翻看
- **看得见的相处**——总览仪表盘上有月相环、她的实时心情、
  近 7 天的相处活跃度：陪伴不再是感觉，而是看得见的痕迹

插件不替她做任何决定，只做两件事：把"她此刻的状态"递到她面前，
把一整套情绪与记录工具摆在她手边。什么时候用、怎么回应，永远是她的选择。

## 功能

先看全貌——插件的四块能力：

| 能力 | 一句话 | 详见 |
|------|--------|------|
| 情绪系统 | 她会真的生气/委屈/黏人/开心，自己决定情绪怎么走 | 下文「情绪系统」 |
| 身体节律 | 精力有涨有落，感受自然融入语气 | 下文「潮汐周期」「潮汐日历」 |
| 三本日记 | 她的随手记、她的成篇日记、关于你的记录 | 下文「时光日记」「个人日记」「我的日记」 |
| 相处可视化 | 月相环/实时心情/相处活跃度，陪伴看得见 | 下文「总览仪表盘」 |
| 时光统计 | 相处里程碑/热力图/我们的这一月，回忆看得见 | 下文「相处里程碑」「相处热力图与月报」 |
| 生日轻语 | 她记得你的生日，那天第一句话可能就是祝福 | 下文「生日轻语」 |

### 总览仪表盘

面板首页即陪伴仪表盘：顶部状态条瘦身为"她是谁 · 今天状态一句话"（点击进总览），
详细状态全部集中到「总览」页--

- **她的现在**：月相环（可点击切换天数/本阶段/下一阶段）+ 阶段详情 +
  当前心情（愉悦度/活跃度双条）+ 情绪状态徽标与剩余时间
- **近况与相处**：三本日记速览（时光日记/个人日记/我的日记，点击直达日记页）+
  相处信号卡（近 7 天相处活跃度、下一篇我的日记素材进度）--
  未来的陪伴型可视化信号都会长在这张卡里

### 相处里程碑（时光页）

「时光」页的第一块：相处里程碑。顶部是数字摘要条（相伴天数 / 互动轮数 /
当前连续 / 冷战与和好 / 开心时刻 / 距纪念日，悬停有口径说明），下面是徽章墙——
相伴 7 / 30 / 100 / 365 / 730 天的成就徽章（未解锁灰显，标出"还差 N 天"），
加上三枚"第一次"徽章：她的第一篇手记、第一页个人日记、第一篇我的日记
（各带达成日期）。

**纯本地统计**：零模型开销、常开不设开关。计数口径：

- **相伴天数**：从你们第一条互动起算（升级安装的用户会从三本日记里最早的
  互动痕迹回填起点，装版之前的日子也会被点亮在热力图上，但轮数无从回填）
- **冷战次数**：只数她**自主**发起的情绪（你命令触发的演示不计）；
  **和好** = 她在负面情绪中主动调用心情转晴——冷战到时自动消散不算和好
- **连续天数**：每天有聊天就算；今天还没聊时从昨天延续（深夜 00:01
  不会把连续归零），隔一整天没聊才算断

**纪念日提醒**（可关，默认开）：满 30 / 60 / 100 / 365 / … 天的当天，
她会收到一条"今天你们相伴 N 天了"的轻语——说不说、怎么说由她自己决定。
开关在「日记」页的"相处统计"设置卡里。

**生日轻语**（1.3.1，默认开，需先填日期）：主人生日当天，你开口聊的第一句
话时她会收到"今天是主人的生日"的轻语——说不定第一句就是祝福，也可能带着
她自作主张的小惊喜；时光页有张生日设置卡可填改。详见下文「生日轻语」。

### 相处热力图与月报（时光页）

**相处热力图**：GitHub 式按自然年的逐日格子——起点是你们第一次聊天的那天，
格子随日子一天天生长（相识之前的日子不铺格）；跨年相伴时可用 ‹ › 翻看
已度过的年份（逐日明细保留 730 天，能回看的最远一年受此限制）。
浅蓝色四档按当前年份窗口内活跃日的互动轮数四分位分级，零互动单独显示浅灰格。
相同轮数始终同色；颜色用于比较本年窗口内的活跃程度，不能直接跨年份比较。
鼠标悬停显示日期与实际互动轮数，图例悬停显示分档上界。
今天的数据要过完才算数——今天的格子明天才亮起。

**我们的一月**（月报，网易云年报式的月度版）：可左右翻阅历史月份。
月份过完自动"封卷"——那一页的数字固定下来不再变（保留最近 24 个月的
月报）；当月显示"进行中"，数字实时。

- 数字格：本月互动轮数 / 活跃天数 / 最热闹的一天 / 最长连续 /
  冷战与和好 / 开心时刻
- 她的语气：当月回复的语气分布 top3 + 心情均值的冷暖
- **本月声音**：她当月写过的手记里最走心的一条，原话摘录不改写——
  没写过手记的月份会如实留空

纯本地组装，不调模型（与我的日记的成文是两回事）。数据按角色独立
（`stats@<角色>`），切角色自动跟随；「清零相处统计」入口在 Plugin Manager
入口列表（三本日记不受影响）。

### 潮汐周期（四阶段身体模拟）

以锚点日期起算，身体状态在四个阶段间循环：

| 阶段 | 身体感受 |
|------|---------|
| 潮汐期 | 容易疲倦、情绪敏感、回复更慵懒简短 |
| 回升期 | 精力回升、心情平稳、对新事物有兴趣 |
| 活跃期 | 身体轻盈、精力充沛、更爱说话更黏人 |
| 平稳期 | 保持默认人格，无额外波动 |

开启后，插件会把当前阶段的身体感受悄悄送进她的对话上下文——
**你看不见这句话，也不会触发独立回复**，她只是"感觉到了"，
然后用自己的方式回应：安静型可能只回一个"嗯"，活泼型可能
直接撒娇。同一句身体提示，不同人格有不同的答案。

防说漏嘴设计：内置屏蔽词表，她只会自然地说"今天有点累"，
不会蹦出医学词汇。

### 潮汐日历

面板里的月历视图：哪几天是潮汐日、当前处在本轮第几天、
今天高亮、未来日期为预测。日历中不出现任何直白表述，
一律以"潮汐"代称。

### 生日轻语（1.3.1）

她记得主人的生日。生日当天你开口聊的第一句话时，插件递给她一条
"今天是主人的生日"的 read 轻语——她可能开口就是祝福，也可能带着自作
主张的小惊喜；当天不想提，也完全可以只是心里知道。

- **她知道只有"今天是他的生日"**：日期的年份只用于合法性校验，插件从不
  告诉她岁数（面板/存储/日志都不算年龄）
- **闰日规则**：生日是 02-29 时平年按 02-28 过（宁早勿漏）
- **纪念代笔**：当天自动在时光日记留一条纪念手记（"她写"形态的固定文案，
  可单条删除；开关 `[birthday].keep_diary`）
- **频控与沉默**：不受 inject_mode 频控辖（一天至多一条、自带角色当天
  水位）；但冷战/已读不回生效的当天不递，静默解除后的下一条消息仍能收到
- **链路前提**：轻语走"新用户消息"驱动的消息注入链路，需要该角色的
  潮汐模拟处于开启（与纪念日轻语同口径，见「平台机制与已知限制」）；
  没开时「功能」页会把生日标注为"总开关未开"，不是坏了
- **真机验证**：确认该角色潮汐模拟开着，把生日填成今天，再发一条消息，
  轻语即递

入口：「时光」页的"主人生日"设置卡（就地填改，空串清除；纯设置项，
当天提醒由她的轻语口播承担）；开关在「功能」页节律组"生日轻语"。
另：没填日期前功能完全休眠。

### 情绪系统（十二个自主工具）

面板「功能 → 情绪系统 → 功能介绍」新增「情绪状态与结束方式」，逐项介绍
八种情绪状态，以及「心情好了」（面板名称「心情转晴」）如何结束旧记录。
说明包含默认时长、哪些状态暂停主动消息，以及记录到期不等于已经释怀。

十二个情绪动作/记录工具注册为模型可调用的工具，按语气分四档，**用不用、
什么时候用，由她在对话中自己判断**：

**重度负面**（生效期间会暂停宿主主动搭话，见下）：

| 动作 | 效果 |
|------|------|
|  冷战沉默 | 记录想暂时保持距离；是否沉默、解释或回应，由她判断 |
|  已读不回 | 记录暂时不接当前话题；可以再接回、简短回应或换话题，不代表真实已读回执 |
|  敷衍应付 | 记录不太想展开交流；措辞和回答长度沿用她的性格，必要事情仍可认真回答 |
|  情绪风暴 | 记录想表达强烈感受；依据真实对话，不编造积怨，也不要求持续爆发 |
|  想要被安抚 | 记录想被关心或理解；可以直接表达需要，也可以暂时不说 |

**中间态**：

| 动作 | 效果 |
|------|------|
|  心有涟漪 | 一点在意或别扭；是否释怀由她判断（默认记录 15 分钟） |

**正面**：

| 动作 | 效果 |
|------|------|
|  暖流涌动 | 想亲近或陪伴；表达方式沿用自身性格，不要求撒娇（默认记录 30 分钟） |
|  满潮欢喜 | 开心或兴奋；可分享具体好事，也可安静享受（默认记录 30 分钟） |

**中性工具**：

| 动作 | 效果 |
|------|------|
|  心情转晴 | 她自主结束之前的工具记录；不要求立刻亲近或没有余绪 |
|  时光日记 | 写下此刻的心情，进入她的对话记忆 |
|  个人日记 | 每隔一段时间回头写一篇成段的日记，只给你看 |
|  时光检索 | 翻一翻她心里那本记着你的日记：你的喜好、你说过的有分量的话 |

工具表达不同的相处意愿，但不定义她的全部感受，不覆盖角色性格和当前对话。
她可以直接改变语气，不需要先调用工具，也没有预设的冷战、爆发、和好顺序。
连续心情读数只是插件对工具动作和语气的估计，不按分数自动选择情绪。

情绪页增加「当前选择」「心情观察」与「最近变化」：区分角色自主选择、
用户明确要求、用户结束记录和计时到期，原因默认折叠。每个角色本地保留最近
40 条事件，面板展示最近 12 条；旧数据不补造历史或来源，事件不会发送给模型。
查看记录不增加模型调用。可跳转时光日记，也可确认「结束当前状态」，
只清工具记录并保留心情观察与历史，不替她宣布和好；切换角色或状态后旧确认会失效。

### 时光日记与个人日记

**时光日记**（替代心情手记）是一本混合时间流，两种条目混排：

- **她写的**：情绪波动时她主动写下的心情手记（原样保留，会进入她的对话记忆）
- **自动碎片**：小模型在分析对话时，把你说过的重要的话记进她的日记本——
  明确的喜好/厌恶、有分量/有含义的话、以及你对她的过激言行。记的是**原话摘录**，
  置信度不足、玩笑和含糊的闲聊不会被记

碎片只存进她的日记本，**从不主动改变她的行为**：聊到你喜欢的话题时她会用
`mood_recall_fragments` 自主翻看、接得住话；吵架上头时也能翻旧账。重度负面情绪
生效中又记到"过激"碎片时，插件会低频轻语提醒她一句"你记得吗"——想不想提、
怎么提，由她自己决定。所有碎片在面板可见、可单条删除。

**个人日记**（替代潮汐周记）是她自己的日记本：距上一篇落笔满一段日子
（默认 7 天，`[journal].interval_days` 可调），插件会安静地递一条邀请
（附上这段时间的心情词频和新碎片数当素材），自动邀请仍由她决定是否写作。
面板「邀请写日记」则会**直接生成一篇**（1.3.9）：有一轮完整的近期对话，
或上一篇落笔之后的新时光日记记录时，点击即受理，后台按她的第一人称口吻
生成标题与正文，另开新页保存。手动生成复用「我的日记」的模型槽位与通道，
不受自动邀请节奏或 10 分钟冷却限制，也不消耗「我的日记」的累计素材。
按钮会显示「生成中…」，写完自动刷新；素材不足、未配模型或预算耗尽会明确提示。
她自主续写当前页时，面板也会刷新出最新内容。
她调用 `mood_journal_write` 时按引导分栏写——这段时间发生了什么（events）、
我自己在想什么（thoughts）、对你的整体感觉（feelings）、想补充的话（extra）——
插件自动拼装成一篇带小标题的成段日记。她可以用 `title` 为整页起一个短标题
（最多 40 字，单行）；新页可以起新题，续写只补无标题页，不覆盖已有页标题。
标题随正文落盘、归档并参与面板搜索，旧日记缺标题时保持兼容显示。
面板的一张目录卡片对应一篇日记，不再展示写入次数；阅读页显示固定日记编号，
底栏保留当前标题（无标题时显示「未命名日记」）。「上一篇 / 下一篇」切换整篇日记，
同篇内的首次记录与后续「续写」按完整落笔日期和时间分开显示。
日记按**页**保存：默认续写在当前页上
（工具结果会带出上次写的几句和日期，让她接着写），也可以翻开新页另起一段时光；
页眉显示这段时间的心情走向（插件记录的连续心情均值）。**日记只给你看**：不进入
她的对话上下文、不进宿主记忆管线--你翻面板就能了解她这段时间的心路。

### 我的日记

第三本日记，关于**你**：插件安静累计相处素材（互动轮数、她的语气分布、
心情走势、她自主起的情绪、碎片里的原话），攒够门槛后由小模型以**中性观察者**
口吻成文一篇客观评价。双门槛先到先写：攒满 `turns_threshold` 轮（默认 50）
或距统计起点满 `days_threshold` 天（默认 7，且期间有聊天--挂机不写空篇）。

- **只给你看**：不进她的对话上下文、不进宿主记忆管线、不注册任何她可调用的
  工具--她连知道这本日记存在的渠道都没有（隔离等级比个人日记更严）
- **如实记录**：过激言行、冷淡期也会写进评价，不粉饰；你命令触发的情绪演示
  （"让她冷战"）与她的自主情绪分开标注，不算你对她不好
- **独立标题（1.3.9）**：同一次成文请求生成标题与正文，标题为单行、最多 40 字，
  在目录、阅读页和档案室显示，并参与搜索。标题随正文保存，重启后仍在；
  旧模型只返回正文也能继续保存，无标题旧篇显示「未命名日记」，不批量改写历史。
- **本卷依据（1.3.0）**：成文时把本次用过的素材--她的语气分布、心情走向、
  你说过的原话摘录--随正文固化进卷宗；素材清零后回看，仍能看到观察者
  是基于什么写下这篇
- 纯文字成段评价（无评分无徽标）；成文默认走宿主模型管线的 **agent 槽**（1.3.3 修订轮
  从 summary 改过来，原因见「模型通道」节），`[review].slot` / `[review].mode` 可换，
  解析不出可用端点或连续被拒时自动休眠
- 面板日记页第三个页签：标题、日期与正文摘录目录，支持全文搜索和每页 8 项分页；
  阅读页以成段正文为主，页眉显示完整生成日期与时间、统计区间。
  互动轮数与其他参考素材可展开查看，宽窗放在右侧、窄窗放在正文后。
  **上一篇 / 下一篇**每次切换一篇完整日记；底栏显示当前标题和生成日期时间，
  不显示阅读位置分数或段数，导航避开设置保存条。目录攒满 52 篇后仍能自动刷新新篇；
  双门槛素材进度
  （轮数条 + 天数副行 + 「到时候了」徽标，两条门槛都看得见）；「立即写一篇」
  按钮（素材不足 10 轮会拒绝硬写）；按角色独立分片
  （`review@<角色>`），保留最近 52 篇
- **她攒得再多也不会丢（1.3.0）**：当前目录攒满 52 篇后，最旧一篇静默搬进
  「档案室」（目录末尾的归档入口显示时段，点开只读翻阅，可跨篇翻页；
  不标卷数不提上限，档案室再满也留了约两年的量），与个人日记的藏书阁同款纪律
- 「立即写一篇」是**排队成文**（1.2.3）：点击秒回"已开始写"、按钮转为
  "正在写…"，实际写作在后台一拍内开始、写完自动落盘并弹出完成提示——
  不用守着页面干等模型出文；素材不足/开关未开/槽位没配模型仍会当场拒绝，
  成文期间重复点击不会叠加（队列槽位只有一个）；
  **手动生成不做随机选择**（1.3.9）：两本日记素材达标后直接调用模型，
  最多尝试两次，每次最多等 45 秒、总期限 90 秒；每次尝试仍遵守通道熔断和每日预算。
  请求超时单独提示，不计作服务端拒绝；请求失败、无有效正文、预算耗尽和保存失败也分别提示，
  失败保留已有记录与素材；
  模型或存储不可用时无法保证写成，不会填入虚构的兜底日记。
  没写成的反馈（1.3.0 第十一轮补齐）：面板开着时成败结论即时弹 toast
  （含挂载后的**第一条**——旧版必吞）；面板关着错过/被吞也没关系，
  日记页会常驻一行"上一篇没写成、可以再点一次"的内联提醒，
  直到下一次点击受理时自动消失

碎片提取要用一个模型：默认**复用宿主自己的模型管线**（`agent` 槽 + `mode=host`，与成文
同一条路）——端点、模型名与客户端身份都由宿主给出，插件不读你的配置文件，**装好就能记**。
代价与闸：agent 档带服务端日配额（宿主自己定 500 次/天，且与宿主 agent 功能共用一份池子），
而碎片节拍约 62 秒一次，所以它配着两道闸跑——当日预算 `[agent_tier].daily_budget`
（出厂 20 次/角色/天，碎片与成文合记一本账）与代码里的 300 秒间隔地板。用满就安静到次日，
面板灯显示"今日额度已用完 · 休眠"，同处给"今日已用 X/20 次"的读数。想让它按老路走
`summary` 槽（语义上与宿主记忆抽取同层级）也行，面板上改一次即可——但免费路由下那一档必被
服务端拒，这条通道会变成休眠；在宿主里配了自己的服务商则两头都通（`custom` 直连也立刻可用）。
两条路都给不出可用端点时功能自动休眠，其余功能不受影响；
总开关与间隔在"时光日记（自动碎片）"设置卡，
槽位与通道在「情绪」页的"模型通道"卡（我的日记同处一张卡）。

配套的宿主协调采用白名单制：只有五个重度负面动作生效期间，
宿主的主动搭话才会临时暂停（只动总开关，不碰你的任何子设置），
结束后按原状恢复——冷战时不会被突然插进来的小游戏邀请打断；
心有涟漪与正面动作不暂停（小情绪和好心情不该把她静默）。
限时动作到期只结束工具记录并通过内部 read 消息同步，不要求她主动开口，
也不表示消气、原谅或恢复亲近。求安抚的兜底时限同样只解除记录。

日常相处中情绪由她自主决定；如果你明确想触发某种情绪，
直接对她说"让她生气/冷战/爆发/求安慰"即可（宿主会路由到插件的「触发情绪动作」入口）。
冷战/已读不回/敷衍/心有涟漪期间出现道歉或安抚关键词，插件只提醒她注意这句话，
不判断诚意或要求和好；语气变暖也不等于矛盾已解决。
也可以直接说"解除她的情绪状态"（路由到「解除情绪动作」入口）。

### 生活感知（与宿主活动系统联动）

她不再只看"现在几点"，也开始看得见你在不在、在忙什么（通过宿主官方
SDK 的 OS 活动快照，与 study_companion 同款，隐私态下自动静默）：

- 你长时间离开电脑 → 潮汐期她也顺势养神，活跃期自己找点事做不干等
- 你在专注做事 → 她陪着但不黏人，回应简短体贴，不主动拉聊天
- 隐私/信号不可用状态 → 完全不描述你的行为，就当看不见

### 语气感知（小模型辅助）

她在**回复完成后**，由一个小模型异步分析这一轮互动（你的话 + 她的回复）的情绪——
不挡聊天链路，零延迟。两种用途：

- **筛选**（她心情正常时）：绝大多数日常闲聊直接跳过；只有这轮互动情绪浓度
  足够高，才轻语提醒她"想记录此刻心情就调情绪工具/手记"——情绪动作不再
  全凭她自由心证，而是由真实互动驱动。抽查频率可调（每轮/一半/偶尔/关闭）。
- **校正**（情绪动作生效中）：每轮都分析她的语气趋势，冷战中她连续几轮语气
  转暖（嘴上和好忘了切状态）→ 提醒她调用心情转晴；开心状态中语气转沉 →
  提醒她换状态或把感受记下来。**只提醒，绝不自动切状态**——决定权始终在她。

阶段灵敏度：潮汐期/回升期/活跃期筛选更灵敏（置信度阈值下移，命中更多），
平静期不变；机制独立开关 + 三档强度（温和/适中/敏感）。

当前心情默认每隔至少 20 秒分析最新的新回复，没有新回复时不调用分析模型。
可在面板「情绪 → 语气感知 → 分析间隔（秒）」设置 10–3600 秒，
点击页面底部「保存设置」后立即生效，重启后保留。实际分析还受每 10 秒
后台轮询及模型响应时间影响，并非固定间隔强制刷新。
愉悦度与活跃度只接受置信度至少 0.6 的有效结果；阶段灵敏度只调整提醒门槛。
中性回复不主动把愉悦度拉回零，仍保留时间带来的自然恢复；
角色活跃度温和地回归静息基线，用户的中性消息不改变角色心情。
用户侧信号以低权重先合入，再合入角色回复，避免开心值接近上限时被用户侧反向拉低。
分析间隔缩短会增加持续聊天时的模型调用，抽查频率与显式配置的间隔仍生效。

### 模型通道（三条通道 · 两种走法）

**三条模型通道与两种通道方式**：语气感知 / 时光日记碎片 / 我的日记成文，每条通道
都有两个正交旋钮——**槽位**（用宿主哪个槽的模型）与**通道方式 `mode`**（由谁去发
这次请求）。`mode=host`（**碎片与成文两条的默认**）把请求交回宿主自己的模型管线：槽位解析、
地域改写、端点与模型名、`neko/<版本>` 客户端身份全部由宿主给出，插件
不读你的配置文件、不自己推端点；`mode=custom` 才是插件读宿主本地
`core_config.json` 拼出端点自己直连（要接本地模型或独立服务商时用，明文 key 的
边界见「隐私与数据边界」节）。host 解析不到端点时自动回落 custom 那条路，所以
默认走法不会比旧版本更差；面板状态灯会替你盯住"选了宿主却没能走通"那一种情况
（自定义走法本来就由插件直连，按正常显示，不误报回落）。

**免费路由按模型档位放行（1.3.3 修订轮实机钉出来的）**：`host` 只决定"用谁的配置和
客户端"，不决定"服务端放行哪一档"。宿主免费路由上 `summary`/`conversation`/`correction`
三个槽都落在 `free-model` 这一档，从插件调用一律被拒（400 `you are not using Lanlan`）；
`agent` 档（`free-agent-model`）实测可用——所以**碎片与成文两条默认都用 agent 槽**，
新用户装完就能记碎片、能出成文。agent 档不是无限的（它的限额真在服务端，本地计数只是
少发无用请求），所以下一段那两道闸是这套默认值成立的前提。

**agent 档的每日预算与间隔地板**：宿主的 `agent` 档带**服务端**日配额（它自己定的是
500 次/天，本地计数只是少发无用请求），而且宿主 agent 功能与插件**共用同一份池子**。
所以凡是实际走 agent 槽的调用（碎片 + 成文，按角色各记一本账）先过两道闸：当日预算
（`[agent_tier].daily_budget`，出厂 20，面板「模型通道」卡上可改，推荐 5~50、硬顶 150）
与 300 秒间隔地板（在代码里，不开放配置——它防的是自动节拍砸配额，用户没有调它的理由）。
预算用完这条通道就休眠到次日零点，灯显示"今日额度已用完 · 休眠"，一条请求都不多发；
面板同处给出"今日已用 X/20 次"的读数（消耗按角色记，所以读数跟着角色走）。
间隔地板只限速、不丢素材：被挡下的那一拍不推进水位，下一拍还会回来。

**连续被拒就熔断**：同一条通道在同一条路上连续失败两次就不再发任何请求（面板灯转成
"服务端拒了·已熔断"），改了槽位/通道、或宿主配置变更、或重启插件服务都会复位重给一次
机会。为什么必须熔断而不是继续按节拍重试：被拒的请求服务端会记成滥用，一直撞下去代价
落在你的账号与出口 IP 上，而功能并不会因此变通。
语气感知不经 `mode` 旋钮：它的默认槽位走宿主本机回环端点，选非默认槽位时插件直连。
以上依赖的都是宿主内部端点与内部模块（官方内置插件同款用法），**无版本承诺**，
宿主改版可能失效——真失效时回落直连，功能不崩。
全部出域通道、截断长度与日志脱敏契约见「隐私与数据边界」节。

### 功能管理（能力中心 1.2.7 · 功能介绍 1.2.7）

所有功能模块接进了统一的能力中心：面板「功能」页把九项能力按
身体节律 / 情绪与感知 / 日记与记录**三组卡横向并排，一屏看全不滚动**
（窄窗自动回落双栏/单栏），每项一个开关 + LLM 触点徽标
（LLM 工具 / 直连模型 / 宿主模型 / 上下文注入 / 纯本地）——不想看心情监控就关
「语气感知」，不想记时光碎片就关「自动碎片」，互不牵连。

三条设计约束：

- **否决式开关，不存在两张皮**：面板关闭 = 往否决集（Store `caps@<角色>` /
  全局 `caps@*`）写一条"关"；重新打开 = 撤掉否决、**回落既有配置默认**
  （plugin.toml 各段与设置页开关照旧是事实源），绝不会"设置页关着、功能页硬点亮"；
  开关拨不动时会如实回弹并说明原因（配置里关着 / 被上游功能挡住）
- **按角色独立**：否决集与周期/情绪/日记同一套分片纪律，切到谁的卡管谁；
  关掉的功能在「已有状态的角色」名单里也能逐人分辨
- **依赖链显式化**：情绪引擎是情绪链路的总闸——关掉它，语气感知/碎片/
  两本日记连带熄灭（面板会写"被谁挡住"）；身体轻语/纪念日等节律注入不受牵连

**功能介绍（1.2.7）**：每个功能行带一个「功能介绍」按钮，点击即在功能页内
切换到页内介绍子页（左上角「返回功能列表」回跳；子页刚好贴合面板框体、
双栏→单栏随窗口宽度自适应折行，无弹窗无横滚条）：
功能作用 / 主要场景 / 依赖 / 限制与注意事项 / 原理演示图（纯 CSS 网格
排版；流程为文字胶囊：输入 → 处理 → 闸门 → 输出，
配色即类型），单页看完。介绍只读不改行为；依赖链与
触点信息现场取自能力声明表，和开关状态同一口径；文案中英双语。

高级选项「关闭的功能从模型可见面摘除工具」（全局，默认关）：温和模式下
关着的功能其 @llm_tool 仍在位、调用时才拒（1.2.x 既有语义）；开启后，对
所有角色都不生效的能力，其工具经官方 `LLM_TOOL_UNREGISTER` 通道从模型
可见面真正摘除（不再占上下文），恢复生效时自动重挂。

**给后续开发的地基**：新增功能模块在 `core/capabilities.py` 声明表登记一行
（id/分组/依赖/绑定的配置键/占用工具/LLM 触点类型），判定改走
`_cap_effective("你的id", shard=...)`，开关/面板渲染/工具显隐/多角色/持久化
全部自动接入；开关操作只经 `set_capability` 一个入口，日志与测试口径统一。

### 面板

- 总览：阶段、周期第几天、距下次潮汐、当前情绪（心情徽标按语气分色：
  暖流涌动/满潮欢喜为绿色 success，其余为 warning，状态栏与管理区名单一致）
- **面板外观（1.3.3 · 柔和默认主题与壁纸联动）**：壁纸贯穿状态栏、侧栏与内容区，
  统一中性底色、细边框，减少嵌套底色和重复阴影；无壁纸时保持默认浅蓝强调色，
  表面仍跟随系统明暗主题。无壁纸的界面采用柔和雾蓝填充、石墨灰正文和较轻的边框、
  阴影；按钮和选中态的浅色底与可读字色分开，深色模式使用中性灰底，
  减少大面积深蓝与近黑色的压迫感。日记保留独立纸页，段落直接排在纸面上。

  - **壁纸图库**：图片和视频共用图库，点缩略图随时切换壁纸，可逐项删除（需确认），
    首格「不用壁纸」恢复默认中性底，共计上限 24 项。缩略图分别标注「已应用」与未保存的
    「预览中」，选择和删除是独立按钮，支持键盘操作。导入方式二选一：
    「自动压缩」（缩到长边 2560 并重编码，图库能放更多张，推荐）或「原画质」（≤4MB 原样保留）；
    PNG/JPG/WebP/GIF/SVG 均可；GIF / SVG、动画 WebP 和 APNG 保留原文件，
    不经 Canvas 压缩成静态一帧，仍须符合图片容量限制。

    **256 MiB**、视频库预算 **2 GiB**。可在「壁纸存储」调整单个视频上限
    （32 至 512 MiB）和视频库预算（64 至 16,384 MiB）。

    新上传还须为同一数据盘保留 64 MiB 可用空间。
    浏览器先实际解码并生成静态封面、缩略图，再以 768 KiB 小块上传；
    扩展名正确但编码无法播放的视频也会被拒绝。视频静音循环，无音频播放；
    「背景调节」中的视频播放开关可停用动态效果，系统减少动态偏好也会生效。
    页面隐藏时暂停，普通 5 秒状态刷新不重启播放；切换或关闭面板会释放媒体资源。
    播放失败时保留可用的旧背景或显示静态封面，面板文字与控件继续可用。
    视频支持铺满裁剪、完整显示和拉伸，不支持动态平铺。
    新视频以原始二进制文件保存，不再将整段视频 Base64 写进数据库。
    导入成功后当前面板保留一个待选择视频的本地预览；选中时无需重新读取整段媒体。
    面板关闭会释放预览，重开时仍读取持久视频，并先显示封面与加载状态。
    播放仍经现有面板动作逐块读取、完整组装 Blob 后开始，**不是 HTTP Range
    流式播放**；大视频可能准备较慢并占用较多浏览器内存。读取硬上限 512 MiB，
    不因提高总库预算而无限扩大单次播放内存。
  - **Wallpaper Engine 目录导入（1.3.8）**：选择包含 `project.json` 的项目目录，
    或包含多个项目的上级目录，在识别结果中逐项导入。只读取你通过文件选择器
    授权的文件，不扫描 Steam 路径，不修改源文件。仅支持 `type` 为 `image` /
    `video` 且 `file` 指向受支持原媒体文件的项目；`scene`、`web`、

### 多角色（每个角色独立）

每个角色（lanlan）拥有自己完整的一份潮汐状态，**切换角色卡无需重开插件**，
面板自动跟随宿主当前角色--切到谁的卡，就看谁、改谁。

**按角色独立**的：总开关、锚点日期、快进天数、周期参数（自动演算/周期长度/
潮汐期长度/活跃日/活跃窗口）、情绪状态、时光日记、个人日记、我的日记、
功能管理的否决集（caps@<角色>）。

**全局共享**的：注入策略（注入模式/间隔/触发关键词）、各阶段提示词与开场白
文案、时区、生活感知、调试模式、屏蔽词表、`[mood]` 情绪系统参数。

两点细节：

- `plugin.toml` 里 `[tide]` 的周期参数现在是**新角色的默认值**；面板里
  改周期参数只作用于宿主当前角色，不影响其他人。
- 旧版（≤0.4.0）的单份数据在升级后首次启动会**自动迁移归属当前角色**，
  旧数据保留备份不删除。
- 所有注入与推送都按角色定向送达；消息轮询也会按记录里的角色字段归属到
  对应角色的状态。情绪动作触发的宿主主动搭话暂停是全局引用计数（仅重度
  负面动作计入）：任一角色情绪生效即暂停，全部解除才恢复。

## 快速开始

安装后的第一次打开面板，会自动弹出一个**六步新手向导**：认识插件的四块能力、
一键开启她的节律、体检三条模型通道、当场填**主人生日**（与「时光」页同一张生日
设置卡）、领你去「设置」页看**面板壁纸**、告诉你后续去哪里细调——除生日那页是
用户主动填、壁纸那页只是跳转引导外，向导不替用户改任何设置，"稍后再说"后不再
自动弹（可在「设置」页底部重新打开）。之后总览页顶部会常驻一张**准备清单**：还差
什么（必办/建议）一眼可见、逐项直达设置页，全部就绪后自动收起。

> 向导改版（1.3.1 修订轮三加了生日/壁纸两页）后，老用户会被再放行一次：完成或
> 跳过新向导即盖新版本号、不再重复弹。

手动路径与向导等价：

1. 打开面板，顶部状态条开启总开关。锚点可以不用动：留空则首启随机落在
   平稳期的某一天（装完前几天不会立刻是潮汐日，每次安装起点也各不相同；
   她早就有自己的节律，只是今天开始被你观测），也可在设置**潮汐首日锚点**
   （如 `2026-08-01`）自己定一个有纪念意义的日子；锚点落定后固定，重启不重随
2. 想更细腻的话再去设置：保存
3. 正常聊天即可。她今天是什么状态，会自然地体现在语气里

> 潮汐期长度、活跃日、活跃窗口默认**自动演算**（基于固定黄体期模型：
> 活跃日 ≈ 周期长度 − 14，潮汐期 5 天，活跃窗口 ±3 天），只需填周期长度；
> 关闭「自动演算」开关后可手动调整每一项。

## 设计原则

- **低侵入**：状态注入有变化门控与频控（默认每 3 条消息至多一次），
  内容没变不重复说；read 注入虽会进入对话历史，但节制的频率
  让记忆抽取自然消化而不是污染
- **不打架**：情绪期自动协调宿主主动搭话（暂停/恢复均只动总开关，
  原值回写）；她的手记经对话上下文自然进入长期记忆，自动碎片只记
  宿主不抽的原话与情绪事件且从不主动注入，个人日记完全不进记忆管线——
  三条路与宿主记忆系统互补不冲突
- **零依赖**：纯标准库实现

## 隐私与数据边界

**本地优先**：周期/情绪/三本日记/统计/配置全部存在插件自己的存储里；
插件不向任何第三方服务器发请求、无遥测、无作者侧回传——插件发起的
网络请求只有两个去向：**宿主本机回环端点**与**你自己在宿主里配置的
模型服务商端点**。

会送到模型侧的对话文本只有三条通道，各自可关（截断长度以代码为准）：

| 通道 | 送什么 | 送到哪 | 怎么关 |
|------|--------|--------|--------|
| 语气感知 `[emotion_sense]` | 她的本轮回复（≤500 字）+ 你的消息（≤300 字，传导用） | 默认槽位走**宿主本机回环**端点；选非默认槽位时插件读宿主本地 `core_config.json` 直连该槽位端点 | `[emotion_sense].enabled=false` 或面板「情绪」页关闭 |
| 时光日记碎片 `[fragments]` | 你的最新一句（≤300 字）+ 她回复片段（≤120 字，仅作语境） | 默认（`mode=host`）**交回宿主的模型管线**：端点、模型名与协议由宿主给出，插件不读你的配置文件；`mode=custom` 时插件读宿主本地配置自己直连该槽 | `[fragments].enabled=false` |
| 我的日记成文 `[review]` | 相处统计 + 期间碎片原话（≤6 条、每条≤60 字）+ 最近对话摘样（≤8 轮、每边≤80 字） | 同上（默认 summary 槽、默认走宿主管线） | `[review].enabled=false` |

三条通道**的服务商都是你自己在宿主里配的**——插件从不替你选去处，改的只是
"由谁去发这次请求"。默认形态下碎片与成文都交回宿主管线（和宿主内置插件同一条
路），插件不需要自己读 `core_config.json`、也不需要自己推端点。但有一条边界要说准：
**两种 `mode` 都不能让插件不持有 key**——`host` 是宿主把该槽的
`{model, api_key, base_url}` 三元组交给插件、由插件调用宿主的客户端工厂发出这次请求，
key 照样经过插件内存（解析结果按 5 秒缓存）；`custom` 则是插件自己从盘上拼。
介意的话面板里把功能关掉即全本地，关后只剩本机回环通信；语气感知的默认槽位是插件
不经手凭据的唯一一条——prompt 交给宿主自己的端点，模型由宿主调。

**明文 API key 的边界（两种 `mode` 同等适用）**：key 只来自你在宿主里配的那一家，
**只用于向该服务商发这次请求**；不写任何日志、不进面板回显（调试入口只显协议+主机名
+`…` 与模型名）、不发送给除该服务商以外的任何地址。两者只差在来源：`custom` 由插件
从宿主本地 `core_config.json` 读出，`host` 由宿主自己的配置解析现算后交给插件（走
这条时插件不读那个文件）。

**日志脱敏（1.3.0 第十轮契约）**：宿主规范要求"不把原始对话、密钥或
私有 payload 写进日志"。本插件的直连失败留痕只记错误类型/状态码/结构
摘要；碎片捕获只记原话长度不记内容；成文失败只记回复形态分类。由常驻
回归门（tests/test_privacy_hygiene.py：行为门+AST 静态门，均带反向对照）
钉死，后续改动一旦把内容写回日志即红。

另：生活感知只读宿主官方 SDK 的 OS 活动快照（在不在/是否专注，不含
屏幕内容），宿主隐私态下自动静默。

## 调试模式快速验证指南（测试用）

大部分内部机制自然触发很慢（兜底等 2 小时、工具校验等 5 分钟、活动感知要你真离开电脑）。
把 `[tide].debug_mode` 设为 `true`（或调 `update_settings` 入口传 `debug_mode: true`），
会注册一组 `debug_*` 入口（Plugin Manager 入口列表 / 命令面板可调用），把每个机制快进到秒级：

| 想验证什么 | 怎么做 |
|---|---|
| 开关是否真的生效 | 开启总开关的瞬间会立即注入一次（日志出现 `body whisper injected`）；不用等满 3 条消息 |
| 注入内容（阶段感受/情绪行/生活感知行） | `debug_inject` —— 强制注入一次并返回全部注入文本 |
| 情绪动作面板不动/想直接触发 | 对她说"让她冷战/爆发/求安慰"（路由到「触发情绪动作」入口），或调试入口 `debug_set_mood`；面板"情绪状态"会实时显示当前动作 |
| 求安抚兜底结束记录 | `update_settings` 把 `open_action_timeout_minutes` 设为 2，然后 `debug_set_mood(action=seek_harbor, minutes_ago=3)`，检查状态清除及到期事件，不要求主动开口 |
| 限时情绪到期记录 | `debug_set_mood(action=ebb_tide, duration_minutes=30)` 再 `debug_expire_mood`，检查情绪页的到期事件；只同步内部 read 消息 |
| 生活感知各分支 | `debug_force_activity(idle_seconds=3600)` 或 `(category=work)` / `(category=gaming)` / `(privacy=private)`，再 `debug_inject` 看返回文本；三个参数全空调一次即清除覆写 |
| 注入频控/计数（interval_n） | 连续调 `debug_simulate_user_message`，看返回的 `message_counter` 与 `injected` |
| 工具重注册韧性 | 重启 main_server 后调 `debug_check_tools`，不用等 5 分钟；返回在位/缺失/是否当场重注册 |
| 个人日记资格与邀请 | `debug_journal` 返回当前资格判定（due/reason/页数）；`debug_journal(force=true)` 立即推一次邀请（1.2.4 起真会跳过 7 天节奏闸；此前这一档仍受节奏限制，刚写过日记的机器上静默不递），观察她是否调 `mood_journal_write` 写日记（面板日记 tab 可见）；返回里的 `deliver` 回显投递方式（respond 当面递到 / read 补递 / failed 通道拒收） |

## 平台机制与已知限制（读完再用）

- **覆盖导入后新入口要重启宿主才可达（1.3.0 实机踩坑）**：面板 action 调用由宿主
  进程**启动时**扫描的静态入口白名单授权；运行中覆盖导入只会重启插件子进程
  （新代码当场生效），宿主不会重扫静态白名单——面板调新增入口会得到
  `403 action_not_exposed`（实测：日志 `Hosted UI action rejected …
  reason=action_not_exposed`，stop/start 也不刷新）。本插件的防御：面板拉取一律
  **搭已白名单的旧入口加参数**（藏书阁翻阅 = `get_journal(scope=archive)`，
  档案室翻阅 = `get_review(scope=archive)`——1.3.0 我的日记完善时同款防御直接复用），
  新入口 `get_journal_archive` / `get_review_archive` 保留给 API/跨插件与重启后的规范调用；根治在
  平台侧（覆盖导入应重扫并刷新注册表静态元数据），插件不越界改平台。
  **临时用法**：装完新包后整启一次 N.E.K.O，新入口即可直达；不整启也不影响
  面板（已走旧入口通道）。
- **轮询节奏**：平台不会向插件派发聊天事件，插件每 10 秒轮询一次用户消息总线，
  因此注入与限时动作到期检测最多滞后 10 秒。这不是 bug；watcher 订阅机制只支持
  messages/events/lifecycle 总线，承载用户消息的 memory 总线不可订阅，轮询已是插件侧最优解。
- **内部提示永不上屏（1.3.2 契约）**：插件递给她的每一条提示（身体轻语、阶段开场白、
  日记邀请、纪念日/生日轻语、情绪到期记录、语气与碎片轻语）都只进她的上下文或只起一轮，
  聊天框里只会出现**她说出来的话**。宿主侧 `visibility` 与 `ai_behavior` 是两个独立出口：
  带 `"chat"` 就把提示原文贴进聊天框（署名为插件 id），起不起轮只看 `ai_behavior`——
  所以"想让她主动开口一句"的正确形态是 `visibility=[]` + `ai_behavior="respond"`。
  情绪到期记录使用 `read`，不主动起轮，不要求缓和。
  1.3.2 之前阶段开场白与情绪恢复台词误带过 `["chat"]`（提示词整段上屏、她接着又说一遍），
  现已由常驻门 `tests/test_push_visibility.py` 钉死。
- **一切"轻语"都挂在潮汐模拟开关上（1.3.1 审查轮明载）**：read 轻语家族——身体
  轻语、阶段开场白、纪念日轻语（`[stats].anniversary_inject`）、生日轻语
  （`[birthday]`）——都由 tick 的消息注入链路驱动。tick 开头有 fail-closed 拦截：
  全局 `[tide].enabled` 与任一角色总开关都关着时整条注入链路不跑（避免空闲期
  每天数千次角色解析空转）；过了全局闸后，某角色的轻语仍要**该角色自己的模拟
  开着**才递。所以"装好了、日期也填了，却什么都没递"先去看面板总开关与「功能」
  页的挡因标注——这是"知情同意"默认形态的实现，不是 bug。
- **排队成文（1.2.3）**：「立即写一篇」的模型成文不再挂在面板入口的请求-响应链上。
  平台对面板动作有约 30 秒的执行超时，与浏览器端默认超时压线：旧版同步等模型出文
  （5～20 秒起步）时，用户既干等无反馈，慢一点还会"超时了文章却照常出现"甚至关面板
  断连把写一半的篇目取消掉。现在入口只做受理（秒回）。1.3.9 起，两本日记的手动
  成文交给每 2 秒检查一次队列的独立 SDK 定时器，在宿主分配的线程里完成请求与保存，
  落盘后经面板轮询回流；队列空闲时通常一拍内开始，已有写作时排队等待。
  每次模型请求最多等 45 秒、最多两次、总期限 90 秒，慢回复不阻塞常规 10 秒轮询的
  用户消息注入、语气感知与碎片捕获。手动写作排队或进行中，自动我的日记暂缓，
  完成后恢复原有门槛；成功日志标明手动或自动来源，便于核对两本日记的生成原因。
  自动我的日记仍在常规轮询尾部执行，模型调用最长 25 秒。
- **自动日记邀请（1.2.3；1.3.9 手动入口另行直接成文）**：个人日记的周期邀请走
  read（安静流进上下文，等她下次开口自然想起，绝不打扰），保留角色自主决定写不写。
  调试邀请可走 respond **当面递到**，由角色决定并调用工具落笔。
  面板「邀请写日记」已改为素材达标后直接排队生成新篇，不再走这条邀请通道。
  调试 respond 档带 10 分钟冷却：刚递过再按会
  回落为 read 补递并如实提示，防连点成骚扰；同 coalesce_key 在宿主队列内还会
  折叠去重。"正等她落笔"挂起提示亮到她写出新页为止；她续写当前页（页数不变）
  时面板靠"页码:段数:末笔时刻"指纹自动感知刷新，不再要求手动点刷新。
  1.2.4 起这条承诺是硬的：递邀会校验平台的提交回执，通道拒收（背压/不可用）时
  面板当场报"没能送到、再按一次试试"，水位回滚可立刻重按，也不会挂着"正等她落笔"
  骗你（周期档的递邀失败不回滚水位，避免通道一直坏时每趟都重推刷屏）。
  **1.3.2 起节流水位随 `cycle@<角色>` 落盘**：插件子进程会因切角色卡/改设置/覆盖导入
  反复重启，而水位过去只在内存——她一页日记都没写时节奏闸恒开，于是每次启动都重递
  一条首邀（实机 2026-09-21：三次重启三条）。落盘后 24h 窗口与手动档 10 分钟冷却都
  跨重启，"正等她落笔"也真能挂到她写出新页为止；**只有递成功那次才写盘**，
  通道拒收那次不占用窗口。
- **重启后开关与记录的保持（1.2.1 起）**：平台的持久存储在建插件实例那一刻可能还
  没"通电"（通电开关来自运行配置，而配置此时尚未就位），未通电时读写一律静默空转、
  不报错——看起来就像"你从没开过模拟"。插件现在会在读状态之前先把存储唤醒，因此
  **开启一次即长期有效，重启后开关、锚点、快进、三本日记与相处统计都会原样回来**。
  万一唤醒失败（日志见 `PluginStore still disabled`），本次会走"不可信载入"降级：
  开关当次显示为关，但**绝不把空状态写回盘**，你的历史记录不受损，重启即恢复。
  1.2.2 起这条防线补成了闭环：若存储是在**会话中途**才回电，插件会在第一次写入
  之前自动把盘上真实状态重新载入替换内存幻影（日志
  `store became ready after an untrusted load`），此后一切读写都作用在真实数据上；
  关机时也会把相处统计与"我的日记"素材一并补刷落盘。
  根治在平台侧（应在插件启动前完成存储通电），已按此口径记录，插件不越界改平台。
- **写失败如实上报（1.2.2 起，审查轮补齐外观/图库）**：开关/锚点/删除/清空/成文
  等操作若遇到**真实的**存储写失败（磁盘满、数据库锁），面板会直接报错而不是假装
  成功——内存里当场生效、盘上保持原样，你可以清理空间后重试。1.2.2 审查轮起，
  **面板外观与壁纸图库**也走同一套统一出口：写失败如实报错、未通电留日志预警，
  不再有"显示已保存、重启后壁纸没了"的旁路。注意区分：只有"启动时存储没通电"
  那一种情形仍是静默降级（当场生效、重启即丢，见上一条），因为那种时候连报错
  通道都被平台堵着，插件只能靠日志与自动重载兜底。
- **主动搭话暂停的恢复凭据（1.2.2 审查轮起）**：她冷战期间插件会临时替你关掉
  宿主"主动搭话"总开关，并在恢复时原样打开。这份"关之前的原值"凭据现在**先写进
  存储、才去翻开关**（写失败则整个暂停放弃、稍后自动重试），消除极端情况下
  （凭据恰好没存住 + 强杀）"总开关被关掉却没人记得恢复"的卡死。注意：**在修复之前
  的旧版本里已经卡死的会话无法事后区分**"是插件弄关的"还是"你自己关的"，若发现
  主动搭话一直不开，请到宿主设置里手动打开一次（此后由本机制接管）。
- **中途通电的自动自愈（1.2.2 审查轮起）**：若某次启动存储没通电（见上），而
  会话中途存储回电了，插件现在**每 10 秒的自检步骤会自动把盘上真实状态重载回来**，
  不再需要你打开一次面板来触发；期间随机生成的周期锚点若属可信会话也会当场落盘
  （强杀重启不再重新随机）。
- **语音会话中的送达延迟**：实时语音聊天期间，平台会把被动（read）类消息暂存，
  等下一次会话自然热切换时才送入——语音正吵得热烈时，身体轻语/情绪指令可能迟到。
  这是平台生命周期机制而非插件失灵；文字聊天不受影响。
- **表情联动**：宿主表情管线分析她回复文本的主导情绪驱动 avatar 表情；插件在情绪动作的
  行为指令里要求主导情绪清晰可辨，让表情能跟上情绪；但静默类动作（冷战/已读不回）期间
  她不回复，表情无输入可分析，属已知盲区。
- **与宿主记忆的分工**：宿主自己会从对话里抽取"你的偏好/习惯"类事实并入它的记忆系统；
  时光日记的自动碎片重点记宿主不记的东西——**原话摘录、情绪事件、过激行为**——
  且从不主动注入对话（只有她自主检索 + 重度情绪期间单条轻语），两者互补不打架；
  个人日记完全不进记忆管线，只给你翻看。
- **多角色**：0.5.0 起已实现 per-lanlan 独立状态（开关/锚点/快进/周期参数/情绪/手记各自独立，
  注入按角色定向；详见上文「多角色」节）。面板自动跟随宿主当前角色，
  查看与修改都作用于正在聊的她。
- **切换角色卡与插件重启**：切换角色等操作会重启宿主插件服务。本插件配置为随宿主自动启动；
  若你在 Plugin Manager 里关掉了它的"自动启动/运行"开关，切角色后插件会静默消失、
  面板报"插件未找到"，需手动重启插件。
- **记录存在哪里**：周期开关/锚点/快进、情绪、三本日记、相处统计都写在
  `应用数据目录/N.E.K.O/plugins/forever_companion/data/store.db`（宿主 PluginStore，
  逐写提交），不写进 `plugin.toml`。手动导出的备份及恢复前的自动备份位于同目录下的
  `backups/`；日常运行不周期性复制数据库。
- **升级与卸载后记录保留（2026-09-07 复核更新）**：新宿主（2026-08-27 起 #2943
  代码/状态布局分离）把插件**代码**与**记录**分家存放——代码在
  `应用数据目录/N.E.K.O/.neko-plugin-installations/plugins/forever_companion/`，
  上面那个 `data/store.db` 原地不动。升级与卸载事务都**只搬移代码目录**
  （rename 进 `.upgrade-backups`/`.uninstall-backups` 留备份，失败原子回滚），
  并有硬校验拒绝任何与记录根重叠的路径；Market 更新与 `.neko-plugin` 覆盖导入
  共用同一套替换事务，卸载后重装记录同样读回——机制上就碰不到你的日记与统计。
  实测（2026-09-07）：布局迁移与 1.2.2→1.2.3 升级连环走完，开关/锚点/三本日记/
  统计原地存活，升级后照常写入。**唯一例外是 2026-08-27 之前的旧宿主构建**：
  那时代码与记录同居一个目录，覆盖导入会连同数据一起重建、记录归零（本条此前
  的警告即源于对旧宿主的实测）。若宿主是旧构建请优先升级宿主；否则升级插件前
  先在面板翻看想留住的记录、自行保存内容。
- **重启不会丢记录（1.2.1 起）**：与上一条不同的另一件事——插件读这些记录的时机在
  1.2.0 及之前有问题，会让开关与锚点"每次重启都像被重置"。1.2.1 已修复：**日常重启
  不再需要重新开启模拟**，锚点/快进/三本日记/统计都会原样回来；万一存储未能按时
  通电，插件会走"不可信载入"降级——当次显示为关闭，但**绝不把空状态写回盘**，
  历史记录不受损，重启即恢复。详见上文「重启后开关与记录的保持」。
- **想清除自己的数据**：相处统计可用「清零相处统计」按角色清除；
  壁纸用「清空壁纸与缓存」并确认。时光日记与我的日记页面不提供整本清空按钮，
  时光日记的对话片段仍可逐条删除。
  仅删除 `store.db` 不再能清除文件型视频，因为媒体另存于同一插件持久数据根内的
  `wallpapers` 目录。手动删除应先关闭插件，并核对宿主当前选择的数据目录；
  不要将任意 C 盘路径当作所有用户的数据位置。
- **壁纸升级与降级边界（1.3.8）**：文件清单独立版本化，旧版 Store 视频双读，
  不做不可逆的首次启动全库迁移。新版文件型视频不会被打入导入包；
  旧插件未必能识别或播放新格式大视频，代码回滚也不等于数据回滚。
  遇到不认识的更高版媒体清单时停止相关写入，不将其当成空库覆盖。
- **相处统计的保留窗口**：徽章与累计总数（相伴天数/总轮数/冷战与和好等）即时重算、
  永久保留；逐日明细（热力图的底层数据）保留最近 730 天，月报保留最近 24 个月，
  超出窗口淘汰最旧——淘汰后旧日子的热度细节不再可见，但总数与里程碑不受影响。
- **聊天侧的入口可见面是收敛过的（1.3.1 修订）**：宿主的"用户插件 Agent 路由"会按聊天
  意图自动挑选插件入口执行，且**触发不经过面板确认**。本插件 32 个静态入口里只有
  6 个（状态查询/总开关/情绪 set·lift/能力列表与单项开关）对这条路由可见，其余
  面板取数、设置写入与全部危险操作均已标记 `agent_hidden` 从路由摘除——面板功能、
  跨插件调用、命令面板完全不受影响；想让隐藏项响应聊天，请走面板按钮。
