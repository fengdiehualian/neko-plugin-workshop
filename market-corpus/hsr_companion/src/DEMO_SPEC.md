# 《崩坏：星穹铁道》AI 陪玩插件旧版 Demo 技术规格（历史）

> 本文记录 0.5/0.6 阶段的历史验证目标。当前正式运行与数据架构以 `ARCHITECTURE.md` 为准。

## 1. Demo 要验证什么

0.5 版验证三条最小闭环：

```text
玩家开启星铁陪玩
  → 插件主动注入可信星铁语境
  → 星铁问题先经过统一查询入口
  → N.E.K.O 使用插件事实而不是自由猜测

玩家提供游戏情况或截图
  → 插件查询带来源的星铁知识
  → 角色名经过注册表校验，识别结果等待确认
  → 玩家纠错按截图、会话或全局别名安全记住
  → 结合玩家结构化档案做基础分析
  → N.E.K.O 用自身人格完成表达
  → 重要经历保存在可更正的插件记录中

插件取得玩家授权后观察前台游戏窗口
  → 共享 OCR 先判断受支持页面，再读取限定区域
  → 插件保存带来源、置信度和证据的已验证短时状态
  → 状态主动进入猫娘语境，并在五分钟后失效
  → 模型自行报告的画面描述仅作为未验证线索
```

Demo 不验证完整攻略库、自动账号同步、实时画面识别、复杂战斗模拟或任何游戏自动操作。

## 2. 演示脚本

1. 玩家说：“我有姬子、艾丝妲、娜塔莎，最近想练姬子。”
2. N.E.K.O 调用 `hsr_update_player_context`，只记录玩家明确提供的内容。
3. 玩家问：“姬子是什么定位？这三个人组队还缺什么？”
4. N.E.K.O 调用 `hsr_lookup` 和 `hsr_analyze_team`。
5. 工具返回知识来源、Demo 版本状态、玩家档案匹配情况与透明的规则分析。
6. N.E.K.O 以自身人格表达，不照抄数据库结果。
7. 玩家之后说：“我终于把姬子练起来了。”
8. N.E.K.O 经玩家确认后调用 `hsr_record_experience`，记录一条 `milestone`。
9. 演示者可调用 `notify_game_event`，验证事件去重、过期、静默读取与主动回应。

## 3. 数据边界

### 3.1 星铁知识

每条知识至少包含：

- 稳定 ID、分类、名称、别名；
- 原创摘要与分析标签；
- `source_refs`；
- 数据修订号、游戏版本和校验状态；
- 不直接复制第三方攻略正文、图片、图标或音频。

### 3.2 玩家结构化档案

允许记录：已拥有角色、喜欢的角色、培养目标、常用队伍、当前目标、偏好和进度备注。

它是可查看、可更正、可清除的事实档案，不冒充 N.E.K.O 的长期情感记忆。

### 3.3 游戏经历

只有玩家明确确认的经历才可记录。每条记录包含类型、摘要、重要性、标签和时间，并明确标记为 `plugin_record_only`。

## 4. 对外能力

| 能力 | 用途 | 是否给对话期 LLM |
|---|---|---|
| `start_companion_session` | 开启陪玩并主动注入可信语境 | 否，供面板调用 |
| `hsr_companion_prepare` | 星铁问题统一入口，返回会话、注册表解析、档案与知识 | 是 |
| `lookup` / `hsr_lookup` | 检索带来源的知识 | 是 |
| `hsr_remember_character_correction` | 保存视觉、语音或聊天纠错 | 是 |
| `hsr_report_game_state` | 保存模型看到的未验证状态线索，不覆盖本地状态 | 是 |
| `hsr_stage_player_context` / `hsr_confirm_player_context` | 暂存并确认视觉建档结果 | 是 |
| `update_player_context` / `hsr_update_player_context` | 更新或更正玩家档案 | 是 |
| `get_player_context` / `hsr_get_player_context` | 读取玩家档案 | 是 |
| `analyze_team` / `hsr_analyze_team` | 透明规则型队伍检查 | 是 |
| `record_experience` / `hsr_record_experience` | 记录确认过的游戏经历 | 是 |
| `notify_game_event` | 将外部游戏事件交给 N.E.K.O | 否，供管理面板或未来适配器调用 |

## 5. 事件安全规则

- `dry_run=true` 为默认值；
- `event_id` 去重；
- ISO 8601 时间校验与事件过期；
- 默认 `ai_behavior=read`，不打断当前对话；
- 只有 `request_response=true` 才请求 N.E.K.O 立即回应；
- 事件文本只陈述已知事实，不替 N.E.K.O 写固定台词。

## 6. 来源与许可策略

Demo 数据源注册表位于 `resources/sources.json`。当前样本只保存来源元数据和原创事实摘要，未把官方站点误标成开放许可。

正式数据管线必须逐源记录：来源名称、URL、抓取或发布版本、获取时间、许可证或服务条款、署名文本、允许的再分发方式和下架机制。代码许可证、API 使用条款、数据集许可证和游戏内容权利必须分别审查。

## 7. 验收标准

- 查询结果能回传来源、数据修订号和校验状态；
- 玩家档案会改变队伍分析结果；
- 玩家更正或清除档案后，旧信息不再被复用；
- 未收录角色不会被编造为已知；
- 星铁陪玩会话开启后，插件会主动发送可信上下文，且统一查询入口能返回已确认玩家档案；
- 视觉纠错不会把另一个真实角色名永久重写为错误映射；
- 未知语音同音写法可作为玩家别名记住；
- 经历只在明确调用后保存，并标明记忆边界；
- 重复或过期事件不会推送；
- `dry_run` 不会打扰 N.E.K.O；
- 插件不读取、修改、控制或注入游戏客户端。

## 8. Demo 之后

0.8 已增加外置版本化资料组件、受支持页面 OCR 与本地状态验证。完整账号同步、自由视角头像模型、复杂战斗模拟和自动操作仍不在当前范围。
