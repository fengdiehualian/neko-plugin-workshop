# 星铁游戏搭子 0.9.1 架构说明

## 目标

0.9 的运行前提不再是 N.E.K.O. 语音或视频通话。玩家在面板开启后台感知后，
插件自己的本地助手观察星铁的独立窗口表面，切换到聊天不暂停；插件把经过数据库约束和多帧确认的结构化事实
写入 N.E.K.O. 上下文。没有可靠证据时保持 `unknown`，不把模型猜测升级为事实。

## 核心链路

```text
玩家开启后台感知
  → 插件启动独立本地助手（127.0.0.1）
  → 助手只捕获星铁客户区，原始帧仅在内存中存在，不包含其他应用和猫娘覆盖层
  → 插件读取最新帧；旧帧不会排队回放
  → 共享 RapidOCR：原始像素重叠分块覆盖全画面，检测到的文字块局部重读
  → 页面无关的名字与等级/命途等字段拆解；未知句子不作为角色名
  → 页面与布局只细化名字含义，不阻断基础读名
  → 角色名称绑定固定版本实体 ID
  → 场景/角色连续帧确认
  → 新鲜度、冷却、优先级和全局节奏裁决
  → 普通状态以 `read` 静默同步，重要事件才以 `respond` 请求自然回应
  → N.E.K.O. 获得结构化星铁上下文，不接收自动观察的原始视频帧
```

## 进程和组件边界

### 市场插件

- 管理陪玩会话、玩家档案、纠错和资料查询；
- 启动、停止和检查本地助手；
- 运行 OCR、数据库校验、多帧稳定和事件仲裁；
- 只向 N.E.K.O. 投递验证后的文字事实与事件。

### 本地助手

- 独立进程，只监听 `127.0.0.1`；
- 识别星铁进程和窗口，不接受任意窗口句柄；
- 仅捕获已定位的游戏窗口表面，不要求输入焦点；最小化、隐藏、关闭窗口时停止，黑屏或无新画面时不复用旧帧；
- 不注入、不读内存、不抓包、不模拟输入；
- 当前协议为 `1`，提供 `/health` 和 `/api/frame`；
- 后续独立视觉模型可以在不改变插件接口的情况下返回结构化 `analysis`。

### 外部资源

```text
%LOCALAPPDATA%\N.E.K.O\data-packs\hsr_companion\
├─ current.json / knowledge.sqlite
└─ assistant\
   ├─ current.json
   └─ 0.9.0\hsr-vision-assistant.exe
```

插件仓库保留轻量源码兼容助手。正式 Windows 助手由 Release 工作流构建为单独资产，
下载后经过固定来源限制、SHA-256 校验和安全解压，再写入 `current.json`。独立组件损坏
时，插件可以降级到进程内兼容捕获；资料查询和玩家档案不受影响。

## 可信状态

- 场景只依据支持页面的文字和布局锚点；
- 角色身份必须经过固定版本角色注册表；
- `mixed` 结果需要连续帧确认；
- 当前帧不再读到的人名立即退出当前证据，不能以历史可信结果填充；
- 两个真实角色之间的玩家纠正只记录歧义，不能全局改写；
- 视觉纠正必须绑定当时角色区域的不可逆指纹。

## 通用文字层（2026-10-07 本地补丁）

`runtime/live_refresh.py` 让自动观察成为唯一 OCR 生产者，问答只请求并等待
新采样。查询同时校验采集时间与递增序号；超时不返回旧事实。OCR 期间监测
助手新帧，检测到界面或既有名字区域大幅变化后撤销旧证据并丢弃旧工作。
停止观察会等待在途识别工作退出，再释放资源。画面变化阈值仍需实机验证。

场景与角色采用分阶段结果：首先用缩略全图读取大字标题和场景特有控件，只发布
高置信、无冲突的完整标签；全分辨率角色 OCR 与头像核对随后继续。场景预读
不算原生全图覆盖、不带任何名字或旧名单。菜单标题必须位于顶部；配队、战斗、
剧情等特有控件可位于其他位置，避免玩家自定义队伍标题挡住快速判断。没有
可靠标签时等待原生全图结果，不为追求速度猜测场景。
仅询问页面时可在场景确认后返回，询问角色或含糊的“再看看”仍等待身份分析。
自然问法“现在在哪”同样进入当前场景查询，工具将场景答复与角色答复分开。
场景预读最长边为 768，身份识别仍保留原生像素覆盖。无标题的探索页面可使用
至少三个有序 HUD 快捷键与左侧任务导航或“疾跑 + 普攻/秘技”控件组合共同确认，
不以角色名或特定任务文案作为场景前置门槛。
完整规范名字另用原图检测框的放大彩色像素复核，两次高置信 OCR 与同一实体
一致才免去第二轮整屏；合并行、冲突、别名和低分证据继续多帧确认。这是同帧
不同尺寸复读，不是独立帧或独立模型，不能证明 3D 角色或当前操控关系。
每次 OCR 调用记录阶段、尺寸和调用耗时（包含初始化/共享等待），不记录原始
文字进计时日志；头像耗时独立记录。`scripts/check_recognition_samples.py` 用
既有授权截图做离线真实 OCR 回放，报告缺失项并返回非零状态，不替代实机验收。
新查询加入正在运行的识别任务；任务完成后对最新画面核对，确认是否可用于这次查询。
只有实际画面变化、暂停或生命周期结束才取消旧识别，不因提问本身无条件重开。
自动观察分析期间和分析间隙均检查新帧；插件向宿主交付查询结果或主动事件前，
再次检查最新帧。该校验不等于截获宿主已经生成或正在播放的语音，宿主生成阶段
仍可能发生切页。变化检测仍是像素启发式，不保证识别每种小幅 UI 变化。

对外配队入口改为 `runtime/team_overview.py` 的身份核对；尚未建立足够的
版本化机制分析能力时，返回不可分析，不把 Demo 资料缺失变成队伍缺陷。

`adapters/text_reader.py` 以不超过共享引擎缩放阈值的原始像素分块，重叠覆盖
全画面；有超时或局部失败时明确报告覆盖不完整。文字块的局部放大重读只由
OCR 检出的几何位置触发，不依赖地图右侧、某个角色或玩家列举的页面。

`detectors/names.py` 先匹配完整数据库名称，再处理混合行内的等级、命途等字段。
注册名 `银狼LV.999` 不拆成 `银狼`；视觉链路不使用同音字或最接近名字猜测。
普通句子中的角色提及不提升为身份。读出的名字与具体人物的语义关联是下一层：

- `screen_label`：只确认界面显示该名字，不声称角色正在场景中或已拥有；
- 编队、详情、跃迁、剧情等另带证据范围；合并行不伪造各名字的独立像素坐标；
- 只有独立的选中位置视觉证据才能关联当前操控角色；目前仍未完成；
- 未分类的新页面仍可读出规范人名，不再被页面白名单全部过滤。

扩展检查范围包括背包装备穿戴者、图鉴、支援列表、试用和委托派遣等。
这些页面的规则测试不代表真实截图已验收；实际通过情况见 `TESTING_STATUS.md`。

## N.E.K.O. 投递

自动观察不再把 JPEG 作为聊天或视频上下文推送给 N.E.K.O.。稳定场景变化会生成简短
结构化消息；剧情、菜单、加载等一般状态默认静默同步，进入战斗、队伍准备、跃迁和
结算等事件才可以请求一句主动陪伴。主动回应仍受冷却、过期、合并和单次至多一个
事件的约束。

## 隐私与安全

- 后台感知必须由玩家在面板中开启；
- 停止观察会取消任务并关闭由插件启动的助手；
- 原始画面默认不写入文件、插件存储或 N.E.K.O. 对话；
- 回环客户端拒绝非本机地址；
- 下载器只接受插件 GitHub Release，校验 SHA-256，并拒绝路径穿越和符号链接；
- 助手异常只会令识别降级，不得影响 N.E.K.O. 本体或游戏客户端。

## 国服 4.6 攻略服务候选（2026-10-16，未安装）

统一入口仍为 `prepare_companion_reply`，不新增一个与观察系统竞争的聊天系统。
入口先用 `plan_guidance` 判断本次需求，再决定是否需要画面：

- 玩家已说清角色或高难模式：读取小型版本化攻略记录及外置实体资料，不等待截图、OCR 或视觉助手。
- 玩家问“这一关怎么打”或“身上这件要不要换”：保留原 `QueryPlan`、常驻工作者和字段验证链路；
  有可靠画面后仅补齐本次攻略目标，不把队伍头像当作账号拥有角色。
- `build_guidance` 将官方期次规则、带来源的攻略候选、玩家条件和缺失项分别返回。
  当前期次按国服开放时间选择，不按“游戏版本号相同”就混用全部活动。
- “没专武”“没有爻光”等追问使用最长十分钟的临时服务上下文；不写入永久玩家档案。
  新话题、暂停和停止会撤销上下文；已有补答请求携带对应攻略计划，仍受原先的期限、取消和一次提交限制。
- `guidance_answer` 不是当前画面事实，也不是最优解计算。旧角色查询、页面文字、任务地点、
  纠错、事件、观察状态、发言仲裁及外置资料组件继续保留。

数据分层：官方公告负责期次与规则；固定提交的 Fribbels 提供部分配装候选和参考模拟条件；
社区文章仅作为注明来源的少量节点事实及原创摘要。外置资料负责装备名称与效果，
不把整套数据库塞进插件。名称冲突的末日幻影社区攻略未纳入已核对节点。
目前混沌回忆和末日幻影仍缺完整逐关资料；不得用通用候选冒充针对该关的已验证方案。

## 数据与许可

### 2026-10-16 第一阶段：需求交接修订（未安装）

本轮保护已实现的功能，不固定旧链路结构；不新增模型、攻略内容或计算引擎。
`hsr_companion_prepare` 在原入口形成 `reply_demand`，分别记录观察要求和攻略要求。
`GuidancePlan` 标明对象来自玩家文本、对话线索、短期讨论、卡池日历或已验证画面，
来源不会升级为账号拥有或视觉确认。discussion_character 只帮助携带对话对象，不更改原问题。

未解析代词走主体证据读取；明确补姓名可继续待确认的培养问题。页面查询不清空或续期讨论，
非画面普通闲聊、停止/暂停清理讨论；讨论代次保护在途结果，防止清理后迟到写回。
过期追问返回待澄清，不随机选角色。新明确条件可以撤销旧排除或专武限制。

工具发现说明和常驻静默上下文包含一致的追问路由要求；它们是模型约束，不是宿主强制调用。
白名单 `service_request` 在内存记录入口 started/planned/completed/failed/cancelled、开始时间和代次，
与旧完成审计分开。诊断只读输出状态，不导出原问题、角色、路径或异常正文。
攻略资源无效独立降级，普通事实与知识入口不随之失败。装备可见名称证据不等于选中/穿戴关系。

知识组件、角色注册表和来源登记继续保留版本、固定提交和许可信息。第三方数据与助手
依赖见 `THIRD_PARTY_NOTICES.md` 和 `assistant_runtime/THIRD_PARTY_NOTICES.md`。

## 兼容性

0.9 沿用已有插件存储键，不主动清除玩家档案、纠错和经历。旧的手动截图入口继续作为
备用能力；0.8 的进程内窗口捕获仅作为独立助手不可用时的临时兼容路径。

2026-10-09 补丁改用公开 `PluginStore` 将本插件 KV 放在外部
`data-packs/hsr_companion/player-state/`，避免部分宿主将代码安装目录与默认数据目录
放在一起、重装时替换 KV。迁移仅补充缺失键，不覆盖既有外部档案；迁移标记不在
用户重置的业务键内，避免重置后重新灌入旧档案。配置刷新后的读取与写入均检查
本插件存储启用状态，不改宿主存储配置。全部 LLM 工具兼容运行入口附加的 `_ctx`，
不将上下文元数据当作玩家或视觉事实；已启用观察的玩家重启后查询会恢复观察任务，
无需先打开面板。

只问场景的查询使用独立的一次 1280 最长边 OCR，仍复用同一个工作者；不等四块
原生名字分析和头像匹配。返回前按实际检测到的场景控件区域核对最新帧，忽略
3D 世界的普通镜头运动，但控件变化或画面尺寸变化仍撤销结果。角色查询维持
完整覆盖和独立确认。重启首次查询等待新画面，不把过期缓存/初始等待当完成。

本地对照后可优先使用独立 PP-OCRv5 模型：检测/识别权重逐文件核验 SHA-256，
存放于外部 `model-comparison/v5`，不捆绑进插件。本插件用公开 RapidOCR API
识别正向 UI，显式限定自身引擎线程，并禁用方向分类，不修改宿主共享引擎。
模型未准备时回退既有宿主 OCR；此补丁尚未集成面向新用户的模型自动下载。
不是训练过的星铁专用模型，也不能证明 3D 身份。权重来源见第三方说明。

## 链路候选：状态保留与按需复用（2026-10-15，源码阶段）

本节是新候选实现，不表示已安装或常用页面实机验收通过。版本号暂仍为 0.9.5，
不覆盖已冻结的 r2 安装包、测试计划和失败记录。识别模型和本体均未更换。

```text
游戏窗口 → 独立助手 → 同一个 OCR 生产者
                         │
                         ▼
              当前结果 + 当前回答权限
                   │               │
             面板当前结果       查询 / 静默上下文 / 主动事件
                   │               │
        上次成功读取（单独标注）    最新区域检查 → 按需复用 / 等待生产者
                                   │
                           未完整：一次有期限的补答
```

- `ObservationStore` 保存当前已提交结果与一份显示用历史。短暂采集失败仅暂停当前回答权限，
  保留结果和区域校验依据；真实切页仍撤销当前资格、清理复用依据。历史不进入工具或主动发言。
- 同页标题预览不覆盖已有完整内容。不同范围的读取不随意拼接；旧内容只能经过最新像素验证后按需复用。
- 场景/导航复用之外，完整结果可复用文字或已受保护的角色区域：必须覆盖全部对外文字证据、
  满足区域数量限制、同一游戏进程和新鲜帧限制。证据不完整就回到原生产者，不补猜。
- 时间分为原始采集时间与本次验证时间；验证成功不伪造新的采集时间。复用绑定状态版本，
  验证期间提交了新结果则拒绝旧检查。面板历史标明读取时间，不伪装为当前识别。
- 采集客户端合并同时发生的读取传输；顺序读取不使用这份传输缓存，不延长帧有效期。
- 星琼、星轨专票、星轨通票和信用点分别检查已知/缺失，漏项不表示数量为零。
- 读取异常期间，只要观察仍开启且游戏未明确关闭/暂停，显式问题可保持一个有限补答请求；
  成功或到期只提交一次。SDK 提交成功仍不代表猫娘已显示或播放回复。

现有大 PNG 传输、两秒新鲜度门槛在实机上的成功率，以及常用页面真实文字覆盖，仍需独立核对；
本候选没有放宽门槛，也没有通过合成测试推断实机准确率。
