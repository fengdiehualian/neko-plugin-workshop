# 星铁游戏搭子 0.9.6

让 N.E.K.O. 的猫娘结合游戏画面、角色资料和玩家存档，陪你聊《崩坏：星穹铁道》的任务、养成和配队。

> [!WARNING]
> **0.9.6 是公开测试快照，不是稳定版。** 已在部分真实场景中完成识别和咨询，但连续切页、首次读取和补答仍可能失败或较慢。
> 请把建议作为参考，不把一次成功演示理解为所有页面、角色和玩法均已支持。

## 可以做什么

- **看任务**：依据已确认的探索画面，说明当前位置、任务或当前目标；缺少的内容会保留为未知。
- **聊养成**：结合当前面板和已收录的角色规则，给出培养重点、遗器主词条及光锥参考。
- **看眼前装备**：读取遗器、光锥详情，讨论它是否适合指定角色；也可以明确要求完整主副词条。
- **管理玩家资料**：通过 UID 查询公开角色展示，或手动选择角色、光锥、套装并填写面板。两种录入方式并列，手动修改不会被后续导入静默覆盖。
- **参考配队**：使用保存的角色资料，为已收录期次的普通混沌 12 层给出不重复占用角色的两队条件候选，并提示装备风险；不是最优解或通关保证。
- **后台观察与有限主动陪伴**：独立助手采集游戏窗口，插件静默更新已确认信息；主动搭话可单独关闭。

这些能力不是一次性全账号扫描，也不是战斗代打或伤害模拟器。

## 开始使用

1. 在支持该插件格式的 N.E.K.O. 中，通过插件管理安装对应版本的 `.neko-plugin` 包。
2. 打开插件面板，按面板提示准备游戏资料组件和独立视觉助手；桌面视觉助手面向 Windows x64。
3. 保持星铁运行，在面板开启陪玩／自动观察，分别确认助手的安装、运行与连接状态。
4. 直接和猫娘聊星铁。问眼前面板或装备时，打开对应详情；问保存的资料或通用配装时，不必为了提问切换游戏页面。
5. 如需基于自己的角色配队，先通过 UID 或手动录入建立玩家资料。UID 只能读取公开展示，不代表已导入全部账号角色。

本次 Release 分别提供插件包、0.9.3 视觉助手原包和下载清单，助手不要求与插件使用相同版本号。若组件下载不可用，请先查看该次 Release 的说明，不要把“插件已安装”当作“视觉组件已就绪”。

### 可以这样问

- “现在这个任务接下来要做什么？”
- “真珠这面板怎么样，接下来先养哪儿？”
- “她有专武了，遗器主词条怎么选？”
- “这件遗器给她用合适吗？”
- “完整报出这件遗器的主词条和四项副词条，再说说适不适合她。”
- “按我保存的角色，这期普通混沌 12 层怎么配两队？”

角色与期次需要在当前资料中有相应内容。没有收录或缺少条件时，不能据此给出确定结论。

## 当前需要了解的限制

| 情况 | 0.9.6 的边界 |
| --- | --- |
| 连续切换探索、角色和挑战页面 | 部分路径可完成，但稳定性尚未达标；可能首答缺读、补答较晚或到期仍未完成 |
| 遗器与光锥 | 可能缺项或无法核验；页面、名称已确认不代表词条已读全。完整请求未读全时应明确缺项，不能冒充完整 |
| 角色识别 | 主要依赖清晰名称、布局和已收录模板；不能保证识别任意 3D 外观，也不能把可见角色当成账号已拥有 |
| 游戏与攻略资料 | 使用带来源和版本的资料快照，不保证自动覆盖新版本、新角色或新一期挑战 |
| UID 查询 | 依赖 Enka.Network 的公开展示和服务可用性，可能受缓存或服务异常影响；手动录入仍可使用 |
| 猫娘回复 | 工具选参、事实转述、表达长度、补答重复和主动搭话时机仍可能出错；插件提交成功不等于玩家已收到正确回答 |
| 战斗场景 | 不承诺战斗中持续理解局势、识别敌我行动或即时给出战术建议；战斗对话专项能力不在本次新增范围 |

已知问题不因发布快照而视为修复。公开验证范围见 [测试状态](TESTING_STATUS.md)，本次冻结与分发边界见 [发布说明](docs/RELEASE_NOTES_v0.9.6.md)。

## 隐私与安全

- 插件和助手不修改、注入或操作游戏客户端，不读取游戏内存、不抓包、不模拟键鼠。
- 开启观察后只采集目标游戏窗口。切换到聊天可继续观察；最小化、关闭游戏或暂停观察时不能继续提供当前画面。
- 自动观察的原始帧默认只在内存中处理，不保存，也不作为自动视频输入发送给猫娘。结构化结果会进入 N.E.K.O.，后续模型处理遵循宿主配置。
- UID 查询只在玩家主动使用该入口时访问 Enka.Network；不需要账号密码或 Cookie。启用系统代理选项后，该查询会经过已配置代理。
- 玩家资料与游戏资料分开保存。玩家档案不等于 N.E.K.O. 的长期情感记忆。
- 关闭主动搭话不会关闭观察；已提交给宿主的消息不能保证撤回。

## 遇到问题

在面板运行“一键诊断”，完成后复制诊断结果，并附上问题发生时间、实际页面和猫娘的回复。
不必为了反馈反复刷新、重载或重复提问。

诊断主要记录状态、请求和计时，不是完整的原始识别回放；某些缺读仍需要单独取证。
报告中的“已连接”“页面已确认”或“服务请求完成”，均不单独证明装备读全或猫娘转述正确。
