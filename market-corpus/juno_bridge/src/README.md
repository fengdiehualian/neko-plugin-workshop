# 和猫娘一起开火箭（朱诺新起源）

让猫娘读懂你在《朱诺新起源 Juno: New Origins》（原名 SimpleRockets 2）里的飞行。

**这个插件是只读的** —— 它只读数据、只给建议，不会操作你的火箭。
不会替你点火、分级、改变姿态，操纵杆始终在你手里。

---

## 它能做什么

装好之后，你可以直接对着猫娘说话：

| 你说 | 她会做什么 |
| --- | --- |
| 「我现在飞到哪了」 | 读出飞船名称、飞行阶段、所在地天体、海拔、离地高度、各种速度、姿态、质量、级数、乘员 |
| 「我入轨了吗」 | 读轨道根数，明确告诉你近点够不够高、算不算稳定轨道，并报出这颗天体的大气层顶 |
| 「油还够吗」 | 列出燃料质量、本级燃料、电量、Delta-V、比冲、推重比、按当前油耗还能烧多久 |
| 「马赫数多少」 | 读出大气层内数据：马赫数、空气密度、气压、气温、音速、重力、阻力、攻角 |
| 「我锁定的是什么」 | 读出目标名称、类型、距离、相对速度（交会对接最有用） |
| 「星系里有哪些星球」 | 列出所有天体及半径、重力、是否有大气、大气高度、引力球范围 |
| 「场景里有哪些飞船」 | 列出场景里所有飞船的高度、质量、零件数、乘员 |
| 「这是啥游戏」 | 念一份中文说明书，讲清楚这游戏和 KSP 的区别、术语、以及常见任务的正确顺序 |

她还会**给出判断**，而不只是念数字。比如你说「我入轨了吗」，她会告诉你：

> 绕 Droo 的轨道：远点 152.34 km，近点 88.00 km，离心率 0.0531，倾角 28.61°，
> 周期 40分。近点（88.00 km）高过大气层顶（50.00 km），是稳定轨道。

如果近点还在大气层里，她会直说：

> 近点（30.00 km）低于大气层顶（50.00 km），还在大气层里，会被拖下来，这样入不了轨。

而不是干巴巴丢一堆字段给你。

## 安装

需要**两部分**配合：

### 1. 游戏模组（BepInEx 插件）

模组仓库：<https://github.com/LShangPiao/N.E.K.O-Juno-bridge>

从 [Releases](https://github.com/LShangPiao/N.E.K.O-Juno-bridge/releases)
下载 `NekoJunoBridge.dll`，放进

```
<你的游戏安装目录>/BepInEx/plugins/
```

然后重启游戏。

> **前置依赖：BepInEx 5.4.23.5（x64）**
> 模组就是针对这个版本编译、并在实机上跑通的。没装 BepInEx 的话模组不会被加载，
> `http://127.0.0.1:21577/ping` 也就不会有任何响应。
> 装的时候注意选 **x64**（Juno 是 64 位 Unity 游戏），x86 的 BepInEx 不会生效。

#### 为什么不用官方 `.sr2-mod`？

Juno: New Origins（原名 SimpleRockets 2）确实有官方 mod 体系，但它有**硬性工具链要求**：

- 官方 `.sr2-mod` 必须用 **Unity 编辑器 + 官方 ModTools** 把资源打成 **AssetBundle** 才能构建，
  它不是「丢一个 .dll 就能跑」的形式；
- 也就是说，做官方 mod 要求作者装一整套 Unity + ModTools，而且构建产物和 Unity 版本强绑定；
- 本项目要的只是一个**只读的本地 HTTP 遥测接口**，不需要往游戏里加零件、贴图或 Vizzy 积木，
  用 AssetBundle 那套流程纯粹是负担。

所以这里选择 **BepInEx 5.4.23.5（x64）插件**这条路：
用 Harmony 挂钩子在运行时读游戏内部数据，编译产物就是一个 DLL，构建和分发都简单得多。

> 模组是**公用**的：任何程序都能读它的 HTTP 接口，不依赖 N.E.K.O.。
> 接口只读，不会发任何控制指令。

### 2. 本插件

在 N.E.K.O 插件中心导入安装。

### 验证装好了

浏览器打开 <http://127.0.0.1:21577/ping>，
看到 `{"ok":true,...}` 就说明模组在正常工作。

## 配置

在 N.E.K.O 的插件设置里可以改（`[juno_bridge]` 段）：

- **bridge_url** —— 模组监听的地址，默认 `http://127.0.0.1:21577`
- **timeout_seconds** —— 请求超时（秒），范围 3-60，默认 12
- **auto_brief_enabled** —— 自动播报，默认开
- **auto_brief_interval_seconds** —— 自动播报间隔（秒），范围 5-300，默认 20

> 改端口要改**两处**：模组侧 BepInEx 配置里的端口，和这里的 `bridge_url`。
> 只改一处两边就连不上；模组侧改完需要重启游戏。

如果你的机器较慢、或者常在复杂场景里玩，可以把超时调大一些 ——
游戏在加载存档、切场景、进出编辑器、开高倍时间加速时会卡顿，读数据会慢一拍。

### 自动播报：为什么它不用你开口

以前是问答式：你问一句，猫娘才去调一次工具读遥测，中间那段时间她其实
**不知道**你在飞什么。现在换成自动播报 —— 只要游戏在跑，插件就在后台按
间隔读一次 `/state`，把最新的飞船状况写进她的上下文里。

具体做法是 `push_message(ai_behavior="read")`：消息会进模型的上下文，但
**不会打断对话、不会突然插话**；等你下次开口时，她已经知道你在哪个天体、
多高、多快、还有多少燃料，可以直接接话，而不是先调一遍工具。

几个细节：

- **同键合并**（`coalesce_key`）：队列里同一时刻只保留最新一条，所以调小
  间隔不会把上下文越堆越长，只会更勤快地刷新。
- **不在飞行场景就不说话**：主菜单、设计器、加载中读不到遥测，这条播报
  直接不发，不浪费上下文。
- **断了会说一声**：本来连着、游戏突然退出了，会播报一次「读不到新的遥测
  数据」，避免模型拿旧数据当现状。从来没连上过则完全静默。
- 想退回问答式就把 `auto_brief_enabled` 关掉。

## 模组接口（HTTP，全部 GET）

插件只是这些接口的消费者，你也可以自己写程序读它们。

| 接口 | 内容 |
| --- | --- |
| `/ping` | 存活检查：桥接版本、游戏版本、是否在飞行、端口 |
| `/state` | 一次性拿到全部数据（飞船 + 轨道 + 飞行 + 资源 + 目标 + 场景） |
| `/vessel` | 飞船基础与姿态 |
| `/orbit` | 轨道根数 |
| `/flight` | 速度 / 大气 / 受力 |
| `/resources` | 燃料 / 电量 / Delta-V |
| `/target` | 锁定目标 |
| `/bodies` | 天体数组 |
| `/vessels` | 场景里的所有飞船数组 |
| `/scene` | 场景与时间加速 |
| `/config` | 模组配置 |
| `/log?n=100` | 日志 |

## 数值单位（实机实测）

模组返回的原始数值，单位已经按实机数据核对过（飞船停在 Droo 的 Juno Village Pad）：

| 字段 | 单位 | 实测样例 |
| --- | --- | --- |
| 高度 / 离地高度 / 距离 / 半径 / 大气层高度 | **米** | `altitude_agl` 7.4445 m、`atmosphere_height` 78146.448 m |
| 速度（surface / orbital / vertical / delta_v） | **m/s** | `orbital_speed` 143.258 m/s |
| 角度（pitch / heading / 倾角 / 攻角 / 侧滑） | **度** | `heading` 248.6278° |
| 周期与时间 | **秒** | `period` |
| **气压 `air_pressure`** | **帕斯卡 Pa**（不是 kPa） | 71905 Pa @ 海拔 2779 m，与海平面约 101325 Pa 的指数衰减吻合 |
| **空气密度 `air_density`** | **kg/m³** | 0.86482 kg/m³ |
| **气温 `temperature`** | **开尔文 K**（不是摄氏度） | 279.65 K = 6.5 ℃ |
| 音速 `speed_of_sound` | m/s | 341.15 m/s |
| 马赫数 `mach` | 无量纲 | — |
| **电量 `battery`** | **0~1 归一化** | 0.9997057 ≈ 100% |
| **燃料余量 `fuel_all_stages_percent`** | **0~1 归一化** | 0 = 0% |
| **质量 `mass` / `current_mass` / `fuel_mass`** | **游戏内部单位，未标定** | 1 零件飞船 `mass` 0.0418 |

> ⚠️ **质量单位未标定，以游戏界面为准。** 实测 1 个零件的飞船 `mass` = 0.0418，
> 和游戏界面同量级的显示对不上（Juno 内部很可能按吨计）。
> 插件**不做 kg→t 换算，也不声称它是 kg 或 t**，摘要里只给原始数值并标注「游戏内部单位，未标定」。
>
> ⚠️ 气温是**开尔文**：279.65 K 是 6.5 ℃，插件摘要写成「6.5 ℃（279.6 K）」这种双标注，
> 就是为了防止把 279.6 念成摄氏度。

**不在飞行场景**时（主菜单、设计器、加载中），`/state`、`/vessel`、`/orbit`、
`/flight`、`/resources`、`/target`、`/scene` 会返回：

```json
{"ok": false, "in_flight": false, "error": "当前不在飞行场景（主菜单、设计器或加载中）"}
```

这时插件会把「读不到数据」如实告诉猫娘，**不会让她编数值**。

- `situation` 取值：`LANDED` / `SPLASHED` / `FLYING` / `SUB_ORBITAL` / `ORBITING` / `ESCAPING`

## 给用户的提示：关于模型能力

本插件把游戏知识写进了内置说明书（`read_juno_docs`），
所以**没玩过这款游戏的模型也能上手**。不过——

> **建议使用「工具调用能力较强」的模型。**
> 轻量模型可能出现「嘴上说去看了一眼，但实际没有调用工具」的情况。
> 如果你发现猫娘报的数字明显对不上，先看她有没有真的调用工具。

另外，模型不会替玩家做决定。**所有操作都要你自己在游戏里做**，
插件只能读数据、给判断、提建议。
