# 注意力重构设计草案：锁 + 连续归属

> 状态：**草案，未实现**
> 起因：多群环境下"看一眼新群、没兴趣就回来"这个人类行为，现有机制在结构上做不到。
> 前置数据：真实运行中 **53.3% 的群消息发生在同时有 2 个群活跃时**（实测，见 §1.3）。

---

## 1. 背景：为什么要改

### 1.1 现有设计的意图（正确的那部分）

现有 `attention_service` 用「标量分数 + rise/fall 相位机 + 焦点线」表达跨群注意力：

- `rise` → 兴趣在积累
- 到线夺冠 → 决定聊这个群
- 蜜月 60s → 正聊得上头
- `fall` → 聊够了 / 冷下来了，去看看别处

这个形状**映射人类注意力是准的**，而且相位是**刻意加进来防"冷群饿死"**的——
若只做"谁热闹关注谁"，不活跃的群会永久拿不到注意力。

**结论：相位机的意图要保留，不能简单换成"每群独立令牌桶"**（令牌桶会让热群恒热、冷群恒冷，恰好毁掉相位）。

### 1.2 现有设计做不到的那件事

> 用户原话："我看一眼这个新的焦点群，如果没有我感兴趣的话题我就会回到旧焦点。但是猫娘不会这样。"

对照人类与现状：

| 人的行为 | 现在猫娘的行为 |
|---|---|
| 看新群 → 发现没意思 → **几秒内**回旧群 | 夺冠 → **蜜月硬锁 60 秒** → 然后才 fall |
| 回旧群几乎零成本 | 回旧群要**从当前分数重新爬到焦点线**（可能几分钟） |

**这不是参数问题，是缺一个机制**：

- 现有系统能判断"这个群够不够格夺冠"（分数到线）
- 但系统里**没有任何东西**判断"夺冠之后这话题其实没意思，快撤"
- 情绪/兴趣都是从消息算出来的，而"我看了觉得无聊"这个反馈**没有入口**
  → **已补上入口**：`bored` 情绪（决策 B，见 §6 与 `SESSION-HANDOFF.md` §4.0c）

### 1.3 相位机目前还跑不完一轮

即便不谈"看一眼就回来"，现有相位也被三处堵住：

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| 1 | `attention_score` 被 `min(focus_threshold, …)` **封顶在焦点线** | `attention_service._advance_phase` | 夺冠即"刚好够线、零余量"，无法支撑"能一直聊很久" |
| 2 | 每次回复**强制** `phase="fall"` 并覆盖 `phase_started_at` | `update_on_reply`（**已修**） | 热群每回一句就被打入 240s/30s 回落 |
| 3 | 焦点可被挑战者**瞬间抢走**，无"刚切过来待一会儿"的闸 | `_choose_focus_state` | 抖动；旧群也可在让出后立刻反抢 |

> 第 2 条已在本轮工作中修复（删掉了强制 fall，改为只消耗分数、相位由时间线决定）。

### 1.4 实测数据（支持"多群竞争真实存在"）

```

群 985066274     7 条 / 跨越  76 分钟

53.3% 的群消息发生在「同时有 2 个群活跃」的时刻
单点最多同时活跃群数 = 2
```

样本来自单次会话（105 个有消息的时点），不是长期统计，但足以说明竞争是常态而非边缘情况。

## 2. 目标行为模型

用户给的模型（**本草案以此为准**）：

> 相位完全交给情绪、兴趣、发言频率；`@猫娘` 和唤醒词触发保持锁，让猫娘维持在一个群一段时间。

展开成两条并行的规则：

| 规则 | 触发 | 语义 | 人的对应 |
|---|---|---|---|
| **锁（lock）** | `@` / 唤醒词 | 硬性维持在某群一段时间 | "有人叫我，我必须回头应对" |
| **归属（focus）** | 无锁时持续计算 | 归属 = 注意力分数最高的群，**随时可变** | "没人叫我，我自己按兴趣决定看哪" |

### 2.1 关键洞察：去掉相位后，"看一眼就回来"变成免费的

因为没有相位就没有"必须走完的一轮"：

- 看一眼新群（它分数最高）→ 归属切过去
- 发现没意思 → 旧群分数回升 / 新群分数下降 → **下一个 tick 自动回旧群**

**不需要"fall→rise→重新爬线"**。用户观察到的那个行为是这套架构的**副产品**，不是额外要实现的机制。

这是本方案相比"优化相位机"的核心优势：**用更少的机制得到更多想要的行为**。

## 3. 状态模型

每个群一份：

```
attention_score   : float     连续注意力指针（情绪 + 兴趣 + 频率合成）
last_message_at   : int       最后一条消息时间（速率与兴趣的输入）
interest          : float     兴趣（见 §4.2，来源待定）
emotion           : str       情绪（沿用现有 set_emotion 枚举）
```

全局（插件级）：

```
locked_group      : str       当前被锁的群（空 = 无锁）
lock_until        : float     锁到期时刻
focus_group       : str       当前归属（连续计算得出）
prev_focus_group  : str       上一个归属（供"回旧焦点"用，见 §6 决策 A）
```

### 3.1 归属判定（优先级从高到低）

```
1. 若 now < lock_until 且 locked_group 有效  →  focus = locked_group
2. 否则                                        →  focus = argmax(attention_score)
3. 若最高分为 0（无任何群活跃）                →  focus = ""（全局休眠）
```

**规则 2 就是"看一眼就回来"**：不需要任何"回退"逻辑，归属每 tick 重算。

## 4. 分数量纲（当前最大的坑）

### 4.1 现有问题

`attention_score` 现在同时承载**三种不同量纲**的东西：

1. **预算**：回复消耗（`score *= 0.9`，乘性、与当前值耦合）
2. **时间线**：rise/fall 相位、蜜月、回落窗口
3. **活跃度**：每条消息 boost

三者挤在一个 0-10 的数里，还被拿去和**绝对阈值**比。后果：

- 乘性消耗让高分扣得多 → 热群"聊得越多掉得越快"
- 回血受相位衰减压制 → "回复后一蹶不振"
- 绝对阈值与漂移量纲不可比 → 焦点线卡死（同类错误在别处也出现过：BM25 用 IDF 量纲的分数比绝对常量，高频词查询整批清空）

### 4.2 建议：分数只表示"我多想聊这个群"

拆开之后，分数**只承载兴趣/注意力强度**，"回复太多该歇歇"交给独立机制：

```
attention_score(group) =
      w_emotion  * 情绪分量      (情绪枚举 → 系数)
    + w_interest * 兴趣分量      (见决策 B)
    + w_rate     * 发言频率分量  (该群自己的消息速率，NLU 归一化)
```

- **频率分量**必须跟着**该群自己的速率**归一，不能是全局绝对阈值 —— 这是"适应各自频率"的实现点
- **回复消耗**仍然保留，但改为**减性**（参考 MaiBot 的 `willing -= 1.8`），避免与当前值耦合
- **回血**独立成项（参考 `willing += 0.4`），不受衰减压制

> 参考：MaiBot 0.x 的 `willing` 是「每秒 ×0.9 衰减 + 回复 −1.8 + 不回复 +0.4」，每个参数有单位、可单独理解。

## 5. 与三家的对照（为什么这么设计）

| | 跨群仲裁 | 裁决方式 | 每群持久状态 |
|---|---|---|---|
| **KiraAI** | **无** | 唤醒词/提及 → 缓冲；未提及则概率 0.1 插话 | 无（affinity/mood/fatigue 全零） |
| **AstrBot** | **无** | 硬二值唤醒 **与** 恒定概率插话（互斥） | 无（概率恒定 i.i.d.） |
| **MaiBot 0.x** | **有**：全局档位配额上限表，超额停最不活跃 | 意愿值 → 概率 | willing / interest（内存）+ 关系值（Mongo） |
| **本插件（现状）** | **有**：焦点单选 + 相位机 + 情绪抢/让 | 9 步门控 + 相位门 + 概率 | 情绪 + 相位 + 疲劳 |

两点值得注意：

1. **两家成熟框架（KiraAI、AstrBot）完全不跨群仲裁**，各自独立。KiraAI 里 `attention` 一词只出现在 prompt 标题「## 注意事项（Attention）」，`affinity`/`fatigue`/`mood` 全仓计数为 0 —— **跨群注意力不是这些框架的既有做法**。
2. **本插件的跨群机制比三家都精细**（MaiBot 只做到"配额表 + 停最久不活跃"）。所以问题不是"做得不够好"，而是**这套复杂度没有先例、也没有被验证过**。

本草案的定位：**保留跨群意图（这是插件真正想要的东西），但把实现从"评分 + 阈值 + 相位"降到"锁 + 连续归属"** —— 机制更少，行为更贴近用户描述。

### 5.1 对现有代码注释的一处更正

`message_chain.py:1` 写 "mirrors KiraAI's recursive MessageChain structure"。

- **递归结构那半为真**：KiraAI 确实有 `Reply.chain` / `Forward.chains` 嵌套。
- **"每个元素 `.repr` 用于 LLM prompt 注入"那半不准确**：`.repr` 的 docstring 是 *"Returns a string to display in **logs**"*；真正的 prompt 输入是另一条路径 `MessageManager.message_format_to_text()`，**也递归但不用 repr**。

即：本插件把「日志表示」与「prompt 格式化器」合并了。工程上可行，但**文档记错了上游设计** —— 不要再用它推断 Kira 的行为。

## 6. 待决策项（**动手前必须定**）

### 决策 A：锁过期后回到哪？

- **(a) 回分数最高的群** —— 简单，但"刚才那个话题"可能已经被别人追上了
- **(b) 回上一个非锁群**（`prev_focus_group`）—— 更像人类"回到刚才那个话题"，但需要维护额外状态

> 用户描述偏 (b)："我会回到旧焦点"。

### 决策 B："没兴趣"的信号从哪来？

这是**能否实现"看一眼就回来"的关键**：

- **(a) 纯频率驱动** —— 群继续说话就是有兴趣。**但做不到"看一眼就回来"**：新群如果很热闹，频率会留住猫娘，即使话题无聊。
- **(b) 模型信号** —— 像现在的 `<feeling>` 情绪标签，增加一个"不感兴趣"的表达，让模型能主动快速让位。
- **(c) 两者结合** —— 频率为主，模型可标记"不感兴趣"来加速让位。

**倾向 (c)**：只有 (c) 能实现用户观察到的行为。(b) 的成本是 prompt 契约增加一项、(c) 还要定义"让位"的衰减速率。

> **已落地（见 §4.0c / `SESSION-HANDOFF.md`）**：按 (b) 实现 —— 复用情绪通道加 `bored`
> 情绪，`bored` 进 `_EMOTION_DROP_FOCUS`，分数压到焦点线并转 `fall`，下一个 tick
> `_choose_focus_state` 就把焦点交给别的活跃群。频率**不参与**让位判定：让位只有
> 模型说了算，避免"新群很热闹所以留住了"这个 (a) 的死结。
> 配套加了看门狗测试强制四份情绪名单一致。

### 决策 C：锁的时长与语义

| 子问题 | 候选 |
|---|---|
| `@` 锁多久 | 固定值？可配？还是"直到该群静默 N 秒"？ |
| 唤醒词锁多久 | 与 `@` 同长？还是更短（话题被提≠被召唤）？ |
| 锁内再来一次 `@` | 重置计时 / 叠加延长 / 不变 |
| 锁内其他群 | 完全静默 / 降权但仍可插话 |

### 决策 D：相位机怎么处置

- **(a) 删除** `phase` / `phase_started_at` / 蜜月 / `fall_seconds`，归属完全由分数算
- **(b) 保留 `fall` 只作"衰减方向"**，不再作为状态机

倾向 (a)：保留一半相位就会重新引入"必须走完一轮"的问题。

> ⚠️ **已由使用者否决，本节的倾向作废。** 使用者原话：
>
> > 注意力如果低了，可以切到其他活跃的群里看看，然后切回热闹的群。但是对于猫娘来说，
> > 这样会让猫娘忽略不怎么活跃的群，**所以补了相位**。
>
> 相位机是**刻意的防饿死设计**，不是历史包袱：纯 `argmax` 会让热群恒热、冷群永远拿不到
> 焦点。所以 (a) 不做，(b) 也不做 —— 相位保留原样。这一节留着是为了记住**为什么**不做，
> 否则下一个人读到"倾向 (a)"会照着做，把使用者要的东西拆掉。
>
> 相应地，§7 的步 4/5 也已作废（见下）。

### 决策 E：情绪与分数/锁的关系

现有情绪枚举含 `_EMOTION_FORCE_FOCUS`（`arguing`/`proud`）与 `_EMOTION_DROP_FOCUS`（`sulking`/`embarrassed`/`bored`）两组**硬编码集合**。

- 这两组是否直接映射成"锁"？（`arguing` 时自动锁住当前群？）
- 还是只作为分数分量？（`arguing` → 情绪分量高 → 自然留住）

### 尚未做、且**需要先有证据**的方向

「模型沉默时不让位」——早期怀疑为缺口，但**实测数据不支持**：

```
回溯补回（"看一眼这个群"的那一刻）：
    有未审核消息 → 交给模型挑    14 次
    模型真的回复了              14 次
    模型决定不回复               0 次
```

回溯补回是"看一眼"最接近的机制，而模型每次都在参与。所以**没有**加"连续拒绝就降权"
之类的机制 —— 那属于草案 §8.4 警告的"把能用的东西换成漂亮的"。

若要做，正确顺序是**先量化再动手**：给每个群记 `replies / declines`（`llm_skip` 目前
被设置后没有任何代码消费），观察真实拒绝率，再决定要不要让它影响注意力。
另需注意：静默**不能**直接当"没兴趣" —— 群聊的默认正确行为就是沉默
（"绝大多数消息不是对你说的"），按沉默降权会让猫娘放弃每一个群。

## 8. 未验证项与边界

1. **多群共现数据来自单次会话**（105 个时点），不是长期统计。长期是否仍以 2 群为主、是否出现 3+ 群竞争，**未验证**。
2. **MaiBot 1.0.0 的 `focus_*` / `attention_drift` 只有配置文档，无源码**，其行为语义未确认；本草案对 MaiBot 的引用以 0.x 源码级结论为准。
3. **"看一眼就回来"尚无量化目标**（多快算"快"？）。需在步 4 前定一个可断言的时延上限。
4. 本草案**未评估**改动对现有生产行为的影响。当前配置下注意力在真实群里是工作的（两个群都有落库的记忆事实），重构有"把能用的东西换成漂亮的"的风险。
