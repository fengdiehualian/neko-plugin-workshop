# 看视频猫娘

让猫娘**知道你正在看的 B站视频到底在讲什么**，而不是只会念标题。

## 解决什么问题

猫娘自带"看屏幕"能力（截图 + 窗口标题），但宿主喂给她的信息里，
关于视频的**只有窗口标题**。而浏览器标题长这样：

```
机械迷城_哔哩哔哩_bilibili
```

所以她只能说出「哇你在看《机械迷城》啊，这个好看吗？」——不是她不会聊，
是她**手上真的只有标题**。

本插件补上"内容"这一层：

```
检测到 B站视频页 → 读窗口标题 → 反查 BV 号
  → 拉取 标题 / 简介 / 弹幕(带时间戳) / 高赞评论
  → 本地算出"观众在哪一秒集中吐槽/发笑"
  → 把这些事实喂给猫娘
  → 她用自己的语气吐槽，终于对得上内容
```

## 效果示例

插件推给她的事实（约 400 字，不是弹幕全文）：

```
《《机械迷城2》公布》（UP主 A9VG，时长 1:05）
简介：官方《机械迷城2》公布，发售日待定。在逃离机械迷城后，约瑟夫和伯塔……
观众反应高峰：0:00 惊点×7（"卧槽"）；0:05 吐槽点×7；0:25 吐槽点×1
高赞评论："果然活着还是有好处的"（赞31）；"蘑菇社总算重启最好的项目"（赞32）
```

她拿到这些，就能聊到点子上，而不是复读标题。

## 设计红线：插件不写一句台词

插件**只提供事实**（标题、简介、弹幕节奏、热评），台词全部由猫娘自己生成。

原因：猫娘用户的人设五花八门，有温柔系也有毒舌系。插件如果内置台词库，
毒舌台词落到温柔人设用户手里就是 OOC。所以插件做"情报"，她做"表达"。

同理，插件推给她的内容明确标注为**不可信数据**，她不会去执行弹幕/评论里的指令。

## 为什么能"人人下载即用"

| 条件 | 做法 |
|------|------|
| 零第三方依赖 | 只用标准库：`ctypes`（读窗口标题）、`subprocess`+PowerShell（读媒体会话）、`urllib`、`zlib`、`xml`。`dependencies = []`，无需 `vendor/` |
| 零登录 | B站搜索/视频/弹幕/评论接口实测无需 cookie 即可用 |
| 零权限 | 普通进程即可读窗口标题、读媒体会话，不需要管理员 |
| 任何浏览器通用 | 窗口标题 + 系统媒体会话都是 OS 层，不挑浏览器（Chrome / Edge / 联想 / 360 / QQ 都行） |
| 不需要装扩展 | 不是浏览器扩展，是一个普通 N.E.K.O 插件 |

## 工作方式

每 5 秒检查一次窗口标题（轻量，纯本地）：

1. 前台窗口是 B站视频页？不是就跳过（可选只在 B站处于前台时识别）
2. 直播间页面（"… - 哔哩哔哩直播，…"）直接跳过——直播没有 BV/弹幕/字幕
3. 用窗口标题反查 BV 号（见下）
4. 拉弹幕 + 评论，算节奏图，生成摘要
5. `push_message(ai_behavior=respond)` 让她就着这些事实开口

### 播放位置：读系统媒体会话（v0.4.0 新增）

"视频播到第几秒"直接读 **Windows 媒体会话（SMTC）**——浏览器会把它上报给系统：

- 真实播放位置、**倍速**、播放/暂停状态、总长（联想浏览器 + B站实测可读）
- 开倍速、拖进度条都能立刻跟上（浏览器在媒体事件点上报，插件按倍速外推）
- 也顺便提供**更可靠的标题**：系统报的是"正在播放"那个，不受前台标签页干扰
- 读不到时自动退回"按墙钟计时"估算，功能不受影响
- 实现是一个常驻 PowerShell 子进程（Windows 自带），**依然零 pip 依赖**

### 反查 BV 号的三个坑（都实测踩过）

1. **不能取搜索结果第一条**：搜"机械迷城"第一条是 77 分钟全流程，
   用户可能在刷 35 秒短视频。→ 按标题相似度挑最像的。
2. **默认"相关性"排序会把精确视频挤出去**：搜完整标题，默认排序 20 条里
   没有那个视频；但 `order=pubdate`（按发布时间）第 1 条就是它。
   → 优先 `pubdate`，其次 `click`，最后才回退默认。
3. **省略号/书名号会毁掉搜索**：`我记录下了妹妹的最后7天...【自制伪纪录片电影】`
   直接搜一条都搜不到，砍掉省略号后的部分才能命中。
   → 多级回退查询。

## 防污染

黑夜君临的教训是"同一份内容被反复推送刷爆上下文"。本插件做了三层防护：

- **高光点硬去重**：同一个峰值只说一次（存在 `data/pushed.json`，重启不丢）
- **开口间隔下限**：两次推送至少隔 `min_gap_seconds`（默认 18 秒）
- **摘要短**：目标 400 字以内，绝不塞弹幕全文

## 配置（`plugin.toml` 的 `[video]` 节）

| 字段 | 默认 | 含义 |
|------|------|------|
| `enabled` | `true` | 总开关 |
| `mode` | `"respond"` | `respond`=直接触发她针对视频说一句（实测唯一有效的方式）；`read`=只塞进上下文（对她的主动聊天无效） |
| `min_gap_seconds` | `18.0` | 两次开口的最小间隔（别把上一句话吞了；不是"多久说一次"） |
| `hotspot_grace_seconds` | `90.0` | 高光点过期窗口（拖进度条跳过的不回头补报） |
| `max_hotspots` | `5` | 最多取几个"观众反应高峰" |
| `comment_on_end` | `true` | 播完后读高赞评论做收尾 |
| `max_comments` | `3` | 摘要里最多几条高赞评论 |
| `max_danmaku` | `600` | 最多拉多少条弹幕算节奏图 |
| `only_when_foreground` | `false` | 只在 B站窗口处于前台时才识别 |
| `manual_bvid` | `""` | 兜底：手动指定 BV 号（留空=自动检测） |
| `show_facts_in_chat` | `false` | 是否把原始事实作为插件气泡显示在聊天窗（调试用） |
| `use_media_session` | `true` | 读系统媒体会话拿真实播放位置/倍速；读不到自动退回墙钟估算 |

## 插件入口

| 入口 | 作用 |
|------|------|
| `video_status` | 查看插件状态、已识别过哪些视频 |
| `check_now` | 立刻检测当前窗口并推送（调试用） |
| `set_bvid` | 手动指定 BV 号，让猫娘了解某个视频（兜底） |

## 已知限制

- **只支持 B站**：其他网站没有弹幕这种结构化数据，且拿不到 BV 号。
- **标题反查依赖 B站搜索**：如果视频标题太新、太冷门，或搜索结果被限流，
  可能当次匹配不到。插件会在后续轮询中自动重试。
- **直播页不支持**：直播间没有 BV/弹幕/字幕，交给专门的直播插件。
- **弹幕/评论稀少时**：退化为"标题 + 简介 + 分区"，至少她知道这是什么类型的视频。
- **仅 Windows**：读窗口标题依赖 Win32 API（N.E.K.O 本身是 Windows 应用）。
