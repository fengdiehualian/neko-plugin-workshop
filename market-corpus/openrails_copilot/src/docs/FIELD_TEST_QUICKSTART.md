# 实战验证与调优 - 快速启动

## 🚀 立即开始

### 1. 安装依赖（如果还没有）
```bash
pip install httpx
```

### 2. 启动 Open Rails 游戏
- 确保游戏正在运行
- 确保 REST API 已启用（默认端口 2150）
- 开始一段正常的驾驶行程

### 3. 运行验证工具
```bash
# 标准验证（30分钟）
python plugin/plugins/openrails_copilot/field_test.py

# 或指定时长（比如 1 小时）
python plugin/plugins/openrails_copilot/field_test.py --duration 3600

# 按 Ctrl+C 可随时停止
```

### 4. 查看报告
```bash
# 查看可读报告
cat field_test_summary.md

# 或在编辑器中打开
code field_test_summary.md
```

### 生成的报告包含

1. **告警统计**
   - 候选告警总数（包括被过滤的）
   - 实际播报数
   - 过滤率

2. **事件分布表**
   - 每个事件触发了多少次
   - 被播报了多少次
   - 播报率

3. **场景分布**
   - 干线行车、停站、调车各占多少时间

4. **自动调优建议**
   - 过滤率过高/过低的警告
   - 频繁触发的事件
   - 建议调整的参数

## 🔧 根据报告调优

### 如果报告显示"过滤率过高 (>80%)"

**意思**：大量候选被过滤，可能太保守了，关键告警可能被压制。

**行动**：
1. 打开 `plugin/plugins/openrails_copilot/core/arbiter.py`
2. 减少冷却时间：
   ```python
   # 在 event_catalog.py 中找到对应事件
   EventSpec(
       event_id="OVERSPEED",
       cooldown_s=20.0,  # 从 30.0 改为 20.0
   )
   ```
3. 或缩短全局冷却：
   ```python
   # 在 arbiter.py 中
   self._global_cooldown_s = 10.0  # 从 12.0 改为 10.0
   ```

---

### 如果报告显示"过滤率过低 (<30%)"

**意思**：几乎所有候选都播报了，可能太吵了。

**行动**：
1. 打开 `plugin/plugins/openrails_copilot/core/constants.py`
2. 收紧阈值：
   ```python
   OVERSPEED_THRESHOLD_KMH = 8.0  # 从 5.0 改为 8.0
   ```
3. 或延长冷却时间：
   ```python
   # 在 event_catalog.py 中
   EventSpec(
       event_id="OVERSPEED",
       cooldown_s=30.0,  # 从 20.0 改为 30.0
   )
   ```

---

### 如果某个事件触发频率过高

**示例报告**：
```
⚠️ `OVERSPEED` 触发频率过高 (450/900 周期)：检查阈值是否合理。
```

**意思**：一半的时间都在超速，可能是阈值太严格了。

**行动**：
1. 打开 `plugin/plugins/openrails_copilot/core/constants.py`
2. 放宽阈值：
   ```python
   OVERSPEED_THRESHOLD_KMH = 10.0  # 从 5.0 改为 10.0
   ```

## 📋 检查清单

验证完成后，确认以下指标：

- [ ] **播报率在 30%-70% 之间**
  - 太高（>80%）= 刷屏
  - 太低（<20%）= 过度静默

- [ ] **没有明显误报**
  - 在报告的"实际播报记录"中，每条都应该是合理的
  - 如果有不合理的，记录下来，调整阈值

- [ ] **没有明显漏报**
  - 回忆驾驶过程中，是否有应该告警但没有的情况
  - 如果有，检查对应事件是否被场景门控静默了

- [ ] **场景分类准确**
  - 停站时确实是 `station_idle`
  - 调车时确实是 `shunting`
  - 正常行驶时是 `mainline`

- [ ] **断路器未误跳闸**
  - 报告中搜索 `"circuit_open"`，应该为空
  - 如果有，说明推送通道失败次数过多

## 💡 推荐的验证场景

### 场景 1：完整行程（最佳）
- **时长**：30-60 分钟
- **内容**：从始发站到终点站，包含加速、巡航、减速、停站
- **目的**：覆盖所有典型操作

### 场景 2：压力测试
- **时长**：10-15 分钟
- **内容**：故意超速、急刹车、冲进信号、在坡道上溜车
- **目的**：测试告警是否灵敏

### 场景 3：静默测试
- **时长**：10-15 分钟
- **内容**：完全按规矩驾驶，不违规
- **目的**：确保无误报

---

## 🎯 目标配置

验证调优完成后，理想状态：

1. **正常驾驶时安静** - 30 分钟行程中，告警 ≤ 3 次
2. **违规时立即提醒** - 超速/冲信号/急刹车时，2-4 秒内播报
3. **不重复刷屏** - 同一问题不会短时间内重复播报
4. **场景感知准确** - 停站时不会误报"制动未缓解"
