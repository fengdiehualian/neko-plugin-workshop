## 替换时改哪里

| 变化 | 修改位置 | 与玩法的关系 |
| --- | --- | --- |
| 同样三表情，仅精修外观 | 替换 PNG；图集布局相同可沿用 JSON | 不改物理和对战规则 |
| 图集排列、每帧尺寸改变 | JSON 中的 `image`、`frames` 裁切坐标 | 不改伤害、技能和回合 |
| 游戏中大小、手部落点改变 | JSON 中的 `drawBox`、`pixelGrid`；必要时调整绘制锚点 | 不随图片尺寸自动改变碰撞范围 |
| 改成斜俯视或多朝向 | 补充对应图片，调整 `static/art.js` 与 `static/game.js` 的选帧、锚点和前后遮挡 | 渲染工作会增加；物理和对战规则仍可沿用 |
| 改画泳圈本身 | 当前由 `art.js` 的 `floatImage` 生成、`game.js` 分层绘制；未来可改成独立泳圈图片 | 圆形碰撞继续由物理层管理 |

角色图与泳圈目前分层，角色 PNG 不包含泳圈。将来若提供整张带泳圈的合成图，必须调整渲染分层，不能直接覆盖角色 PNG 后重复绘制两个泳圈。

物理半径以 `static/physics.js` 的 `RADIUS` 为准，目前是 40。JSON 中的 `collisionRadius` 用于资源一致性核对，不会驱动物理。仅换美术时保持物理半径不变，围绕它对齐泳圈外缘，避免图片变大就改变路线和手感。

## 交付与核对

替换资源时保留三种表情和稳定的手部基线；保留透明背景和像素边缘。核对普通显示尺寸、碰撞圆、受撞切帧、头部点击和小屏幕表现。图片加载失败时仍应可用占位泳圈继续游玩。
