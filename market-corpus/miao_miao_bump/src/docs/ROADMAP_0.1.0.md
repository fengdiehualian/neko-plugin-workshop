# 喵喵碰碰大作战 · 0.1.0 完整规划

更新日期：2026-10-21。本文整合已确定的玩法、角色、界面、地图扩展与淘汰动画，作为 0.1.0 的主规划。

**版本目标：做出一款可以完整游玩的本机三对三猫娘泳圈对战。** 调整角度和力度，借队友、池壁和技能连续碰撞；双方轮流出手，击退得分，先达到目标分数的一方获胜。

当前版本为 **0.1.0（本地发行准备）**。基础对战、地图配置、每轮限制、积分复归和基础飞出已接入；当前界面为顶部猫头记分牌、左角色信息、右操作，新猫猫与水面第二稿已实装。2026-10-21 本机完整对局验收后，用户确认玩起来没有问题，授权准备正式版本并审核 README。GitHub Release 尚未发布，见 [发布准备](RELEASE_0.1.0.md) 与 [试玩记录](ACCEPTANCE_DEV9.md)。下文旧底栏描述以当前两侧布局为准。

## 1. 核心体验

把猫猫弹出去，看她撞上对手、带动队友、借池壁反弹，再撞回来。换一个角度、力度或擦边位置，就能出现不同的路线。

玩家既能认真算角度，也能享受意料之外的连撞。技能、攻防和胜负为弹射提供目标；水阻让运动自然收尾，让人开始想下一发怎么弹。即使在无伤害的练习模式里，单纯发射和碰撞也应该有趣。

## 3. 交付范围

- 可在 N.E.K.O 中打开的独立游戏插件，默认玩家对本机电脑。
- 双方各三只猫：橘子、布丁、奶盖；每人有攻击、血量和一个自动技能。
- 一张夏日像素水池，预留不同地图的接入位置。
- 拖拽瞄准、松手发射、取消、连续碰撞、水阻与自然停稳。
- 每猫每轮一次主动出手，双方轮流行动、换轮、交换先手。
- 击退得分、飞出淘汰、下一轮复归、目标分胜负与重开。
- 已选①界面、像素反馈、本机音效开关、八种语言。
- 保留独立自由练习和调参，以及使用说明、验证记录和可安装插件包。

核心游玩不依赖账号、模型调用、外部网络或 CDN。

## 4. 操作与瞄准

1. 我方可行动且全场停稳时，按住一只可出手的己方猫娘或泳圈。
2. 向后拖拽调整方向和力度，发射方向与拖拽相反。
3. 松手发射；轻点或拖拽距离过小只选中，不消耗出手机会。
4. Esc、右键、触摸取消或失去指针时取消瞄准，不消耗机会。
5. 等当前运动和淘汰表现结束后，再进入下一次行动。

鼠标与基础触摸共用逻辑。敌方、已行动、已淘汰角色不能被主动发射；查看技能不消耗机会。点击可见头部或泳圈均应准确。

辅助线考虑泳圈半径，提示初始方向与首次接触。首先碰到猫时预览停在接触处；先碰池壁时提示第一次反射方向。不预演完整连锁或精确伤害，不显示独立力度条／力度数值。

## 5. 行动、轮次与先手

### 名称约定

- **一次行动／出手**：发射一只猫，直到全场停稳且淘汰表现完成。
- **一轮**：双方用完本轮所有可用主动机会。
- **一局**：从开局到任一方达到目标分数。

### 出手限制

- 每只猫每轮一次主动出手机会，成功发射即消耗，顶部头像保持彩色并加勾。
- 对手行动后，下一次我方出手必须选本轮未行动的猫。
- 已行动的存活猫保持彩色留在水中，照常传递运动、参与本方碰撞伤害及触发适用被动。
- 被队友或对手撞动不消耗主动机会。
- 双方交替行动；一方无可行动角色时跳过，由另一方完成剩余机会。
- 被淘汰角色本轮未使用的机会作废，不顺延、不转给队友。
- 0.1.0 的三个技能不赠送额外行动，暂不加入额外行动系统。

### 换轮与先手

双方均无可行动角色，且运动和淘汰表现结束后进入下一轮。存活者保留位置、剩余血量；待复归者按第 7 节返回。在场角色获得新一轮的一次主动机会，头像恢复彩色。

第一轮由玩家先手；以后每轮交换先手：第一轮我方、第二轮电脑、第三轮我方。换轮不重置存活猫的位置，不自动回满她们的血量。

示例：我方橘子出手 → 对方出手 → 我方只能选布丁或奶盖 → 双方机会用完 → 下一轮电脑先手，我方橘子重新可用。

## 6. 碰撞与伤害

**当前行动方的任意存活猫与敌方发生新接触，敌方受到该行动方猫娘自身攻击力对应的伤害。** 不要求她正在移动，也不要求她是本次发射的角色。

- 我方行动时，敌人撞到静止或已行动的我方猫，同样受伤；电脑行动时反过来。
- 同阵营不互伤，正常传递运动；普通敌我碰撞不会双方同时扣血。
- 普通撞墙不扣血，本版不增加伤害机关。
- 伤害无速度门槛，低速的新接触也有效。
- 基础伤害取攻击猫的攻击力，再应用减伤；力度影响运动与碰撞机会，不直接放大伤害。
- 同一对猫持续贴靠只结算一次，分离后重新接触才能再伤害。不设置妨碍快速连撞的时间冷却。
- 小幅空间容差用于过滤接触抖动；换边不会重算仍贴住的旧接触。

水花、音量与泳圈挤压可随撞击强弱变化，与是否扣血分开处理。

## 7. 击退、复归与胜负

### 击退与计分

HP 首次归零即被击退，立即失去攻击、被动、选择与场内碰撞能力，对方获得 1 分。同一条生命只计分一次，随后播放飞出动画；飞行本身不能再伤人、挡路或产生额外分数。

这会调整 dev8“败退身体保留到全场停稳”的旧行为。须在安全物理步边界清理身体和接触记录，不能把可见角色画走却留下隐形挡板。

### 下一轮复归

- 被击退的猫本轮不再返回；下一轮满血复归，恢复被动和新一轮的一次机会。
- 优先使用当前地图为该角色定义的己方出生点。
- 出生点被占用时，在己方出生区域寻找最近合法位置，不能重叠或推开存活者。
- 无合法位置则暂待复归，在后续行动结算后重试；待复归者不计入本轮待行动名额。
- 复归给出简短落水水纹／位置提示；不因动画结束提前复活、不额外计分。
- 存活猫保持已有位置与剩余血量，保留上一轮的站位价值。

### 怎么赢、怎么输

暂用 **先得 5 分**作为试玩规则。我方先达到目标分获胜，电脑先达到目标分则失败。目标分作为可调对局配置，不写死在地图或记分牌图片中。

一发击退两只得 2 分。达到目标后完成当前这发的运动和淘汰表现再显示结果，不中途弹窗截断连撞。整队暂时离场不单独判负，胜负以积分为准。

0.1.0 暂不增加倒计时判负或轮数上限，先试玩确认节奏。结果能看清胜负与比分，并直接再开一局。

## 8. 角色与技能

双方使用相同阵容，每人先有一个自动生效的专属技能，不增加主动技能按钮、能量或冷却系统。

| 角色 | 原型猫与识别特征 | 血量 | 攻击 | 技能与体验 |
| --- | --- | ---: | ---: | --- |
| 橘子 | 中华田园橘猫；橘色短发、琥珀眼、花叶配饰、头顶小橘猫 | 120 | 24 | 沉甸甸：质量 1.6，更难被推走；同力度保持相同初始动能，起步稍慢 |
| 布丁 | 海豹重点色暹罗猫；奶油／深棕配色、蓝眼、布丁配饰、头顶小暹罗 | 85 | 18 | 超弹泳圈：撞墙保留更多速度，池壁弹性暂为 0.97，普通为 0.90 |
| 奶盖 | 蓝双色布偶猫；奶白长发、灰蓝耳尖、蓝眼、淡紫配饰、头顶小布偶 | 100 | 20 | 软垫护护：每次敌方出手中首次新接触受击减伤 8，随后正常扣血 |

这是现有初始数值，需在积分复归规则下重新试玩。奶盖的减伤按敌方每次出手重置，不是整轮一次；复归不保留上一条生命的消耗状态。

悠怡是独立角色。三位新角色借鉴其可爱的大头短身表现语言，各自拥有原型猫、配色和配饰。

## 9. 物理手感与练习

沿用圆形刚体、固定物理步长与持续水阻。当前逻辑画面 960 × 600，泳圈半径 40；仅换图片不改变碰撞半径。

| 情况 | 调试目标 |
| --- | --- |
| 小力度 | 轻推近处角色、调整站位 |
| 中力度 | 命中后仍有余力，能看清运动传递 |
| 大力度 | 合适参考路线下争取约 3～5 次明显碰撞，含撞猫和撞墙 |
| 结束 | 明显减速后自然停稳，不突兀刹住，也不长时间爬行抖动 |
| 一次典型出手 | 约 4～7 秒作为调试目标，不是所有路线的硬限制 |

不硬限最多碰撞次数，不靠定时强停制造正常手感。异常保护负责恢复故障并提示，不把模拟错误判成正常胜负。

自由练习保留单圈撞墙、两圈对撞、三圈连撞、墙角拥挤固定布局，以及水阻、弹性、最大发射速度、所选质量和恢复默认。练习不启用伤害、积分和被动；调参不带入对战，运动中不能修改参数。

## 10. 界面：采用概念图①

![已选顶部记分牌界面](art/battle-ui-scoreboard-concept.png)

图片确定信息布局和风格，不要求照搬全部装饰或拉伸地图。以合适的水池大小、角色清晰和首屏完整为准。

### 顶部记分牌

双方各三个猫娘头像，配队伍标识和比分；中间显示轮次、当前行动方与目标分数。

| 状态 | 头像表现 |
| --- | --- |
| 本轮可出手 | 彩色 |
| 当前选中 | 清楚的亮边框／选择标记 |
| 本轮已行动 | 彩色加勾 |
| 已淘汰／待复归 | 独立叉号／复归提示，与已行动区分 |

头像保持彩色加勾仅表示主动机会用完，场内存活角色仍为彩色。敌我不能只依赖色差，同时使用形状／文字标记。

### 水池与底栏

先留出顶部和底栏高度，再按剩余宽高等比显示完整水池。水池不遮头像、不挤掉底栏，不要求用户下滑。水纹和装饰不过度干扰血条、角色和瞄准线。

底栏显示选中角色、当前／最大血量、攻击与被动；保留拖拽提示、声音、设置和重开。技能、表情与调参按需弹出，长内容只在弹窗内滚动。

**不恢复明显碰撞、本次用时、当前速度、发射力度四项可见统计。** 内部事件和计时仍可用于规则与验证。

## 11. 飞出淘汰动画

采用二维效果，现有角色图片即可实现，不等新精灵表或三维模型。

**HP 归零 → 受撞表情与水花 → 猫娘和泳圈沿致命撞击方向腾空 → 越过池沿 → 轻微翻转、缩小淡出。** 头顶小猫先随主体整体运动。

- 暂以约 0.6～0.8 秒调试，这是我们的目标值，不是原作测量值。
- 用离水弧线、影子与水花表现被打飞，保持清楚的像素边缘。
- 多只淘汰并行播放，不逐只打断其余猫的连撞。
- 表现与逻辑分离：淘汰及计分先完成，动画回调不负责加分或复活。
- 独立表现层可跨越池沿，不遮顶部和底栏；按地图范围计算终点。
- 减少动态效果时使用短距离、无旋转离场，仍给出明确淘汰提示。
- 隐藏页面随游戏暂停；重开、换图、销毁清理旧效果；结果弹窗等待最后的淘汰表现完成。

接入评估与细节见 [dev9 整合计划](DEV9_PLAN.md)。

## 12. 多地图预留

0.1.0 交付一张夏日水池，实现不能永久绑定这张地图。

| 独立部分 | 配置职责 |
| --- | --- |
| 身份 | 稳定地图标识、国际化名称 |
| 美术 | 图片、像素网格、池沿切片、水纹与渲染元数据 |
| 场地 | 逻辑尺寸、可玩边界、声明式碰撞体 |
| 出生与复归 | 双方各三只猫的位置、合法复归区域 |
| 扩展位置 | 障碍物与地图机制配置；本版保持矩形池壁、空机制 |

公共头像、比分、轮次和底栏不画入地图图片。物理、瞄准、电脑、绘制、出生和淘汰表现共用场地配置，不各自写死边界。

同类新地图以后主要通过资源与配置接入；新机关仍须实现，不承诺换图即可支持任意玩法。通过第二份开发测试配置验证接口，本版不额外制作第二张正式地图。

地图在开局设置中选择，不在对局中直接热换；重开保留选择。先验证配置再建立场地，未知地图回退默认并提示。仅美术失效时按所选有效场地程序绘制，不能混用另一张地图的边界。详细接口见 [界面与地图规划](UI_MAP_PLAN.md)。

## 13. 美术与声音

保留夏日水池、泳圈、猫娘和头顶小猫，使用统一像素网格与整块放大，不因界面升级丢掉像素感。

当前待机、受撞、回弹三表情继续使用；正面视角、浮水姿态、尾巴和完整动作后续精修，不作为玩法发布门槛。换同规格图片不改战斗规则；图集、朝向或锚点变化由渲染配置处理，图片大小不驱动碰撞范围。见 [美术替换约定](art/ASSET_REPLACEMENT.md)。

音效先用本机合成的发射、碰撞、减伤、淘汰和结果提示，提供开关。音乐、配音与外部音频不作为本版条件，实际听感与响度需人工试玩。

## 14. 电脑、暂停与重开

- 电脑与玩家遵守相同的行动、伤害、积分和复归规则。
- 本机比较有限直射、借墙路线和力度，优先命中及收掉残血；不读取未提交的瞄准输入，不调用模型。
- 自动能打完只证明流程可用，难度与准确度仍需试玩。
- 页面隐藏暂停物理、动画和电脑等待，回来不补算隐藏期间的大段运动。
- 设置／角色弹窗阻止新的玩家和电脑出手；已经开始的行动按统一暂停策略处理。
- 重开清除比分、轮次、机会、血量、淘汰／复归、接触、拖拽、音画反馈与旧电脑等待；保留模式、地图和声音选择。
- 页面关闭清理循环、事件与声音，重新打开不重复运行。

## 17. 0.1.0 发布验收

### 玩法与规则

- [ ] 选择、拖拽、取消、发射和下一次行动顺畅。
- [ ] 每猫每轮一次主动出手，被撞动不消耗机会；已行动者仍能参与本方伤害。
- [ ] 轮次结束、阵营跳过和先手交换一致，电脑无额外权限。
- [ ] 伤害归属、减伤、持续接触过滤和分离再撞正确。
- [ ] 淘汰立即退出场内碰撞，每条生命只计分一次。
- [ ] 复归位置合法、状态正确，存活者位置和血量不被重置。
- [ ] 达到目标分后看完最终碰撞与动画，正常结算并重开。

### 手感与表现

- [ ] 力度区别清楚，参考路线能连续弹几次并自然停稳。
- [ ] 高速、拥挤、墙角和即时移除后无穿透、抖动或异常加速。
- [ ] 现有效果不阻断连撞、复归和最后一击结算，不残留隐形身体；击飞可读性与完整入水动作按最新决定留下一版本。
- [ ] 角色、泳圈、血条和敌我标识可辨认，像素边缘清楚。
- [ ] 猫头、轮次、行动方与比分对应真实状态。
- [ ] 桌面与常用小屏尺寸下整屏完整，基础触摸可用。
- [ ] 不出现已移除的四项统计，设置在下方按需展开。
- [ ] 实际试玩确认三种技能有区别，电脑难度与一局节奏合适。

### 生命周期与交付

- [ ] 重开、切换练习、暂停恢复、关闭重开不残留旧行动或动画。
- [ ] 地图测试配置、缺失资源和无效配置不混用画面／物理数据。
- [ ] 八种语言可用，较长文案不遮挡主要操作。
- [ ] 原练习模式与已确认基础碰撞无明显回退。
- [ ] 插件严格检查、相关自动验证与构建包检查通过，记录实际结果。
- [ ] 安装打开方式、技能、对战规则、素材说明和已知限制已更新。
- [ ] 记录浏览器／设备覆盖，不把未测环境宣称为已通过。
- [ ] 用户完成整局试玩、确认无阻断发布问题，再制作正式标签与发行包。
