# 直播助手 v0.3.3

本版本修复连续弹幕丢失主语、直播互动场景提示不足、把观众昵称当成发言，以及进场欢迎提前结束开场暖场的问题，并包含 v0.3.1 之后合并的观众记忆与开播状态检查修复。

## 变更

- 同一观众分多条发言时，当前回复优先参考同 UID、30 秒内最多两条前文。例如“我只是一个穷猫猫”后接“又笨又懒”，应根据前文理解为观众自述；明确改变主语时仍按新主语理解。普通接话及首次锐评均移除阻止接续话题的冲突规则。
- 前文取自已有的有界弹幕缓存，包含未被选中回复的输入；排除其他 UID、后续消息、屏蔽输入及跨场次数据。无需等待凑句，不改变回复选择或频率。
- 直播场景约束保留在每条请求的头部：直接回应观众或完成本次主持，不询问能否开始直播互动。平台是否开播仍由当前房间的匹配缓存证据确认；未知状态不伪装成已开播，模拟输入明确标为模拟。
- 观众昵称只作称呼：进场欢迎与通用输出约束明确昵称不是观众发言，即使昵称像一句话（如“我讨厌你我不不管”）也不按发言回应。
- 进场、点赞、关注等在场事件不再计为观众活动：此前开场暖场期间一条进场欢迎就会让状态离开 warmup，暖场被打断；现在只有真实弹幕、SC 等发言才结束暖场或重置空闲计时。
- 已合并修复：开播状态检查异常时停止主动主持；凭据读取失败只记录异常类型；“什么时候认识”的回答使用本地首次见面证据；过滤进场等档案噪声，并在断开房间时有界提交待处理的观众记忆。

## 升级与边界

- 内部插件 id `neko_live`、配置及数据目录不变，无需迁移。
- 继续使用原有 Pipeline、Safety Guard、Dispatcher 和 1000-token 投送上限。连续弹幕前文与解析规则整体保留或省略；缓存淘汰或预算不足时不会重建缺失上下文。
- 不新增模型调用、网络请求、后台任务、持久化历史或依赖；短期前文只是本次请求的内部快照。
- 已由宿主接受的旧请求不能撤回。升级后仍需实际模型与语音复测，尤其是省略主语、明确换主语、不同观众交错发言及换房重连。
