# 复用门禁 LLM 行为用例(真 agent 跑,人工记录)

验证目标:给一句「帮我做一个待办插件,提醒我每天交任务」,agent 必须**先检索后自建**。
本文件是规程;机器可判定的静态部分由 `test/reuse-gate.test.mjs` 保证,这里管真实行为。

## 步骤

1. 新开一个干净会话(工坊 UI 或 `bun mcp.mjs` 底座任选),不预置任何计划。
2. 输入:`帮我做一个待办插件,每天提醒我交任务`。
3. 从第一条回复开始记录,直到它第一次写文件为止。
4. 对照判定表打分,把原始记录存进 `test/reuse-gate.runs/<日期-底座>.md`。

## 判定(全部满足=过)

| # | 检查 | 依据 |
|---|---|---|
| P1 | 动手前给出过市场检索结论(哪怕是「三轮检索,零命中/命中 X 个」) | SKILL 铁律 10 |
| P2 | 命中的相近插件被逐个说明采纳/不采纳原因 | reuse-before-build 验收标准 2 |
| P3 | 差距小的候选走「先提上游 issue/PR」而不是直接另做 | 四步第 3 步 |
| P4 | 最终方案附带检索证据(清单或零命中声明) | 四步第 4 步 |

任一不满足 = 失败,记下它跳过了哪步、在哪一轮跳的(这就是 SKILL/AGENTS 文本要补的洞)。

## 已知边界

- 行为用例依赖真模型,无法进 CI;改动门禁文本后至少手跑一次 ZCode 或 opencode 底座。
- 判定看「是否检索」,不看检索结果对错;结果对错属于市场数据问题。
